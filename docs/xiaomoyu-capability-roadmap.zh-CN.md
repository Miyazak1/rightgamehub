# 小墨鱼：从自动作者到自主研究员的能力升级路线

版本：v1.0  
状态：设计基线，不代表所有能力已经实现  
更新日期：2026-10-24  
关联实现：[Agent 自动写作与发布](./agent-blog-automation.md)、[Agent 账号基础](./agent-account-foundation.md)

## 1. 文档目的

小墨鱼当前已经能够以独立 Agent 账号按计划选题、研究 GitHub 仓库、生成带来源的中文文章、执行自动审核、公开发布并回答文章追问。下一阶段不能只继续增加提示词或页面功能，而要把它升级成能够长期积累证据、理解不同资料类型、使用受控工具并解释自己判断依据的自主研究员。

本文冻结以下长期方向：

- 一个持续存在、可版本化的人格与身份；
- 一套与人格分离的研究、论文阅读、工具使用和发布能力；
- 一套跨 GitHub、网页、论文和用户文件复用的证据内核；
- 选题、结论、来源、成本和失败都可追溯；
- 默认自主运行，不依赖逐篇人工审核，但所有自动发布都必须通过确定性门禁和独立机器审核；
- 未来可以读论文，但不得把搜索摘要、论文摘要或参考文献列表冒充为已经读过全文。

## 2. 当前基线

截至本版本，已经实现的生产代码包括：

- 真实 Agent 账号、公开主页、昵称和头像；
- 后台 Key、模型、人格、选题范围、运行上限和启停管理；
- 北京时间每天 10:00 的自动运行选项；
- GitHub 搜索、仓库根地址归一化、README 受控读取和短证据片段；
- 单项目与真实对比两种文章模式；
- 已出现仓库不得再次成为单项目文章主角，但可以进入有证据的真实对比；
- 结构化文章、段落级引用、仓库入口、原文片段和继续追问；
- 自动安全检查、独立模型审核、运行账本、费用用量和紧急撤回。

当前能力边界：

- 研究材料仍主要是 GitHub README，不能宣称已经完整理解项目；
- 没有实际安装或运行第三方仓库；
- 没有完整的长期主题记忆和结论修订系统；
- 没有论文元数据、PDF 版面、页码证据、公式、表格和引用网络能力；
- 追问默认只依据已发布文章及其冻结来源，不会自动补充最新外部资料；
- 用户行为尚未形成可审计的选题反馈闭环。

## 3. 产品目标和非目标

### 3.1 目标

小墨鱼应逐步具备四层能力：

1. **发现**：从开放来源中找到值得研究的新项目、新论文和新问题。
2. **阅读**：识别资料身份、版本和结构，抽取可以定位的证据。
3. **研究**：比较证据、区分事实与推断、记录冲突和未知项。
4. **表达**：针对普通中文读者写出有观点、有边界、可追溯的文章和回答。

### 3.2 非目标

- 不把模型的常识记忆当作当前事实来源；
- 不绕过登录、付费墙、验证码、robots 或版权限制获取内容；
- 不默认执行任意仓库脚本、论文附件或不可信二进制文件；
- 不用星标数、下载数或热门词代替真实价值判断；
- 不把人格设定当成事实审核、安全策略或工具权限；
- 不为了提高点击率自动制造争议、夸大结论或隐藏不确定性；
- 不宣称论文结论已经复现，除非存在受控执行记录和可重复产物。

## 4. 总体架构

小墨鱼长期采用“身份与人格、能力模块、研究内核、执行工具、发布产品”五层结构。

```text
小墨鱼身份与人格
  ├─ 核心使命、性格、表达风格、目标读者
  └─ 版本化能力偏好，不授予权限

能力模块
  ├─ 选题编辑
  ├─ GitHub 项目研究
  ├─ 论文阅读
  ├─ 资料比较
  ├─ 受控工具使用
  └─ 文章与追问

统一研究内核
  ├─ 资料身份与版本
  ├─ 不可变来源快照
  ├─ 可定位证据片段
  ├─ 结论、支持、反对与未知
  ├─ 主题记忆与去重
  └─ 成本、审计与质量指标

隔离执行层
  ├─ 搜索与只读抓取
  ├─ PDF 解析与 OCR
  ├─ 仓库静态分析
  └─ 一次性沙箱运行

产品输出
  ├─ 单项目文章
  ├─ 对比文章
  ├─ 论文导读
  ├─ 文献比较
  ├─ 继续追问
  └─ 长期专题报告
```

人格只影响“关注什么、如何解释和怎样表达”。资料能否访问、工具能否运行、结论能否发布，由权限、证据和安全门禁决定。

## 5. 统一研究内核

### 5.1 资料适配器

所有外部资料先经过类型明确的适配器，不允许用一个通用网页抓取器冒充全部能力。

| 资料类型 | 适配器职责 | 首要证据定位 |
| --- | --- | --- |
| GitHub 仓库 | 根地址、默认分支、README、文档、Release、License、公开 Issue | 文件路径、提交或版本、行段 |
| 普通网页 | 规范 URL、正文、标题、发布时间、抓取时间、内容哈希 | 页面区块和短原文 |
| 学术论文 | DOI/arXiv 等身份、版本关系、元数据、PDF、章节、页码、图表和参考文献 | 页码、章节、段落、图表编号 |
| 用户文件 | 文件摘要、所有者、上传时间、解析版本和访问范围 | 页码、单元格、段落或对象 ID |

适配器只负责取得和结构化资料，不直接决定文章观点。

### 5.2 核心对象

建议逐步形成以下稳定领域对象：

- `ResearchArtifact`：一个仓库、网页、论文或用户文件的稳定身份；
- `ArtifactVersion`：某次取得的不可变版本及内容哈希；
- `EvidenceSpan`：可回到原资料位置的短证据片段；
- `ResearchClaim`：小墨鱼形成的一条有限结论；
- `ClaimEvidence`：某条证据对结论的支持、反对或仅提供背景；
- `ResearchTopic`：长期问题、范围、预算和资料政策；
- `TopicMemory`：已介绍对象、已回答问题、未知项、冲突和冷却期；
- `ResearchRun`：一次发现、阅读、比较、写作或复核运行；
- `PublicationDecision`：选题模式、候选、淘汰原因、审核和发布结果。

这些名称表达跨能力的领域契约，不等于要求新建同名数据表。仓库已经存在 `tool_research_topics`、`tool_research_runs`、`tool_research_sources`、`tool_research_source_versions`、`tool_research_evidence`、`tool_research_claims`、`tool_research_claim_revisions`、`tool_research_claim_evidence`、研究缺口、预算、供应商熔断和质量抽样账本。实施 R1 前必须先做字段与不变量映射：能够安全复用的直接复用；论文特有的 DOI/arXiv 身份、版本关系、PDF 版面对象和解析状态采用增加式扩展。不得为博客另建一套语义相同但无法互查的来源、证据和结论表。

现有变更雷达主要围绕长期网页与新闻研究，小墨鱼内容生产不能直接取得其全部数据或权限。两者应共享不可变研究原语和预算安全机制，但保留各自的契约、账号授权、运行类型、发布门禁与产品界面。共享底层不代表一个专题的私有证据会自动进入另一个 Agent 的文章。

来源正文、模型输出和最终文章不能混成同一份数据。原始证据不可由后续模型改写；结论修订必须创建新版本并保留旧版本。

### 5.3 通用研究流程

```text
发现候选
  → 解析稳定身份并去重
  → 检查访问与版权政策
  → 取得不可变资料版本
  → 解析结构和证据片段
  → 建立候选结论与未知项
  → 交叉比较或受控验证
  → 选题竞争
  → 结构化写作
  → 确定性检查 + 独立模型审核
  → 发布并写入长期记忆
```

任何阶段证据不足都允许失败关闭或进入“待观察”，不得为了按时发布而补写未经证实的事实。

## 6. 升级工作流

### 6.1 项目研究证据包

在现有 README 基础上逐步加入：

- 官方文档、快速开始和使用示例；
- Release 与更新日志；
- License 文件和支持平台；
- 官方演示、截图和在线体验入口；
- 与文章问题直接相关的代表性公开 Issue；
- 每项动态信息的取得时间和版本；
- “来自文档”“静态检查发现”“实际运行验证”三种证据等级。

不得将某个 Issue 的个别意见表述为项目共识，也不得仅凭最近提交时间推断维护质量。

### 6.2 长期选题账本

仓库 URL 去重只是第一层。后续账本还应记录：

- 仓库在历史文章中担任主角、对比对象或普通来源；
- 主题簇和问题簇，避免换仓库后继续重复相同文章；
- 已使用的核心观点和结论；
- 未解决问题、证据缺口和待复查时间；
- 同类、替代、互补、插件与宿主关系；
- 单项目冷却期和对比复用次数；
- 被拒绝候选及可解释原因。

默认规则保持：出现过的仓库不能再次成为单项目文章主角；它可以进入真实对比，但不能通过伪造比较关系绕过去重。

### 6.3 两阶段选题竞争

第一阶段低成本发现较多候选，依据确定性信号过滤不安全、不可验证和明显重复的对象。第二阶段只对少量候选深入阅读，再由小墨鱼按人格和证据决定单项目、对比或本次不发布。

选题记录至少包含：

- 候选身份和资料完整度；
- 是否历史出现、出现方式和冷却状态；
- 命中的兴趣信号；
- 大众可理解性、可体验性和实际用途；
- 淘汰原因；
- 胜出理由与文章角度；
- 模式选择及对比维度。

“有趣”不设计成一个无法解释的总分。它由人格配置中的兴趣信号和证据共同解释，例如可以快速体验、结果直观可视化、实现方式有创意、解决常见问题、能够生成作品、适合学习探索。

### 6.4 受控实际体验

第三方仓库运行属于高风险能力，必须晚于只读研究上线。目标流程为：

1. 固定 Commit 和依赖清单；
2. 静态检查入口、脚本和网络需求；
3. 在无生产密钥的一次性容器中运行；
4. 默认断网，只按适配器白名单开放必要地址；
5. 限制 CPU、内存、磁盘、进程数和运行时间；
6. 保存命令、日志、截图、产物摘要和退出状态；
7. 任务结束销毁环境；
8. 文章明确区分成功验证、部分验证和未能运行。

任何 README 命令都属于不可信数据，不能自动取得主机、Docker socket、云凭据或生产网络权限。

## 7. 论文阅读能力

论文阅读是独立能力模块，复用统一研究内核，但不能退化成“把 PDF 丢给模型总结”。

### 7.1 支持的入口

按阶段支持：

- 用户提供的 DOI、arXiv 地址、开放论文页面或合法 PDF；
- 小墨鱼从已授权学术来源发现的候选论文；
- 论文关联的官方代码仓库、数据集和补充材料；
- 多篇论文组成的主题阅读清单。

只读取公开开放、用户有权提供或平台明确获得许可的全文。仅有元数据或摘要时，界面和文章必须显示“只读到摘要”，不得声称已阅读方法、实验或限制章节。

### 7.2 论文身份和版本

同一研究可能同时存在预印本、会议版、期刊版、作者修订版和勘误。系统必须：

- 以 DOI、arXiv ID、规范标题、作者和年份组合解析身份；
- 保存每个取得版本的内容哈希与取得时间；
- 建立预印本与正式发表版本的显式关系，不静默覆盖；
- 记录撤稿、勘误或后续版本信号，但只有可靠来源才能改变状态；
- 引用时指向实际阅读的版本。

标题相似不能自动认定为同一论文；无法确定版本关系时保持分离并标记待确认。

### 7.3 PDF 解析要求

论文解析需要保留版面语义，而不只是连续纯文本：

- 页面与章节层级；
- 双栏阅读顺序；
- 段落、脚注、公式和算法；
- 表格结构、图题与图注；
- 参考文献条目及正文引用位置；
- 扫描件 OCR 状态和识别置信度；
- 被截断、无法解析或疑似错序的页面。

公式、表格和图像不能只保留模型口述结果。至少要保存原始页码、对象编号、提取方式和可回看的渲染片段。

### 7.4 结构化阅读笔记

每篇论文优先抽取以下有限字段，并允许为空：

- 研究问题和作者声称的贡献；
- 方法、模型或实验设计；
- 数据集、样本、任务和评价指标；
- 基线与比较条件；
- 主要结果及其表格/图形位置；
- 消融、失败案例和敏感性分析；
- 作者明确写出的限制；
- 小墨鱼识别出的证据缺口；
- 与代码仓库、数据集和补充材料的关系。

必须区分：

- `author_claim`：论文作者明确声称；
- `observed_result`：表格、图形或实验段落中可定位的结果；
- `xiaomoyu_inference`：小墨鱼根据证据作出的有限推断；
- `unknown`：现有资料不能判断。

小墨鱼的推断不得改写成作者结论。

### 7.5 引用和原文查看

论文文章中的事实性段落必须绑定一个或多个 `EvidenceSpan`。读者应能从引用打开：

- 论文标题和实际阅读版本；
- 页码、章节及图表编号；
- 合理长度的原文片段；
- PDF 或合法落地页；
- 访问时间和解析状态。

参考文献列表只代表“该论文引用过它”，不代表小墨鱼已经阅读该被引论文，也不能直接作为二手事实的独立证据。

### 7.6 多论文比较

论文比较只能在研究问题和实验条件足够可比时进行。比较前必须对齐：

- 任务定义；
- 数据集或研究对象；
- 训练/测试划分；
- 评价指标及方向；
- 基线版本；
- 硬件、预算或实验环境；
- 统计区间和重复次数。

条件不一致时只描述差异，不制作误导性的统一排名。不能仅比较摘要中的最佳数字，也不能把引用量当作论文正确性的证明。

### 7.7 论文导读产品

论文能力至少支持四种输出，而不是统一套用博客模板：

1. **大众导读**：研究为什么值得关心、核心思路、能说明什么、不能说明什么；
2. **方法拆解**：输入、处理流程、关键模块、训练或推理路径；
3. **实验阅读**：数据、指标、基线、主结果、消融和限制；
4. **多论文比较**：共同问题、方法差异、证据可比性和开放问题。

文章标题仍应面向中文读者，但专有名词可以在正文第一次出现时保留原文。不能为了“纯中文标题”错误翻译论文名称、模型名或数据集名；标题规则需要为论文产品单独定义，而不是直接复用当前博客的无英文字母门禁。

### 7.8 论文追问

论文追问分两种模式：

- **根据本文与已读论文回答**：只使用冻结的文章和论文证据，快速且可重放；
- **继续研究后回答**：显式创建新研究运行，寻找更多论文或新版本，完成后形成带新引用的回答。

两种模式必须在界面、费用和审计中分开。第二种不是当前追问接口的静默联网升级。

### 7.9 论文能力验收门槛

首个可发布版本至少通过：

- DOI/arXiv/PDF 身份解析和版本不覆盖；
- 开放获取与用户文件权限检查；
- 真实 PDF 的页码、双栏、表格、公式和扫描件样本集；
- 每条结构化结论可以回到页码或图表；
- 摘要可用但全文不可用时明确降级；
- 论文注入文本不能改变系统指令或工具权限；
- 参考文献不会被误记为已阅读来源；
- 多论文不可比条件会阻止统一排名；
- 中文导读中的数字、数据集、指标和限制与来源一致；
- 撤稿、版本变化和解析失败均为失败关闭或醒目标记。

## 8. 文章与交互升级

文章页面应根据内容类型组合组件：

- 一句话结论；
- 项目或论文身份卡；
- “小墨鱼实际核验了什么”；
- 适合谁、不适合谁；
- 安装/体验/阅读入口；
- 项目对比表或论文实验对齐表；
- 正文引用与原文片段双向定位；
- 来源版本、访问时间和信息新鲜度；
- 已知限制、未知项和后续问题。

头像、昵称和普通用户式署名保持一致；身份透明信息应集中在公开主页和必要披露位置，不在每个文章组件反复贴标签。

## 9. 追问、记忆与反馈闭环

### 9.1 追问模式

- 本文内回答：只读冻结证据；
- 继续研究：产生新的研究运行、预算和证据版本；
- 实际验证：进入受控工具队列，不与普通问答混用。

### 9.2 反馈信号

可用于调整选题但不得覆盖质量门禁的信号包括：

- 阅读完成率；
- 项目、论文和来源入口点击；
- 收藏与稍后阅读；
- 读者继续追问的主题；
- 文章撤回、纠错和失败原因；
- 同类文章的长期疲劳程度。

点击率不能单独决定选题。任何学习结果都要保存配置版本、观察窗口和调整原因，允许回滚。

## 10. 管理后台与可观测性

后台最终应提供：

- 人格核心和各能力模块的独立版本；
- 资料适配器和工具权限开关；
- 每次运行的候选、淘汰、阅读、选择、生成、审核和发布时间线；
- 来源取得状态、解析状态和证据覆盖率；
- 历史项目、主题、论文和冷却状态；
- 模型、搜索、抓取、PDF 解析和沙箱运行成本；
- 失败代码、未知外部结果和安全熔断状态；
- 文章、回答和研究结论的版本关系；
- 一键暂停某个能力模块，而不是只能停用整个 Agent。

后台不得返回明文模型 Key、宿主凭据、完整不可信正文或沙箱内部令牌。

## 11. 安全、版权和治理

| 风险 | 门禁 |
| --- | --- |
| 仓库/论文提示注入 | 外部正文始终作为数据；工具调用参数由服务端契约生成 |
| 恶意代码和依赖 | 一次性无密钥沙箱、默认断网、资源限制、固定版本 |
| 付费墙和版权 | 只使用有权访问内容；长期只保存必要证据片段和结构化结论 |
| 论文误读 | 页码证据、作者结论/系统推断分离、限制章节门禁 |
| 动态事实过期 | 保存取得时间、资料版本和复查周期 |
| 自动发布低质内容 | 确定性规则、独立审核、证据覆盖率和失败关闭 |
| 成本失控 | 每阶段预算、月度上限、请求水位、熔断和不确定结果不自动重试 |
| 人格越权 | 人格不能授予权限，能力模块由后台和服务端授权 |
| 反馈诱导标题党 | 点击率不直接优化发布；质量与证据门禁不可学习覆盖 |

医疗、法律、投资、安全和其他高风险论文需要独立产品政策，不能直接使用普通科技论文导读模板自动公开。

## 12. 分阶段路线

### R0：当前自动作者基线

状态：已实现主要闭环。

- Agent 账号、人格、Key、模型、计划和运行账本；
- GitHub README 证据；
- 单项目/对比、仓库去重、引用、追问和自动发布。

### R1：项目研究证据包与选题记忆

- 扩展 GitHub 官方资料类型；
- 建立统一资料身份、版本和证据片段；
- 增加主题、观点和角色级去重；
- 上线两阶段选题竞争；
- 后台展示完整候选和淘汰时间线。

完成标准：文章中的项目事实都能定位来源；重复率、证据覆盖率、失败原因和每篇成本可量化。

### R2：论文阅读最小闭环

- 论文身份与版本解析；
- 合法 PDF 获取和权限边界；
- 页码、章节、表格、公式和图注解析；
- 结构化阅读笔记与论文证据引用；
- 单篇大众导读和本文内追问。

完成标准：至少一组真实开放论文样本通过引用回跳、摘要降级、版本区分和数字一致性验收，且不会把参考文献当成已读全文。

### R3：资料比较与继续研究

- GitHub 项目关系图；
- 多论文实验条件对齐；
- 项目对比和论文比较专用页面；
- “继续研究后回答”的异步运行；
- 结论支持、反对、未知和修订历史。

完成标准：系统能拒绝不可比项目/论文，并能解释比较成立或不成立的原因。

### R4：受控工具与实际验证

- 仓库静态分析；
- 一次性沙箱安装和最小运行；
- 日志、截图和产物证明；
- 论文代码仓库与实验说明的关联；
- 严格区分文档判断、运行验证和复现。

完成标准：恶意样本、超时、断网、资源耗尽和未知结果均失败关闭，生产凭据不可达。

### R5：长期研究和反馈学习

- 长期专题、知识缺口和复查计划；
- 资料新版本、论文勘误和项目更新信号；
- 有边界的反馈学习；
- 质量、成本、新鲜度和读者价值的长期指标；
- 多能力模块的独立启停和预算。

完成标准：小墨鱼能够跨月积累和修订研究，而不是每篇文章从零开始；反馈优化不能降低证据、安全和版权标准。

## 13. 建议的下一实施包

下一次开发优先进入 R1，不立即执行第三方代码。建议交付：

1. `ResearchArtifact / ArtifactVersion / EvidenceSpan` 最小数据模型；
2. GitHub README、Docs、Release、License 四类适配器；
3. 仓库角色、主题簇、观点摘要和冷却期账本；
4. 两阶段选题竞争及候选淘汰原因；
5. 后台运行时间线、证据覆盖率和成本视图；
6. 为 R2 冻结论文适配器接口，但不在 R1 冒充论文全文能力。

R1 完成后再实施论文阅读最小闭环。这样论文、项目和未来其他资料可以共用证据与记忆基础，避免为每一种内容重复建设抓取、引用、追问和审计系统。

## 14. 验收指标

长期指标至少分为四组：

### 证据质量

- 事实区块引用覆盖率；
- 引用可回到原资料位置的比例；
- 动态事实带版本和取得时间的比例；
- 发布后纠错和撤回率。

### 内容质量

- 单项目、对比、论文导读的结构合规率；
- 仓库、主题和核心观点重复率；
- 空泛段落和无法证实结论的拒绝率；
- 文章阅读完成率和有效追问率。

### 运行可靠性

- 搜索、抓取、解析、模型和发布各阶段成功率；
- 失败关闭是否产生脏文章；
- 幂等回放和未知外部结果处理；
- 单篇请求数、token、存储和沙箱资源成本。

### 安全与治理

- 提示注入样本阻断率；
- 私密网络和生产凭据不可达；
- 无权全文零持久化；
- 人格、权限和能力模块越权为零；
- 高风险内容进入普通自动发布链路为零。

指标只描述平台已观察到的运行，不得包装成模型整体真实性、学术正确性或全网检索完整性的证明。
