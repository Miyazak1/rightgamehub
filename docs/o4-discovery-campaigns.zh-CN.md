# O4.1：发现专题与增长归因

状态：代码实现、契约校验、生产构建与完整本地自动化测试通过，待合并部署和生产验收（2026-10-12）。

## 目标

把“每周一个开放游戏”“一起完善”和阶段性游戏合集变成可持续运营的发现页专题，同时验证专题是否真的带来作品浏览、试玩和有效试玩。专题仍然属于“发现”，不新增“开放游戏馆”，也不改变玩家个人游戏库。

## 产品流程

1. 管理员在平台后台创建专题，选择类型、标题、简介、传播文案、开始/结束时间和现有公开作品。
2. 草稿只有管理员可见；发布后，在生效时间内显示于发现页。
3. 玩家可以进入稳定专题地址 `/discover/c/{slug}`，查看并打开专题中的作品。
4. 从专题进入作品时，客户端记录 `campaign` 来源和不可识别个人身份的活动代号。
5. 作者中心和平台数据中心按专题聚合浏览、试玩、有效试玩和转化率。
6. 管理员可以归档专题；归档后不再出现在发现页和公开接口中，历史归因数据保留。

## 专题类型

- `weekly_open_game`：每周一个开放游戏，用于集中讲清玩法、来源与作者关系。
- `improve_together`：一起完善，优先展示有公开任务、反馈入口或待认领关系的作品。
- `collection`：普通运营合集，用于节日、主题和跨游戏策展。

专题类型只影响运营语义和界面标识，不把游戏复制到新的内容系统中。

## 可信与运营边界

- 每个专题必须包含 1—12 款当前公开、可访问、可玩的现有作品。
- 专题不改变作品来源、许可证、认领状态、作者关系或发布状态。
- 专题项只保存作品引用、排序和可选运营短句，不复制作品资料。
- 发布和归档使用版本号做乐观并发控制，避免旧后台页面覆盖新状态。
- 专题事件只追加，禁止 SQL 更新或删除。
- 归因只保存渠道类型和活动代号，不保存完整来源网址、玩家输入或个人身份。

## 数据与接口

- 迁移：`0064_discovery_campaigns.sql`。
- `discovery_campaigns` 保存专题资料、状态与生效时间。
- `discovery_campaign_items` 保存作品引用、排序和运营短句。
- `discovery_campaign_events` 保存创建、编辑、发布和归档事件。
- `GET /v1/discovery/campaigns`：当前生效的公开专题。
- `GET /v1/discovery/campaigns/{slug}`：公开专题详情。
- `GET /v1/admin/discovery-campaigns`：管理员专题列表。
- `POST /v1/admin/discovery-campaigns`：创建专题草稿。
- `PATCH /v1/admin/discovery-campaigns/{campaignId}`：编辑、发布或归档。
- `GET /discover/c/{slug}`：不依赖 Hash 的稳定专题公开地址。

## 验收清单

1. 非管理员不能创建、编辑、发布或归档专题。
2. 草稿和未到开始时间的专题不会出现在公开接口或发现页。
3. 已发布且处于生效时间的专题显示在发现页，并可打开稳定公开地址。
4. 专题只能引用公开可玩的现有作品；私有、撤下或不可访问作品会被拒绝。
5. 专题页作品顺序与后台设置一致，作品资料仍来自统一目录。
6. 从专题打开作品后，浏览、试玩和有效试玩均记录为 `campaign` 来源并带专题代号。
7. 作者中心和平台数据中心将该来源显示为“发现专题”，不显示内部英文枚举。
8. 归档后专题从公开入口消失，历史统计仍保留。
9. 并发使用旧版本号修改会返回冲突。
10. 专题事件无法通过普通 SQL 更新或删除。
