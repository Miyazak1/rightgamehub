# 小墨鱼公开流程恢复整改

本轮只调整公开仓库调研与发文的恢复和故障隔离，不改历史记忆、已有发布回执、线上配置或论文开关。

## 原因与处理

- 启动准入先检查活动任务，而恢复又在准入后，造成遗留任务无法恢复。现在每轮先接管过期触发记录、处理请求检查点，再判断是否允许新任务；心跳记录缺失不会挡住恢复。
- 工作流未注册、熔断和额度暂时不足曾使调度器退出。现在进程保留，记录等待原因，定期重查；已到探测时间的供应商熔断允许网关执行受控探测。
- 请求重试重新读取历史输入。新增 0162 迁移，保存冻结输入、原触发身份、执行租约、重试状态和追加式恢复事件。恢复复用原请求、原 Run、已有工具/模型输出及草稿/发布回执。
- 重启沿用 workerId 被旧心跳挡住。每次创建独立执行身份，阶段租约和请求租约负责互斥，过期后接管，旧持有者不能继续发布。
- v4 允许有限次数重试只读调研和模型调用。未知模型结果按原预算上限计费，成功输出重放；旧版本和其他工作流的未知副作用处理保持保守。草稿和发布只重放可查询的已提交回执，不能盲目重发未知领域写入。
- 正常空搜索记录成功跳过。达到重试上限的请求进入可审查记录，保留所有证据；确认运行已终止并被租约隔离后，不再永久挡住后续公开任务。新失败不再自动关闭每天的调度；历史暂停仍需显式恢复。
- PostgreSQL 查询、锁等待和连接建立都有上限，闲置连接断开由进程捕获。退出信号传入执行阶段，容器提供 45 秒停止宽限；强制退出后的恢复仍使用持久化租约。

## 容量与保留边界

生产每日发布数、每月 120 次模型调用与费用总上限不变。v4 的请求内预算为发现阶段最多 2 次模型调用、写作阶段最多 8 次，包含故障恢复；实际未调用不计费，未知调用按保守上限记账。GitHub 请求在发现和文章阶段之间共享持久化的 **43 次总上限**，重启和重试不会重置；5 个候选和每仓库请求上限仍有效。

原有 Run、阶段、预算和记忆的终态不改写。发现旧请求时追加接管记录；已发布但确认丢失时以同请求、同 Run 的数据库回执为准。观察接口额外返回等待数、待审查数、最早等待时间及最近业务完成时间。密钥、被撤销权限等需要操作员处理的阻塞不会被自动绕过。

## 验收矩阵

| 边界 | 注入方式 | 验证 |
| --- | --- | --- |
| 模型断网 | 本机 HTTP 连接中断，下一次使用实际 DeepSeek | 原请求完成，未知调用留账，重放不新增调用 |
| 草稿提交后进程退出 | 实际 Node 子进程退出，保留真实 PostgreSQL | 冻结输入不变，同 Run 恢复，仅一个发布事件和回执 |
| 数据库连接故障 | PostgreSQL 终止实际执行连接 | 不猜测事务结果，重启后查询草稿/发布回执继续 |
| 调度器闲置连接故障 | PostgreSQL 终止调度器连接 | 进程存活、重连、心跳恢复 |
| 临时准入阻塞 | 在隔离数据库暂时打开供应商熔断 | 不退出重启；解除后自动恢复检查 |
| 租约接管/并发 | 过期原租约、新持有者接管 | 身份保持、旧持有者完成/续租被拒绝 |
| 完成确认丢失 | 提交后丢失调用方确认 | 数据库回执优先，不重复发布 |
| 历史与配置 | 比较原记忆记录与论文运行 | 历史内容不变，论文运行数为零 |
| 发布与回滚 | Bash 发布故障与原子迁移回归 | 配置保留，迁移失败整体回退，保留兼容迁移清单和旧镜像 |

显式验收入口：`node scripts/test-blog-resilience-live.mjs <本机模型配置文件路径>`；数据库矩阵入口：`node scripts/test-blog-resilience-live.mjs --db-matrix`。两者只创建带唯一标签、回环端口和内存数据卷的临时 PostgreSQL，不读取生产数据库地址。真实模型密钥仅由已有本机文件读入，不写入报告；报告位于 `.runtime`，不提交仓库。

## 部署边界

这是包含 API 代码、Compose 停止宽限及新增迁移的完整发布，不能使用 finish-only。使用固定提交的 `deploy/update-blog-editorial-continuity.sh`，保留现有 `.env.prod`、数据库卷、正式安装包和回滚材料。脚本通过 API 注册当前工作流后再校验调度器，四个论文开关继续为 false。成功更新后显式恢复每日计划，不额外触发一次立即发文。

已启用计划的幂等恢复命令如遇暂时阻塞，保留真实的 enabled 状态、阻塞原因及原触发时间，命令不误报部署失败；原本未启用的计划仍必须通过准入后才能启用。

## 本轮验收结果

- 全量覆盖 374 个文件：1641 项通过，98 项按环境条件跳过。两个 Windows 发布模拟文件超过原 180 秒文件级超时，使用显式 `MOOYU_TEST_FILE_TIMEOUT_MS=300000` 复跑全部原断言通过；原始超时记录和复跑报告均保留，未排除测试文件。
- 25 个数据库文件通过；补充验证空搜索跳过、无效模型输出后继续发文、过期持有者拒绝，以及 161→162 失败事务整体回滚、旧用户和校验值保留。
- 实际 DeepSeek 与 GitHub、隔离 PostgreSQL 完成 4 次发布：断网、进程退出、数据库连接故障后的同请求重放均未新增模型调用和发布回执。共 12 次已结算调用、1 次未知结果保守计费；各请求 GitHub 用量 33～35 次，均不超过 43。原记忆记录不变，论文 Run 为零。
- 临时熔断与调度器连接断开后进程存活并恢复。前端生产构建、实际 Docker 实例发现、发布/回滚边界和宝塔后台命令的成功/失败日志保存均已验证。

本机汇总证据：`.runtime/public-resilience-acceptance.json`。实际模型报告及不含密钥的数据库证据：`.runtime/blog-public-live-Has3cL/`。这些运行材料留在本机，不随源代码推送。
