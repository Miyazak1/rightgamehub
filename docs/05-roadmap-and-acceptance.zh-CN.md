版本：v1.0 · [目录](./README.md)

## 1. 开发基线

已确认的产品是多作者小游戏与创意项目平台，包含网页 3D、自主定价、平台抽佣和双入口。首发面向海外，由中国大陆公司经营。英文、USD、先评估美国市场、15% 佣金和付费最低价均是方案建议，不是用户已确认的参数。

长期扩展顺序为：真实作品托管与运行 → 创作者与用户闭环 → 根据需求决定是否建设交易结算 → 扩大宿主与市场覆盖。当前只实施免费版本，支付渠道不进入当前关键路径。

当前以 [S 档最小试运行](./06-server-sizing.zh-CN.md) 启动：单台 2 vCPU/4 GB，沿用约 30—40 USD/月规划预算；正常包自动检查发布，异常包复核，不开发支付沙箱。下文排期和清单仅供未来完整平台扩展使用。

### 当前已有材料的复用范围

| 现有内容 | 可复用之处 | 不能推定的能力 |
| --- | --- | --- |
| 本地 Canvas 演示 | 页面尺寸、输入和基本宿主体验参考 | 多作者作品托管、3D、账户与交易 |

## 2. 阶段安排

以下是 **3 位工程师 + 1 位兼任产品/运营负责人 + 部分时间设计、测试与安全支持** 的估算。阶段可部分交叠，整体按 10—14 个开发周规划；渠道准入、公司开户、合同和外部评估时间不包含在技术工期内。单人开发应按约 4—6 个月或更长重新排期，不把 AI 辅助等同于取消验收工作。

| 阶段 | 参考时间 | 主要产物 | 放行条件 |
| --- | --- | --- | --- |
| P0：关键可行性 | 第 1—2 周 | 真实 ZIP 上传与隔离播放器、三类作品样本、3D 测试、渠道业务材料 | 作者 A 上传，用户 B 可运行；核心隔离成立；收付方案有明确验证路径 |
| P1：平台基础 | 第 3—5 周 | 账号、作品库、创作者后台、预览、审核、发布回滚、云存档 | 免费作品完整闭环、权限隔离与数据恢复通过 |
| P2：交易闭环 | 第 6—8 周 | 入驻、价格、订单、权益、私有资产、退款、账本、结算和对账 | 渠道沙箱全流程通过；真实业务准入材料具备后再做正式环境小额验收 |
| P3：宿主与稳定性 | 第 9—10 周 | VS Code 实装、Codex 浏览器适配、Cursor 候选、观测、故障演练 | 主目标宿主通过；失败能回退；无越权和关键交易缺陷 |
| P4：邀请制发布 | 第 11—14 周 | 首批作者与作品、支持流程、质量指标、成本报表 | 技术、业务、渠道和运营四方放行，逐步提高配额 |

每阶段交付可演示的闭环，不以“页面已经画完”作为阶段完成。若渠道评估显示现有主体与业务组合不可接纳，继续免费/内部验证并评估获准替代渠道；任何经营主体变化另作商业决策，不擅自假定必须设海外公司。

## 3. P0 必须验证的技术问题

### V1：真实作品发布

准备三份独立包：一个 Canvas 小游戏、一个 WebGL2 3D 小游戏或场景、一个创意工具。使用两个独立账户：作者上传、预览、提交，审核员批准后由作者发布；另一用户通过平台链接运行。资源从对象存储与分发链路加载，不能继续只播放平台源码里写死的演示。

验收：三种包可上传与版本化；失败日志明确；更新不覆盖历史包；回滚后启动新会话取得目标版本；用户 B 不能读取作者草稿或修改作品。

### V2：宿主与网页 3D

| 场景 | 目标测试 |
| --- | --- |
| 普通浏览器 | 当前稳定 Chrome/Edge；Mac 用户加入后测 Safari；Firefox 作为独立兼容项 |
| Codex 内置浏览器 | WebGL2、WASM 单线程、纹理/音频、输入焦点、页面隐藏和恢复 |
| VS Code 功能区 | 安装开发扩展、移动到右侧、重启、可见性变化、浏览器回退 |
| Cursor 编辑器 | 实际版本的扩展安装、页面和浏览器命令；独立 Agents Window 另记结论 |

至少完成 30 分钟 3D 运行及 20 次隐藏/恢复操作，记录帧率、加载、异常和显存/内存趋势。选择 360/480/960 px 宽度，覆盖高 DPI 和不同缩放。音频必须由用户动作激活，指针锁和全屏可退出。

网页 3D 的首版放行以 WebGL2 为基线；WebGPU 或多线程失败不伪装为已支持。宿主禁止 GPU 或嵌入要求不能满足时，给出受支持浏览器入口或明确不兼容状态。

### V3：隔离与付费资产

使用专门测试包尝试读取父页面、业务 Cookie、其他作品存档、未允许外网，以及发送伪造 SDK/agent 指令。使用 ZIP 路径穿越、重复文件、超限展开和异常文件类型样本验证拒绝行为。

再以未购账户请求 HTML、JS、WASM、模型、贴图和 Range 分段，即使此前其他买家已把资源放入缓存也必须拒绝。检查私有源桶不能被公开访问，预览链接不能升级为正式权益，能力路径不会进入来源头或分析日志。

记录第三方 Cookie 禁用、资产会话过期、延迟加载、跨入口登录和存档冲突的实际行为。禁用作品后，目标为 5 分钟内阻止新资产请求和新启动；已经下载到客户端的字节无法收回，验收记录明确这一边界。

### V4：中国大陆主体的收付路径

准备可审阅的业务材料：公司信息、作品实例、作者协议草案、买家国家、作者国家与类型、平均客单价、退款办法、佣金及资金流图。先提交渠道准入评估，再按获准方案确定收单/分账 API。

向渠道确认以下问题并留存答案：

1. 是否接受中国大陆公司经营多作者 UGC 游戏及非游戏创意项目市场？
2. 支持哪些个人与企业作者？是否支持大陆作者？所需文件分别是什么？
3. 谁是销售责任人、收单商户与税务责任人？是否允许平台按作品佣金抽成？
4. 买家付款、作者分账、到账、退款、拒付、追回、保留金和负余额各如何处理？
5. 国家、币种、最低交易额、费用、结算周期、最低业务量及暂停账户后的处理规则是什么？
6. 能否提供大陆公司的入账及跨境付款所需交易材料？

公开文档只支持“存在候选路径”。没有实际准入与端到端测试，不标记“自动分账已验证”。本次编写方案没有替用户开户或向任何服务商发送上述材料。

## 4. 首版验收清单

| 编号 | 用例 | 合格标准 |
| --- | --- | --- |
| A01 | 两位作者互相访问草稿、预览和后台 | 越权全部拒绝，不通过对象 ID 猜测获取文件 |
| A02 | 上传异常、断点/重试、重复完成通知 | 无重复版本、任务可恢复、配额不被绕过 |
| A03 | 审核后替换资产、新增联网权限 | 不可静默替换；创建新版本并重新检查 |
| A04 | 2D、网页 3D、创意工具真实发布 | 三类作品均由上传包运行，用户 B 可体验 |
| A05 | 缓存命中情况下访问付费资产 | 未授权请求仍被拒绝，源桶保持私有 |
| A06 | 价格在支付前后被修改 | 已创建订单快照不变，过期订单重新确认总价 |
| A07 | 支付成功回调重复 10 次 | 只记一次收款、一个来源权益、一组账本分录 |
| A08 | 支付事件乱序、丢失、用户关页 | 查询和对账可恢复，不用前端回跳发权益 |
| A09 | 退款、部分退款、划转后退款 | 累计金额正确，权限按规则更新，资金差异可追踪 |
| A10 | 作者渠道能力突然受限 | 阻止新销售，已有买家/应付款进入明确处理流程 |
| A11 | 功能区不存在、超时或报错 | 只回退一次并说明入口状态，不假报页面已就绪 |
| A12 | 宿主不允许交易 | 关闭该渠道不被允许的行为，不用浏览器回退绕过政策 |
| A13 | 两入口同时保存、作品升级再回滚 | 冲突可处理，旧快照仍可恢复，不静默覆盖 |
| A14 | 普通作者停售与紧急安全禁用 | 前者按协议保留已购权益；后者阻止新启动并形成售后工单 |
| A15 | 数据库恢复和渠道事件重放 | 达成恢复目标；重放不重复扣款、发权益或付款 |
| A16 | 扩展重启、换任务、隐藏恢复 | 会话行为符合说明；无法恢复的内存状态明确提示 |
| A17 | 授权令牌与支付数据泄漏检查 | 包、日志、第三方分析和错误报告中无敏感令牌/卡数据 |
| A18 | 收款、分账、到账与每日对账 | 订单—渠道—账本—作者四方一致；异常有处理记录 |

最后一项真实资金测试必须在生产准入、账户和测试交易方式获准后执行。无需为了方案编写进行任何真实扣款。

## 5. 发布门槛和观测指标

公开付费试运营前，必须完成以下四类放行：

- **工程**：无未修复的跨租户访问、资产鉴权绕过和关键记账缺陷；备份恢复与禁用机制有效。
- **交易**：主体、内容类别、收款与作者结算都获得渠道准入；真实环境验收及对账完成。
- **产品与运营**：退款、举报、申诉和紧急下架有人负责，首页内容和作品兼容性真实。
- **市场与合同**：首批国家、销售角色、费用、税务、隐私、受众和权利政策明确并落实。

试运营建议观察目标：

| 指标 | 定义 | 初始目标/使用方式 |
| --- | --- | --- |
| 支持档作品启动成功率 | 获准启动后收到有效 ready 的次数 / 对应启动次数 | ≥98%；未接 SDK 作品单列，不混入分母 |
| 标准档启动耗时 | 点击启动至 SDK ready，分地区/冷暖缓存统计 | 基准条件下 p95 ≤10 秒 |
| 平台 API 耗时 | 不含第三方支付及公网往返的服务时间 | p95 ≤300 ms |
| 存档正确性 | 并发、迁移、恢复用例及线上故障 | 验收无静默覆盖，线上失败可定位 |
| 财务差异 | 渠道、订单、账本、结算差异 | 每日归零或形成有负责人和期限的差异工单 |
| 成本 | 每作品、每启动字节/请求、基础服务账单 | 预算 50%/80%/100% 阈值告警 |
| 供需质量 | 作者再次发布、用户回访、有效体验、退款原因 | 先形成连续四周基线，再定增长目标 |

不同作品时长和体积不同，不能只用总游玩时间奖励大包或耗时项目。首次试运营需要足够样本，例如累计 500 次以上真实启动，并覆盖三种作品档位；小样本好看不构成大规模可用性承诺。

## 6. 风险与处理顺序

| 风险 | 影响 | 处理策略 |
| --- | --- | --- |
| 大陆主体无法接通所需收付模式 | 核心商业闭环受阻 | 第一周验证业务准入；准备合规备选；不先售卖后找结算办法 |
| 宿主没有原生功能区 API | 入口体验受限 | 网站与内置浏览器先行；按正式接口增加适配 |
| 公开插件目录限制数字商品交易 | 无法按商店形态上架 | 独立评估允许的插件功能，不依赖目录收入或绕过政策 |
| 作者包携带恶意行为 | 用户数据和平台信誉受损 | 独立域、最小权限、扫描、动态测试、举报及快速禁用 |
| 3D 资源太大或设备不兼容 | 加载失败、退款和高支出 | 发布预算、性能档位、预购检测、资产优化模板 |
| 支付费用高于低价作品收益 | 作者不愿意销售 | 定价模拟、清晰费用表、最低付费价、免费作品选项 |
| 免费内容增长快于收入 | 托管与审核成本不可持续 | 配额、缓存、防滥用、按作品成本管理、后续托管套餐 |
| 来源不明的 AI 素材或代码 | 版权及商业使用争议 | 来源声明、许可证、审核与申诉；不保证 AI 产物天然无权利问题 |
| 存档跨版本损坏 | 玩家流失与退款 | schema、旧快照、迁移测试、回滚兼容 |
| 获得海外用户但无人维护内容 | 故障和投诉积累 | 邀请制控制规模，维护状态及售后责任写入作者协议 |

## 7. 工程任务建议拆分

首版代码仓库建议沿以下边界组织；这是未来结构，不要求为了文档交付立即创建空目录。

```text
apps/web                 网站、创作者后台、可信播放器
apps/api                 业务 API 与支付回调
apps/worker              上传校验、检测、通知、对账
packages/contracts       API/manifest/SDK 消息 schema
packages/player-sdk      作者使用的有限能力 SDK
packages/domain          作品、权益、交易领域逻辑
adapters/hosts           Codex 浏览器、VS Code、其他宿主
adapters/payments        渠道无关契约与获准渠道实现
infra                    环境、私有存储、网关和备份配置
examples                 2D、WebGL2、创意工具标准发布包
docs                     方案、导出说明、运维手册与验证证据
```

工程负责人 A 负责上传、版本与运行隔离；B 负责网站、播放器、SDK 和宿主适配；C 负责账号、订单、权益、结算和运维。产品负责人负责首批作者、价格测试、渠道与经营材料；安全与测试人员在 P0 和付费放行前分别审阅。

按闭环组织测试：上传后另账户运行、付费后读取所有资产、退款后阻止新会话、两入口保存冲突。单独页面快照和模拟适配器测试不能替代这些验收。
