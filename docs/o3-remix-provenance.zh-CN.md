# O3.1：二创来源关系

## 目标

让允许二创的开放作品形成可核查、可双向浏览的衍生关系。二创仍然是“发现”中的普通游戏或互动作品；本阶段不新增社区游戏馆，也不改变玩家个人游戏库。

## 产品流程

- 创作者在新建或编辑作品资料时，可从平台已核验为允许二创的公开作品中选择一个来源。
- 创作者必须填写 10—1,000 字改编说明，说明保留内容、新增创作和主要变化。
- 二创作品详情显示原作品、原作者、许可证和改编说明，可返回原作品。
- 原作品详情显示已公开且当前可运行的二创作品。
- 暂不接受仅凭自由文本填写外部仓库作为二创来源；外部 GitHub 上游需要在后续接入固定 Commit 与许可证验证后开放。

## 可信边界

- 来源作品必须处于公开发布状态，关联公开仓库，并使用平台认可为可二创的许可证。
- 服务端拒绝自引用和任意深度的循环来源。
- 作品公开后，已经声明的来源关系由创作者侧锁定；纠错需要进入平台审核，避免事后替换来源。
- 每次声明、更新或移除都写入不可更新、不可删除的审计事件。
- 来源作品后来撤下时保留关系记录，但界面明确标记当前不可访问；不会静默改指向其他作品。

## 数据与接口

- 迁移：`0062_work_remix_provenance.sql`。
- `works.remix_source_work_id` 保存单一直接上游，`works.remix_note` 保存作者的改编说明。
- `work_remix_events` 保存只追加的来源变更审计。
- 创建与编辑作品沿用现有接口，增加 `remixSourceWorkId` 与 `remixNote`。
- `GET /v1/works/{workId}/remixes` 返回最多 12 个当前公开可运行的直接二创。

## 验收

1. 新建草稿可选择允许二创的来源并保存改编说明。
2. 无许可证、非可二创许可证、私有、撤下或不可访问的来源均被拒绝。
3. 自引用和 A → B → A 等任意深度循环被拒绝。
4. 已发布作品的既有来源不能由创作者替换或删除。
5. 二创详情可返回原作品，原作品详情可进入二创作品。
6. 来源撤下后不泄露新的私有信息，并明确显示来源暂不可访问。
7. 审计事件无法通过普通 SQL 更新或删除。
