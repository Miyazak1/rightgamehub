# Windows EXE 与网页作品的双版本分发

更新：2026-09-22 · 方案补充，尚未实现 · [目录](./README.md)

**当前需求**：Windows 下载分发已列入首版，包含 EXE 安装包；作者与玩家在 Harness、VS Code、Cursor 编辑器内完成操作。本文保留分发原则，具体包类型、接口与宿主验收以 [18](./18-multi-host-client-spec.zh-CN.md)、[19](./19-windows-package-spec.zh-CN.md)为准。EXE 侧栏运行按 [独立验证计划](./09-exe-sidebar-validation.zh-CN.md)继续实测，下载不代表已满足游玩目标。

## 1. 支持结论与首版边界

平台同时承载网页作品与 Windows 发布包，两种分发都属于免费首版。Windows 包完成专用检测与三宿主下载管理验收后开放，不需要自行维护一套编程客户端。全部免费，不引入订单、购买权益或支付。

| 作者发布的内容 | 作品页入口 | 实际运行位置 |
| --- | --- | --- |
| 网页构建包，包含 HTML/JS/WASM 等 | 在线玩 | 普通浏览器，或已验证兼容的 agent 内置浏览器/功能区 |
| Windows 完整程序包，包含 EXE 和依赖 | 下载 Windows 版 | 玩家自己的 Windows 电脑 |
| 同一作品同时提交以上两种包 | 同时显示两个入口 | 由玩家选择，两个包分别检查和更新 |

普通网页或浏览器型侧栏不能直接加载任意 Windows EXE 执行。浏览器的 WebAssembly 运行的是对应编译目标及其 Web API 集成，上传 EXE、改后缀或包一层 iframe 都不等于网页移植。要在线玩，通常由作者从源码或引擎项目导出兼容的网页版本，并完成适配。[MDN WebAssembly 概念与编译流程](https://developer.mozilla.org/en-US/docs/WebAssembly/Guides/Concepts)。

EXE 也可以是创意工具或互动项目，不限于游戏；仍按平台内容范围和可分发权利判断。同一作品的网页与 Windows 版本可以功能不同，作品页应说明，不承诺存档互通。

## 2. 作者和玩家流程

作者在插件内：登录并创建作品 → 选择“网页在线版”或“Windows 下载版” → 上传对应包 → 检查 → 发布。已有作品可以补充另一种构建目标，不需要复制作品详情。

玩家在插件内：打开作品页 → 在线玩，或下载 Windows 版 → 在下载管理查看进度、校验结果和保存文件。页面展示系统、架构、包类型、大小、版本和作者。未验证原生侧栏运行前，Windows 包不显示已可用的“功能区运行”按钮；下载完成不自动启动安装器或游戏。

三宿主的文件保存、下载进度与完成状态需要分别验收。仅能交给浏览器下载器的形态标为受限兼容；外部浏览器或复制链接是可选回退，不能通过“全部在宿主内”的完整验收。旧 Codex Canvas 原型结果也不证明 EXE 下载能力。

平台插件不自动启动作者 EXE，不通过 agent shell 执行下载内容，也不把浏览器作品的工具桥权限交给本地程序。原生程序运行后不受平台网页 iframe 的隔离规则约束。

## 3. 上传包和发布检测

### 包格式

接收完整便携 ZIP、确实不依赖旁置文件的单文件 EXE，以及 EXE 安装包，分别声明类型，见 19。不要只上传引擎 EXE 而漏掉数据目录。安装器可以分发，下载服务不执行安装；涉及提权、驱动、服务或联网拉取其他组件的包按策略复核，不因扩展名合规就自动放行。

Windows 包不要求 `index.html`，也不进入网页播放器。上传表单记录目标系统、x64/x86/ARM64 架构、作者声明的最低要求及 ZIP 内启动文件路径；“作者声明”与平台实测兼容性分别标记。

配额按类型配置，具体以 19 为准：网页 100 MiB 压缩/300 MiB 展开，Windows 初始建议单包 500 MiB、便携 ZIP 展开 1 GiB、10,000 文件，扫描器更低限制优先。TD-1.1 使用受控 API 流式上传到私有隔离区，不能将整个包转为 base64 或装入内存；对象存储直传留作后续优化。

### Windows 发布链路

```text
私有隔离上传
  → 校验大小、真实格式、SHA-256、归属和配额
  → 受限解析 ZIP/PE、路径检查、识别完整依赖
  → 对发布内容做恶意文件检测，并记录扫描器、规则版本和时间
  → 检测成功且符合策略：发布不可变下载包
  → 命中、不可完整检测、超时或服务不可用：保留私有，提示失败或进入复核
```

检测覆盖包内可执行文件和依赖；加密包、无法解析的嵌套内容或超过扫描器能力的文件不自动放行。ZIP 解包继续防止路径穿越、链接、重复规范路径和解压炸弹。解析器和扫描器也处理不可信输入，应运行在独立受限任务环境，不拥有生产数据库、云账户或工作区凭据。

首批 Windows 作者建议邀请制；普通包可在检测与策略通过后自动发布，不要求每个包必经人工试玩。运行兼容性抽测需要干净的隔离 Windows 环境，不能在业务服务器或日常办公电脑试跑陌生上传程序。

检测通过不能证明程序绝对安全；显示事实性的检测状态，不使用“平台保证无毒”。保留作者标识、举报、版本禁用与下载撤回能力。不要默认将作者私有文件提交到会公开或共享样本的第三方服务，先确认其数据处理规则。

记录作者数字签名及验证结果；平台不替所有作者用同一个证书签名，也不修改已签名文件。新程序即便有有效签名，仍可能出现 Windows SmartScreen 提示。平台不承诺免提示，也不引导用户关闭系统防护。[Microsoft SmartScreen 开发者说明](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)。

## 4. 最小数据与下载接口

继续共用 User、Work、Release、UploadJob、Artifact 和管理日志，不新增商业实体。建议让每个 Release 对应一种构建目标，同一 Work 可同时拥有网页和 Windows 的已发布 Release：

| 字段/规则 | 用途 |
| --- | --- |
| `Release.distribution_type`：`web` / `windows` | 选择播放器或下载链路 |
| `Release.target_arch`、`entry_path`、`requirements` | Windows 架构、包内启动位置和运行要求；网页入口沿用原契约 |
| `WorkTarget` 按构建目标维护当前 Release 指针与 generation | 更新 Windows 包不意外覆盖网页在线版 |
| `Artifact.sha256`、字节大小、真实格式、私有存储键 | 下载对象的身份、完整性与配额 |
| 扫描状态、扫描时的包哈希、扫描器/规则版本/时间、签名结果 | 保证扫描结论绑定最终发布的相同字节 |
| 禁用原因、发布/撤下日志 | 追踪新旧包和后续处置 |

复用 14 的上传任务与状态接口，按 19 增加目标和包类型，发布按目标执行。新增 `/v1/works/{workId}/releases/{releaseId}/download-info` 和 `/download`；仅允许读取已发布且未禁用的 Windows 包，无需登录、领取或支付令牌。

下载通过与平台账号域隔离的资产域提供，使用正确的附件响应头及安全文件名，支持 Range/续传和按 IP/作品的滥用控制。先验证发布状态再读取缓存或对象存储，私有桶源站不能绕过网关；不把数据库中的存储键直接作为永久公开入口。

下架后阻止新的下载请求并清理边缘缓存；已经下载到用户设备的程序、以及已开始传输的字节不能追回。版本字节不可原地替换；重新上传或修改文件后必须重新检测。后续发现风险时可以禁用对应哈希并复核关联版本。

## 5. 服务器和复杂度

仅做 EXE 下载分发，游戏由玩家电脑运行，平台不需要为每位玩家购买 Windows/GPU 服务器。网站/API/数据库可以沿用 [S 档](./06-server-sizing.zh-CN.md)，包放对象存储，经下载网关分发。

新增成本主要是包体积、下载请求/带宽、恶意文件检测与隔离兼容性抽测。原先约 30—40 USD/月是低用量网页试运行预算，不能视为包含任意规模 EXE 扫描与下载的总价。扫描器可能需要独立内存/CPU，不能直接套用网页文件任务的 512 MiB/60 秒配置；确定检测服务与包上限后再核算。

下载分发需要专用检测、受限传输和下载管理，不能只多加上传后缀。以下不列入已承诺的首版能力；原生侧栏运行另做实验：

- 平台桌面客户端、安装管理、自动更新与差分补丁。
- 任意 EXE 自动转换为网页游戏。
- 云端运行 Windows 游戏并把画面和输入串流到网页。该路线需另做执行隔离、远程会话、图形资源、延迟和按并发/时长计算的成本验证。
- 自动兼容 macOS/Linux，或承诺所有 EXE 都能运行。

## 6. 开放 Windows 上传前的验收

1. 同一作品可同时提供独立更新的网页版本和 Windows 包，按钮和平台要求显示正确。
2. 用自有单文件程序、含 DLL/资源的完整 ZIP 和 EXE 安装包验证下载及哈希；安装/启动抽测在隔离 Windows 中单独记录。
3. 检测不可用、文件超限、加密包、恶意路径或策略命中时，包不能公开；失败更新不影响先前允许下载的版本。
4. 私有草稿不可下载，作品或版本禁用后新下载被阻止；限流、续传、日志与举报可用。
5. Harness、VS Code、Cursor 编辑器分别完成 18—19 的插件内下载管理验收；外部浏览器回退不能充当完整通过结果。

当前仅完成方案补充，真实上传、Windows 文件检测、下载接口及宿主下载行为均待实现和验收。
