# G3.1 作者增长基础：数据看板与 README 徽章

状态：代码完成，待生产部署验收
更新日期：2026-10-02

## 1. 本阶段交付

G3.1 在不扩大 GitHub App 权限的前提下，为作者增加两个可立即使用的增长入口：

1. 创作中心作者数据看板，可切换最近 7、30、90 天。
2. 已发布作品可复制 README “在线体验”徽章，把 GitHub 访客带回 GameHub 的固定作品页。

本阶段不创建 GitHub Issue、不修改 README、不向仓库推送 Commit。复制徽章后是否写入仓库，仍由作者明确决定。

## 2. 作者数据口径

接口：`GET /v1/creator/analytics?days=7|30|90`

接口必须登录且要求创作者 `works:read` 权限。服务端只查询当前账号名下的作品，不接受任意作者或作品筛选参数。

看板展示：

- 作品详情浏览次数；
- 游戏启动与有效试玩次数；
- 有效试玩率（停留至少 30 秒的结束会话 / 启动事件）；
- 复访玩家（同一匿名设备在周期内至少启动两次）；
- 当前仍收藏作品的账号数；
- GitHub 源码构建次数、成功次数和成功率；
- 上海时区的逐日试玩趋势；
- 各作品的聚合表现。

隐私边界：作者只能看到聚合数值，不返回玩家账号、匿名设备标识、会话标识、访问地址或输入内容。收藏数表示当前状态；其余事件与构建指标按所选周期统计。

## 3. README 在线体验徽章

公开徽章地址：

```text
GET /v1/works/{workId}/badge.svg
```

该地址先经过公开目录门禁：只有仍处于公开发布状态的作品才能返回 SVG。作品撤下、暂停或不可见时，与作品详情一致地失败关闭，不让徽章绕过目录状态。

创作中心复制的 Markdown 形态为：

```md
[![在 GameHub 在线体验](https://mooyu.fun/v1/works/{workId}/badge.svg)](https://mooyu.fun/w/{workId})
```

SVG 是固定文案，不插入作品标题等用户输入；响应启用 `nosniff` 和限制性 CSP，可短时公开缓存。

## 4. 验收清单

- 普通账号无法读取作者数据。
- 创作者只能获得自己作品的聚合结果。
- 7、30、90 天以外的周期被拒绝。
- 没有事件时仍返回完整日期序列和零值。
- 公开作品徽章返回 `image/svg+xml`。
- 撤下或不存在的作品无法取得徽章。
- README 按钮只出现在已发布作品上。
- 窄屏下看板改为单列，作品指标表允许安全横向滚动。
- API 契约、客户端、服务单元测试、路由测试和 Web 构建全部通过。

## 5. 后续 G3 路线

建议按以下顺序继续：

1. G3.2：站内结构化反馈，作者确认后生成 GitHub Issue 草稿；仍不默认授予写权限。
2. G3.3：新手贡献任务、`good first issue` 映射与贡献者公开资料。
3. G3.4：Remix / Fork 来源证明和上游 Commit 追溯。
4. G3.5：新增由游戏 SDK 明确上报的可靠通关信号，再将有效试玩、复访和真实通关纳入发现排序，同时设置最小样本量和反作弊门槛。
