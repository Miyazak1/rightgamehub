# QQ 原生反向连接修复发布说明

本文件和命令用于准备发布，尚未执行线上更新。

## 更新与重启范围

| 对象 | 正式执行更新时的操作 |
| --- | --- |
| `mooyu-qq-napcat-1` | 以当前审计镜像为基础，只替换 `napcat.mjs` 中的反向 WebSocket 类，并重建此网关容器一次 |
| `mooyu-qq-worker-1` | 切换窗口停止后再启动同一容器；不更换镜像、不重建容器 |
| 现有 QQ guardian | 只更新 `image` 和 `identityHash` 绑定；定时器、服务文件、启用状态、恢复次数和次数上限保持原样，不重启守护器服务 |
| API、Web、交互执行器、日调度 | 不更新、不停止、不重启 |
| 网站数据库、QQ 数据库、桌面全部服务 | 不更新、不停止、不重启 |
| 两套论文 | 保持关闭，任何开关或重启策略不符即拒绝更新 |

这是原生网关修复，不能用此前只替换采样文件的 worker 包代替。本包不包含 API、Web、模型服务或论文开发。
仍存在腾讯会话失效后需人工扫码的可能；不会承诺重建后必定免扫码。

## 保留内容和门禁

- 保留原网关主机名、入口、命令、环境、端口、资源限制、权限、网络、登录卷及设备数据。
- 保留权限、预算、定时计划、业务历史、QQ 历史及旧锁定记录；不迁移或恢复数据库，不清理登录目录，不重试旧任务。
- 只允许审计过的原生基础镜像 `ac32edd…` 和源文件 SHA-256 `7967149b…`；原始 worker 四份文件也须与已验收的观测修复版本一致。发现现场不同，预检将停止，不能强行跳过。
- 用原 guardian 的身份绑定核验当前网关。正式切换后，只重新绑定新网关身份，不清零 guardian 的恢复状态或计数。
  预检要求 timer 已启用且 active，恢复状态有效；保留滚动 24 小时最多两次、至少间隔 15 分钟的既有自动恢复边界。
  若状态损坏、时间回退、待人工审核或 timer 未运行，则停止，不擅自重置计数或启停服务。
- 要求工作与发送均空闲，日计划距离下一次执行至少 45 分钟。旧锁、旧任务或待核对发送阻塞时，保留现场，不清锁、不标记成功、不补发。
- 切换前备份登录数据；停止 QQ worker 和网关后，再备份登录数据及 QQ 数据库，并完整读取校验。其他服务继续运行，备份不冒充跨库原子快照。
- 候选镜像构建上下文只有 Dockerfile 和补丁文件，私有配置、登录备份、数据库备份不进入镜像或上传包。

## 宝塔命令使用顺序

本轮仅交付文件。暂不要在宝塔执行以下命令。

1. 先结束本机使用同一 QQ 账号的测试会话，避免与服务器争用同一账号。保留其登录数据。
2. 执行 `server-create-upload-directory.txt`，只建立新的私有上传目录。
3. 只上传 `qq-websocket-owner-20261128-r2.tar.gz` 和同名 `.sha256` 到
   `/www/backup/gamehub/qq-websocket-owner-release-20261128-r2`，不要预先解压。
4. 执行 `server-prepare-and-plan.txt`，校验外部哈希、内部清单并预检。成功标记：
   `QQ_WEBSOCKET_PLAN_READY`。预检不会更新、停止或重启服务；会短暂持有维护互斥锁。
5. 另行决定正式更新时，执行 `server-update-gateway.txt`。该命令只执行上表中的操作，
   不执行数据库迁移、任务分发、论文开启或旧记录修复。

命令必须使用完整内容，不能把旧包或旧目录里的脚本拼接过来。私有 Node 从既有 `/root/mooyu-…-runtime-20261124-*/node`
中查找，并与当前 API 镜像的 Node 二进制核对。找不到或不一致时停止，不在 `/www` 下执行临时下载的 Node。

切换时 QQ 会暂时停止收发；在命令完成前不要发送验收消息、刷新二维码或改后台设置。
更新采用新的 Compose overlay，原 Compose、环境文件、旧发布包和旧锁记录均不改写。

## 成功、扫码及故障处理

- `QQ_WEBSOCKET_UPDATED_READY_NEW_MESSAGE_REQUIRED`：网关与后台当前可用，但仍须验收一条新的真实消息。
- `QQ_WEBSOCKET_UPDATED_SCAN_REQUIRED`：修复和保留项核验通过，登录入口已恢复，须到后台扫码确认，再验收新消息。
- `QQ_WEBSOCKET_STOPPED_REVIEW_REQUIRED`：命令停止，输出新维护记录及停止阶段。不会自动重复执行、自动恢复备份或自动回退。
  若故障发生在停止服务之后，QQ 可能仍处于停止状态；先保留输出，再使用本包的独立回退命令审核恢复。

需要回退时执行 `server-rollback-gateway.txt`。它仅使用本次新维护记录中的原镜像和相同登录卷，
再次短暂停止 QQ worker、回退网关程序、更新 guardian 身份绑定并启动同一 worker。
回退不恢复数据库、不删除新历史、不重置 guardian 计数，不恢复旧的单进程配置。
回退会带回原反向连接缺陷，只用于撤回本次程序修改。

```text

```

再执行 `server-check-new-message.txt`。只有本次更新完成之后的新输入，以及直接回复或关联任务最终回复
已取得远端发送回执且包含预期短语时，才返回 `QQ_WEBSOCKET_NEW_MESSAGE_CONFIRMED`。
旧成功记录、“任务已保存”、待发送和未确认回复均不算通过；命令本身不会主动发消息或重试任务。

## r2 预检修正（2026-11-28）

r1 的窗口规则遗漏已结束的对话与 GitHub 搜索事件，因此用户执行 plan 时被拦截，尚未停止 QQ 服务或应用补丁。只读分类证明 69 条均为 pending、attempts=0、无事件或阶段租约且关联一致：20 条成功对话，49 条已成功或失败结束的 GitHub 搜索。

r2 只在 QQ 网关更新预检中加入这两类终态事件，要求运行与阶段均有已发生的结束时间、无租约、无未完成尝试时钟、消息关联完整；对话仅允许 respond 成功，搜索仅允许 plan/search/gather/verify 的已成功或失败阶段。运行成功而阶段失败、活动或 uncertain 状态、未知工作流、尝试过的事件均不放行。原通用 cutover 规则不修改。

这些事件原样保留，不投递、删除、标记已送达或重试；更新过程中继续检查完整数据指纹。新 stage 和操作目录独立于 r1，旧归档和旧锁保持不变。无需重传 r1，不要覆盖旧目录；只上传 r2 到新目录，先执行 r2 plan，通过后再执行明确的 upgrade。
