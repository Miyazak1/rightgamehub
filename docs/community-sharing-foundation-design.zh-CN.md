# 游戏 AI 与计算机分享板块设计

状态：首版 S0–S2 已实现并完成本地验证；未推送、未上线。S3 生产环境验证及开放准备仍待完成。
更新日期：2026-10-08。
适用分支：codex/game-services-foundation。

## 产品范围

分享板块承载用户主动分享的游戏、AI 和计算机相关内容，包括外部链接、自己的短文、截图和图片。它使用统一内容底座，后续可以增加评论、专题、长文和官方精选。首版保持功能集中，数据身份、媒体生命周期、权限和审核从第一天建立清楚的边界。

用户已确认：首版包含分享、点赞和收藏，评论以后开放。此前的编辑精选资讯页、自动资讯采集和迷阵排行榜均不属于本轮方向。

首版包含：

- 最新分享列表、游戏 / AI / 计算机三个频道、分享详情。
- 一个编辑器同时支持文字、外部链接和静态图片，不强迫用户在“图文帖”和“链接帖”之间二选一。
- 我的分享、待审核状态、撤回和删除，以及仅自己可见的收藏列表。
- 点赞和取消点赞、收藏和取消收藏。
- 管理员审核、隐藏、恢复、举报处理，以及用户发帖资格和上传额度控制。
- Web、VS Code / Cursor、Harness 共享同一套客户端与 API。

评论、私信、热度算法、转发、用户自建频道、视频、动图、搜索服务和自动抓取网页摘要列为以后独立交付的能力，不因本设计预先运行后台服务。评论接口、输入框和评论数首版均不出现。

展示名称可继续讨论，底层使用 community 领域名称，不把“前沿”或“休息室”写进数据库语义。分享者身份与内容来源分开显示；用户分享不等于平台已核实新闻事实，内容审核通过也不代表新闻真实性背书。

## 用户路径与页面迁移

新分享入口使用 /community；列表、频道和详情支持可分享地址，详情稳定地址为 /community/posts/{postId}。编辑器草稿保存后保持同一 postId，修改、审核和删除不重新分配帖子身份。

发布路径：新建草稿 → 输入文字 / 来源链接 / 上传图片 → 预览 → 提交审核 → 在“我的分享”看到待审核状态 → 审核通过后公开。发布前清楚显示公开范围；上传完成不代表已经发布。

列表卡片显示作者、频道、标题、正文摘要、按需加载的缩略图、来源域名、分享时间和点赞数。详情显示完整正文、图片、来源链接及最后编辑时间。来源的发布日期只有用户明确提供时才显示为“来源日期（分享者填写）”，不把抓取时间或分享时间冒充新闻发生时间。

旧 /social 地址兼容到分享入口；原猜百科排行榜、成绩反应、挑战记录和旧社交通知先提取到猜百科专属入口，再切换导航。同步修正挑战失效页、挑战完成页、退出游戏等返回地址。保留原 API、数据和旧通知功能，禁止通过覆盖 SocialPage 造成历史互动无入口。

游客可阅读满足公开条件的内容；发帖、点赞、收藏要求登录并满足对应资格。收藏发生在站内账号下，与游戏库收藏分表，界面名称和空状态明确区分。外部链接使用已有宿主 openExternal 能力，并在 Web 环境安全打开。

## 模块结构与扩展原则

~~~
共享客户端 CommunityPage / PostEditor / PostDetail / MyBookmarks
                         |
                 /v1/community/*
                         |
        PostService / MediaService / InteractionService
                         |
      CommunityPolicy / ModerationService / Repositories
                         |
           PostgreSQL             CommunityMediaStore
                                      |
                         首版本机文件系统，后续对象存储
~~~

首版采用现有进程内的模块化实现，不增加常驻搜索、消息总线或独立社区微服务。API 负责权限和事务；图片处理通过受限后台任务执行，不能在列表请求或 API 主进程里同步解码大图。

扩展约束：

1. 稳定 postId 作为内容与互动的连接点，正文版本、媒体、互动、分类分开管理。
2. 筛选、权限、状态、时间等稳定字段使用有类型的关系字段；正文块使用有版本的受限 JSON，拒绝任意 HTML 和不受约束的 metadata。
3. 每种新增块类型先增加契约、服务端验证和客户端渲染器，再开放写入。旧客户端能显示“不支持的内容，请更新”，不能执行嵌入脚本。
4. 新业务优先增加明确的扩展表和 API，不靠无外键的 target_type / target_id 任意关联所有对象。
5. 未来模块有明确接入点，但不为未开放功能创建空接口、空队列或伪造计数。
6. API 错误码和 capabilities 独立版本化；新增字段保持旧读接口兼容，未知写字段默认拒绝。

## 内容与关系模型

下列为逻辑表和约束，迁移编号在编码时按分支最新迁移分配。本设计不修改数据库。

| 表 | 关键字段与约束 |
| --- | --- |
| community_channels | id、稳定 key、名称、enabled；预置 game / ai / computing，用户不能自建 |
| community_posts | id、author_id、channel_id、kind=share、visibility=public、publication_state、moderation_state、working_revision_id、published_revision_id、version、first_published_at、created_at、updated_at、deleted_at |
| community_post_revisions | id、post_id、channel_id、schema_version、title、blocks、content_hash、review_status、created_at；正文及摘要不可原地修改，工作版本另建记录 |
| community_media_assets | id、owner_id、post_id、state、输入/输出大小、摘要、宽高、variant 对象键、created_at、expires_at；所有权与帖子归属不可由提交正文覆盖 |
| community_revision_media | post_id、revision_id、asset_id、position、alt_text；同一帖子的复合外键确保不会引用其他帖子附件 |
| community_post_likes | post_id、user_id、created_at；唯一键 (post_id,user_id) |
| community_post_bookmarks | id、post_id、user_id、created_at；唯一键 (post_id,user_id)，按用户与收藏时间建索引 |
| community_post_stats | post_id、like_count；仅作可重算投影，与真实关系事务更新 |
| community_reports | post_id、reporter_id、category、details、status、resolution；每用户每帖最多一条待处理举报 |
| community_moderation_events | actor_id、post_id、revision_id、action、reason、前后版本与时间；管理员操作仅追加 |
| community_write_receipts | actor_id、operation、idempotency_key 摘要、request_hash、结果 ID、expires_at；同键异参拒绝 |
| community_media_reservations | owner_id、asset_id、预留字节、状态、到期时间；配额预留/转换/释放有原子语义 |

版本指针必须通过 (post_id,revision_id) 复合外键约束，不能只依赖应用“应该传对 ID”。频道归属、来源链接和图片顺序都是需要审核的内容；已公开帖更换频道同样通过新的提交版本生效。

visibility 首版只开放 public，不提前支持复杂群组可见性。公开读取同时要求作者账号有效、作者社交资料允许公开、帖子已发布且未被隐藏/删除。资料转为私密时内容停止公开，转回公开也不能恢复被管理员隐藏的帖子。发帖器解释现有隐私设置的影响，不自动修改用户主页可见性。

正文 schema_version=1 的块：

| 块 | 字段与限制 |
| --- | --- |
| paragraph | text；纯文字，按正文总长度计额 |
| link | HTTPS url、用户提供的 label；首版最多 3 个，不接受抓取后的 HTML |
| image | assetId、altText；最多 3 张，必须属于当前作者、当前帖子并已处理成功 |

标题、正文、图片、链接可以组合。禁止把“图片帖”“新闻帖”“转发帖”分别做成没有共同身份的业务表。kind 首版只有 share；长文或提问若以后具有不同规则，再增加受控 kind 与专属扩展字段。

客户端只能提供资产 ID，不能指定本机文件路径、对象存储键、已审核状态、作者、点赞数或发布时间。所有整数范围由 schema 限制；API bigint 计数和版本使用十进制字符串，避免客户端精度差异。

## 内容版本与审核状态

帖子公开状态和内容版本审核状态分开：

- publication_state：draft / published / withdrawn / deleted。
- moderation_state：clear / hidden。
- revision.review_status：draft / pending / approved / rejected / superseded。

首次发布仅在当前提交版本已批准且全部附件可用时设置 published_revision_id 和 first_published_at。普通用户不能直接写这两个字段。

编辑已公开帖子时，新版本进入工作区或待审核；公开页面继续读之前的批准版本，并在作者端提示“修改待审核”。审核拒绝不会替换公开正文。全帖被举报处置为 hidden 时，公开版本也停止返回。

每次审核绑定 revisionId、内容摘要和帖子 version；事务中加锁检查它仍是当前待审版本，再记录决定、切换公开指针、更新公开频道和状态。并发编辑或撤回后，旧审核请求返回 409，不能把旧内容重新发布。恢复隐藏与批准正文是两个不同权限动作，批准内容不能顺便解除隐藏。

编辑不刷新 first_published_at，列表不能靠反复修改或撤回重发刷到顶部。重新发布沿用原首发时间；新的原创分享使用新帖子，但受发帖限额与重复内容治理约束。

删除先建立不可公开读取的墓碑，解除公开引用后再做可重试的附件回收。审核证据、申诉和备份正在引用的附件不能被孤儿清理删除。正文历史与审计按配置保留；上线前确定留存策略及总预算，不把“保留历史”实现成无限保留全部图片副本。

审核通过只表示当前平台发布政策通过，不应展示“新闻已证实”之类标签。

## 点赞与收藏

点赞、取消点赞和收藏、取消收藏使用 PUT / DELETE，而不是 toggle。相同请求重试不会反转用户意图，数据库唯一约束防止重复关系。

写入事务中检查可见性，插入/删除实际发生时才增减 like_count，计数不得为负。统计与关系同事务提交；周期性、小批量核对用于修复，不把全表重算放在列表请求中。首版允许用户给自己的帖子点赞，点赞只表示回应，不作为竞技成绩或排名依据。

收藏为私人关系，不公开收藏者和收藏次数，也不向作者发送“某人收藏”的通知。收藏不能突破原帖权限：帖子撤下后只显示不可用占位或从公开内容结果中省略，用户仍可移除自己的收藏。取消自己的点赞/收藏允许对不可见帖子执行，并返回幂等成功，不借此泄漏正文。

首版不生成每次点赞的通知。以后增加通知时，同一事务增加待投递记录，用唯一事件键去重和逐条租约重试；不得仅靠提交后的进程回调保证通知可靠，也不得把数据库自增 ID 当作提交顺序水位。

## 图片的上传与分发

CommunityMediaStore 提供 put / open / stat / remove，业务使用资产 ID，存储内部持有对象键。首版落在独立社区媒体目录，后续增加对象存储适配器时不修改帖子 ID 或已发布正文。

路径如下：

1. 作者创建帖子草稿，为单张图申请上传资产；服务端验证发帖资格、绑定 postId，并原子预留用户与全站额度。
2. 上传到不可公开访问的暂存位置；执行声明大小和实际流量上限，不先把无限请求体读进内存。
3. 完成上传后排入有上限的处理队列。任务绑定不可变输入摘要，只有当前租约能提交输出。
4. 受限进程校验真实格式、像素、帧数，旋转并清除 EXIF 等附带元数据，生成缩略图和展示图。
5. 持久化对象并验证摘要后，事务将资产变为 ready，额度从“预留”转为“实际占用”；崩溃残留按任务身份对账。
6. 投稿时检查每个 assetId 的所有权、帖子归属、ready 状态和额度，再将它绑定当前修订。
7. 只有被公开批准版本引用且内容仍可见的图片，才允许通过媒体端点读取。

输入首版支持 JPEG、PNG、静态 WebP；输出为静态 WebP。GIF、动画 WebP、SVG、视频和外站图片代理以后按独立策略支持。仅文件扩展名或客户端 Content-Type 不足以判定实际格式。

同一帖子的新修订可引用原附件；不同帖子首版不跨帖复用资产，避免权限、删除和配额归属混乱。新上传也不能替换原资产的字节内容；修改图片需要新的资产 ID。

图片端点根据已批准修订重新判断可见性，不直接暴露整个目录给静态服务器。首版响应使用 private / no-store 和正确 Content-Type、nosniff；隐藏、删除或资料收紧后，新请求立即拒绝。已经下载到用户设备的图片无法收回。未来引入 CDN 必须补充撤销与失效传播设计，不能只给永久公开 URL。

原图仅用于处理和待审核证据需要的短期留存，首版不提供公开原图下载。缩略图用于列表，展示图仅在详情/查看图片时加载，不能在列表隐形预加载全部大图。

## 外部链接与内容边界

首版只保存用户主动输入的 HTTPS 链接和介绍，显示解析后的实际域名。拒绝带凭据的 URL、危险 scheme 和明显的本机/内网目标；不嵌入外部 iframe，不执行来源页面脚本。

首版没有服务端自动抓取，因此不会因用户提交任意 URL 就触发服务器出网。自动标题、Open Graph、远程封面、RSS、AI 摘要等以后通过独立预览任务接入；接入前需要目标地址与每次重定向校验、DNS 解析后的私网阻断、字节/超时限制、缓存、版权与来源处理。预览失败不能阻塞纯链接分享。

自己编写的摘要与原文链接分开；转载全文和上传图片不能仅凭“注明来源”认定有权使用。首版提供来源说明与侵权举报入口。

| GET /v1/admin/community/review | 待审内容与举报队列，有界分页 |
| POST /v1/admin/community/posts/{postId}/decisions | 固定版本的审核、隐藏或恢复决定，必须填写理由 |

上传凭据不能同时授权发布、修改他人资产或读取任意文件；作用域只限一名用户、一个资产、限定字节与期限。复用普通账号鉴权，不创建游戏运行 gameSession。

典型错误码：COMMUNITY_DISABLED、SHARE_NOT_ALLOWED、POST_NOT_FOUND、POST_VERSION_CONFLICT、MEDIA_NOT_READY、MEDIA_QUOTA_EXCEEDED、REVIEW_VERSION_STALE、RATE_LIMITED。不可见和不存在的帖子统一为 404；作者在自身管理端可以看到明确审核状态。

服务端能力控制以独立配置为准。上线准备阶段默认关闭公开发帖和媒体上传；接口前置拒绝，不能仅隐藏按钮。读取、发帖、上传、点赞和收藏可分别降级。后台操作使用独立管理员授权，不因 canPublish 游戏而获得社区管理权。

## 查询与权限一致性

最新列表按 first_published_at DESC、id DESC 使用复合游标，默认每页 20，最大 50。相同首发时间不会漏项或重复；后续页面沿用初始查询时间上界，刷新后获取新内容。游标绑定频道、作者、筛选和查看者范围，损坏或错用返回明确参数错误。

公开筛选条件在数据库分页之前应用，不能先取 20 条再在内存过滤屏蔽作者。列表、详情、收藏、图片以及未来搜索共用 CommunityPolicy；详情中拒绝返回未批准正文与暂存对象键。

帖子最少需要公开时间索引、频道公开时间索引、作者管理索引。点赞与收藏分别按 (post_id,user_id) 和 (user_id,created_at,id) 索引；待审与过期资产使用独立局部索引。查询批量读取作者与当前用户互动状态，避免按每帖发起额外请求。

首版内容响应使用 no-store，避免共享缓存混入作者草稿、私人收藏或屏蔽结果。后续缓存只能在完整处理发布版本、权限代际与撤回失效后启用。公开资料可由游客访问；屏蔽用于登录关系下的隐藏和互动限制，不能宣称它让公开内容对被屏蔽者绝对保密。

## 不扩容条件下的初始限额

以下数字为实施候选值，不是服务器容量实测或已经上线的配置。配置集中返回给客户端，服务端和数据库配额为最终准则。

| 项目 | 初始候选值 |
| --- | --- |
| 标题 / 正文 | 120 字 / 4000 字，总 JSON 请求上限 32 KiB |
| 正文块 / 链接 | 最多 32 块 / 3 个 HTTPS 链接 |
| 单帖图片 | 最多 3 张 |
| 单张输入 | 2 MiB，最多 1600 万像素；实际解码峰值需验证 |
| 派生图 | 展示图最长边 1600，最大 1 MiB；缩略图最长边 480，最大 160 KiB；压缩后仍超限则拒绝 |
| 用户上传 | 每日最多 20 张，已用与预留合计最多 50 MiB |
| 社区媒体总预算 | 首期候选 2 GiB，和磁盘水位限制取更严格值 |
| 未引用资产 | 24 小时到期；清理前检查工作版本、公开版本、审核与备份引用 |
| 发帖 / 草稿 | 每用户每日 10 次提交，最多 10 份未发布草稿；编辑提交同样计额 |
| 用户待审核 | 最多 3 条；平台待审核上限另行配置，满额暂停新投稿 |
| 图片处理 | 并发 1、等待队列最多 20、单任务 5 秒、隔离进程内存上限候选 256 MiB |
| 写入幂等回执 | 常规请求至少保留 24 小时；对象唯一键继续防止重复持久关系 |

额度在并发申请时通过数据库原子预留，按用户和全站统一预算锁定，不用每个 API 进程自己的计数替代。声明大小、输出与暂存空间一起计入；失败、取消、过期只释放一次。磁盘检查失败时拒绝新图片，但允许浏览和清理，文本投稿是否继续由独立开关决定。

单进程并发 1 不能证明整机有余量。图片处理还必须与源码构建、规则构建、备份等后台任务错峰或接受统一准入限制。上线门槛包含 API / Realtime 混合负载验证；图像解析本身应在有硬资源限制的隔离进程执行，不能只用 Promise 超时包装主进程 sharp。

第一阶段不需要云存档、不运行 AI 模型生成摘要、不对每次浏览自动外抓内容。记录处理耗时、队列长度、拒绝原因、媒体总占用与请求尾延迟；数据不足时不承诺并发人数或无需扩容的长期容量。

## 发布治理与上线前置条件

用户已选择开放用户投稿，首版不因先前的论坛顾虑退回“只允许官方发内容”。发布方式采用可配置审核策略，初期候选为全部投稿和实质编辑人工审核。先审后发是本方案的运营选择，不声称所有技术分享依法都必须逐条预审。

身份认证、用户协议、举报申诉、审核运营与媒体处理方案需要在公开投稿前完成适用性确认。现有邮箱验证码证明邮箱控制权，不应直接标记为真实身份认证完成。测试白名单和管理员放行也不是公开服务资质或身份要求的替代品。

相关依据：

- [互联网论坛社区服务管理规定](https://www.cac.gov.cn/2017-08/25/c_1121541921.htm)：互动信息发布的主体责任、身份认证和举报处理。
- [互联网跟帖评论服务管理规定](https://www.cac.gov.cn/2022-11/16/c_1670253725725039.htm)：服务范围包括评论、回复、点赞等，评论尚未开放不等于其他互动不需核实适用要求。

底层通过统一 CommunityPolicy 接入资格校验和审核策略，具体核实方式不硬编码进帖子表。没有完成发布准备时保留开关关闭；可以完成本地开发和测试，但不能据此宣称已满足公开运营条件。

| 阶段 | 交付与完成条件 |
| --- | --- |
| S0 内容基础 | 契约、迁移、权限、版本、文字/链接草稿与审核事务；真实 PostgreSQL 测试通过；功能开关默认关闭 |
| S1 图片与容量 | 资产绑定、限额预留、隔离处理、缩略图、媒体读取、孤儿回收和备份恢复；越权与故障恢复测试通过 |
| S2 分享体验 | 最新/频道/详情/我的分享、点赞、私人收藏、管理员队列；替换旧入口并保留猜百科功能；三宿主适配 |
| S3 发布验收 | 适用运营条件确认、小范围验证、实际部署资源限制下混合负载、媒体与数据库联合恢复、撤回可见性验证 |

S0–S2 是同一首版的连续实现阶段，文字接口完成不能称为“图片分享已完成”，设计或迁移落地也不能称为“分享板块已上线”。

必测行为：

- 相同请求重试不会重复建帖、重复提交、重复预留空间、重复点赞或收藏。
- 相同幂等键不同正文返回冲突；并发编辑不会覆盖他人已确认的版本。
- 审核旧版本、并发撤回、管理员隐藏后再批准正文，均不能重新公开错误版本。
- 未审核正文、原图和临时对象不能从详情、列表、图片端点或收藏绕过访问。
- 伪造作者、资产 ID、跨帖/跨用户图片引用被拒绝；MIME 伪装、畸形图、像素炸弹与动画超限不能拖垮 API。
- 并发配额申请不能超过用户或全站上限；任务失败和进程重启后计量不会泄漏。
- 重复上传完成、处理提交后确认丢失、清理与投稿竞争均可恢复。
- 取消收藏可清理不可见内容；收藏者名单不公开；屏蔽和主页隐私变化作用于全部读取路径。
- 游标相同时间排序、频道切换、最后一页、空列表和已撤下内容不会漏验权限。
- 图片处理期间与现有联机流量共同测试；处理和数据库提交不能占满线上连接池或破坏现有尾延迟门槛。
- 旧 /social、猜百科榜单、挑战返回和通知入口保留可达性；云存档开关继续关闭。

备份必须包含数据库和引用的媒体对象，不能只验证 pg_dump。数据库一致快照导出的资产清单须覆盖该快照引用的全部对象；备份期间保护这些不可变对象不被回收，恢复时逐项核对摘要。媒体丢失、数据库指针孤立或历史私密内容被公开均属于验收失败。

### 实现细节与原设计的对应

- 公开正文由 published_revision_id 指向；编辑产生独立 working_revision_id。审核检查帖子版本和修订 ID，旧页面不能批准新内容。隐藏与正文审核状态独立，批准新正文不会解除隐藏。公开响应不包含审核理由。
- 配额预留直接记录在 community_media_assets.reserved_bytes，使用全局事务锁原子检查总量；未另建一张同义预留表。状态为 reserved / uploaded / processing / ready / failed / deleting / deleted。
- 上传使用普通 bearer 与受限资产记录，共同绑定用户、帖子、摘要、输入大小和过期时间；没有另签发独立上传令牌。重复传输同一资产只接受相同字节。
- 首版固定每页 20 条，管理员每页 50 条；游标保留数据库微秒精度并绑定查看者和筛选范围。审核列表包含工作版本与不同的已发布版本，以免误把举报当成针对新草稿。
- 图片处理复用现有 worker 的空闲时间；生产使用可选 community-images profile 中的无网络容器，单任务、0.5 CPU、256 MiB、只读系统目录、32 个进程上限。关闭图片功能时不启用该容器。原图不公开；列表按需取缩略图，详情和审核取展示图。
- 孤儿 24 小时后可回收；非删除帖的所有历史修订继续保护图片，删除帖至少再保护 30 天。回收先提交 deleting 意图，再删除文件，下一轮可恢复中断的清理。帖子最多 100 次修订，暂不自动裁剪历史。
- 错误图和处理故障保留失败状态，不循环重试；工作进程崩溃留下的超时租约最多重新领取 3 次。预留和失败资产最终按孤儿策略回收。文件邮箱的过期任务定期清理。
- 发帖资格通过管理员的 community_members 策略开放，普通账号的 can_publish 不参与。首版没有自助申请入口，资格不是实名认证证明。
- 社区总开关同时控制读取、点赞、收藏；投稿和图片上传另有开关。设计中的独立点赞/收藏降级开关留待需要时加入。
- /social 兼容进入分享页；猜百科原排行榜、通知、挑战与隐私设置保留在 /games/guess-baike/community。个人主页新增“查看公开分享”。Web、VS Code/Cursor 与 Harness 共享代码；编辑器宿主本轮完成构建验证，未重新做人工安装验收。

### 部署与回退边界

部署前先备份；发布代码后执行迁移到 50，再重建 API、worker 和 Web。COMMUNITY_ENABLED、COMMUNITY_POSTING_ENABLED、COMMUNITY_IMAGES_ENABLED 默认均为 false。计划开放时先确认管理员审核安排和公开运营条件，再逐步打开读取与投稿；图片另需启动 community-images profile。CLOUD_SAVE_ENABLED 保持 false。

备份脚本会暂停原有 worker（同时暂停后台作品验证与社区图片处理），在数据库导出后复制 community-media 卷，然后恢复 worker 原先的运行状态。API 和联机服务不因此停止。不能单独拿数据库备份代替媒体备份，也不要在备份期间额外运行媒体回收。

本迁移只新增社区对象。紧急回退优先关闭三个社区开关并停止可选图片容器，保留数据库及图片。旧版本严格要求 49 个迁移，因此不能在 50 版数据库上直接启动旧 49 版镜像并假定 ready 通过；完整回退需要匹配版本的数据库与媒体备份，不能现场删除社区表或迁移记录。
