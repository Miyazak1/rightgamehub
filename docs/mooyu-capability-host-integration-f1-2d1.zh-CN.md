# 墨鱼工坊多宿主接入协议 F1.2d-1

版本：v1.0
状态：协议、共用客户端、认证控制面传输、服务端宿主网关、共享任务界面、可信产物打开、编辑器/Harness 与桌面宿主可靠性闭环已实现
更新日期：2026-10-29

## 1. 目标

F1.2d-1 冻结桌面能力节点进入 Codex MCP App、DeepSeek Harness 右侧栏、Cursor / VS Code
侧栏和未来墨鱼桌面窗口时共同使用的任务语义。能力引擎、文件授权、安装、更新、沙箱和产物存储
继续只有一套；各宿主只提供轻量入口，不能各自实现 OCR 或另一套任务循环。

## 2. 连接边界

- `control-plane` 是默认连接：宿主向平台提交任务，本地节点通过已有出站连接领取；它适用于所有宿主，
  不依赖 Webview 访问 localhost，也不要求开放入站端口。
- `local-pipe` 只允许受信桌面应用和编辑器扩展使用，作为同机低延迟增强；MCP App 不允许直接声称
  获得本机命名管道。
- Webview 不持有节点令牌、配对码或桌面控制密钥。宿主扩展或平台控制面代为传输。
- 用户文件仍使用现有任务级文件授权；任务输入只能引用授权 ID，不能把任意本机路径交给侧栏。

## 3. 协议

`@gamehub/host-contract` 现在导出 `capability-host-profile-v1`、`capability-host-run-v1`、
`capability-host-artifact-v1` 和 `capability-host-event-v1` 的严格规范化函数，以及统一客户端：

- `snapshot()`：恢复宿主可见的活动任务；
- `submit()`：用幂等键提交能力任务；
- `get()`：按运行 ID 恢复状态；
- `cancel()`：请求取消，最终状态仍由控制面确认；
- `artifacts()` / `openArtifact()`：列出并由受信宿主打开产物；
- `subscribe()`：接收单调序号事件，忽略重放事件。

运行状态固定为等待授权、排队、安装、运行、成功、失败和取消。宿主不得把部分结果伪装成成功，
失败必须带稳定错误码，非成功状态不得声明公开产物。

## 4. 已完成的证据

- 同一客户端在模拟 Codex MCP App、Harness 和 Cursor 传输上完成提交、查询、取消和产物打开；
- 事件序号可阻止旧进度覆盖新状态；
- MCP App 伪装本机管道、运行中伪造产物、失败但没有错误码均被失败关闭；
- 输入正文限制为 64 KiB，较大内容和用户文件必须通过已有授权与内容寻址产物传递。

1. `createCapabilityControlPlaneTransport()` 将协议操作映射为同一组登录态 API；访问令牌刷新继续由
   平台 API 客户端负责，Webview 不接触节点令牌；
2. 传输使用 Agent 作用域路径，幂等提交、查询、取消、产物列表和产物打开均携带当前宿主画像；
3. 订阅采用有界轮询恢复：一次断网不会清空最后状态或终止后台任务，重连后只发出发生变化的运行；
4. 产物打开先验证短期指令，再交给受信宿主执行；无效过期时间、伪造运行或未知打开方式不会触碰本机；
5. 自动测试覆盖登录作用域、断线恢复、去重事件和失败关闭。

### F1.2d-2b（已完成）

1. 已在 API 上实现 Agent 归属校验后的宿主网关，直接投影现有 `agent_runs`、阶段和产物账本，
   没有另建第二套任务数据库；

   能力契约 key 和版本，禁止用名称猜测路由；绑定记录只能退役，不能原地改写；
3. 宿主提交使用现有 Runtime 幂等键、能力授权快照和运行事件；取消对已领取或正在执行的阶段失败关闭，
   避免“界面显示取消但本地仍在写文件”的竞态；
4. 成功运行才能列出产物，打开产物返回五分钟有效的虚拟定位指令，原始本机路径和节点令牌不会交给 Webview；
5. Cursor / VS Code、Harness 与 Codex MCP App 复用同一服务端投影和认证传输，不为宿主复制 Runtime。

### F1.2d-2c（已完成）

1. 新增无界面的 `createCapabilityTaskSurface()`，统一加载、轮询恢复、排序、取消、产物动作和错误状态；
2. 共享任务区已接入平台机器人控制台。MCP App、Codex、Harness、Cursor、VS Code 和未来桌面壳只提供
   宿主画像，任务语义和界面实现保持一份；普通网页不会伪装成本地宿主；
3. 关闭侧栏只解除订阅，不会取消后台任务；取消必须由用户明确触发，并继续服从服务端阶段租约门禁；
4. 任务事件与刷新并发时使用实时修订号和 `updatedAt` 双重保护，已经完成的新状态不会被稍后返回的旧快照覆盖；
5. 未提供可信产物打开器的宿主会保留产物数量与运行记录，但不显示虚假的“打开”动作；只有宿主声明并实现
   可信打开器后才启用产物列表和打开按钮；
6. VS Code / Cursor Webview 和 Harness 侧栏真实构建均通过；协议、传输和任务区定向回归 14 项全部通过。

## 6. 当前边界

- 共享任务区已进入各宿主复用的平台客户端；它目前用于查看、恢复和安全取消，不把尚未提供的能力伪装成可用；

  与现有 Windows 桌面壳已接入打开器，普通网页仍不会获得本机打开能力；
- 桌面接入完成代表现有桌面基座具备可信产物打开能力，不等于面向最终用户的完整桌面产品已经完成；真实 OCR、
  论文解析等能力包及其桌面交互仍按 F1.2d-2d-2c / F1.3b 推进；
- 数据库集成测试随隔离 PostgreSQL 测试环境运行；普通本地回归在没有该环境时会明确跳过，不会伪装通过。
