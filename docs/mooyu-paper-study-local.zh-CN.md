# 论文研读：共享工具与隔离验证

入口为“工具 → 论文研读”（`/tools/paper-study`），网页与 Electron 复用同一个 React 工作区、主题变量、账号客户端和操作契约。匿名用户先登录；论文、原文、分析和草稿均按当前账号归属校验。界面包含论文列表、原文/分析/待审稿标签和原文依据侧栏，支持引用跳页、逐段证据链接、PDF 缩放和窄窗口布局。

下述离线回放与真实模型入口仍使用独立的本地内存服务，不读取正式账号和存档。新增的 PostgreSQL 持久化、正式 API 账号适配和研究运行时恢复见 [持久化说明](./mooyu-paper-study-persistence.zh-CN.md)；该适配默认关闭，本轮未在生产启用或迁移数据库。

## 默认离线回放

```powershell
node scripts/verify-paper-study-clean.mjs
node scripts/verify-paper-study.mjs
node scripts/start-paper-study.mjs
```

手动入口使用任意 `@example.test` 测试邮箱，验证码只打印在启动终端。默认不访问生产或模型服务。导入本机已有的公开样本 `.runtime/paper-layout-audit/1706.03762v7.pdf`。该样本 SHA-256 为 `bdfaa68d8984f0dc02beaca527b76f207d99b666d31d1da728ee0728182df697`。不在源码中附带本机路径、密钥或 PDF 二进制。

回放会重新解析真实 PDF，再按当前语义提取、证据核验、分节成稿和全文核验流程运行，14 个模型响应来自此前未人工修改的成功录制。不同 PDF 可以导入和阅读，但不会套用该样本的分析；哈希不匹配会明确拒绝。回放不等于本轮新的真实模型验证。

`verify-paper-study.mjs --source <干净导出的 source 绝对目录>` 可直接对独立导出构建执行 Electron 验收。干净目录脚本只复制实际导入依赖和指定录制样本，排除旧 D1 原型；平台 API 客户端中原有的 D1 诊断方法仅从测试导出中移除，不修改工作区旧改动。功能清单在导出内重新生成并校验。

## 可选真实模型模式

只有显式运行以下入口才启用真实模型；从当前进程环境读取 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 与 arXiv 请求必需的 `AGENT_ARXIV_CONTACT_EMAIL`，不要把密钥写入源码或聊天。

```powershell
node scripts/start-paper-study.mjs --live
```

密钥仅由本地 API 进程使用，不传给 Electron、渲染页面或日志。导入时填写版本化 arXiv ID。分析前复用既有 arXiv 获取器取回公开版本并核对 PDF 哈希；仅有标题、用户填写的链接或上传同意，不能把私人文档标为公开资料。没有匹配公开来源的文档仍可阅读，但不会外发给模型。

自动真实窗口验收入口为 `node scripts/verify-paper-study-live.mjs`。它只从被忽略的 `.env.paper-text-draft.local` 读取上述三个字段（联系邮箱也可来自当前进程环境），以独立环回 API 服务供 Electron 操作；密钥不进入 Electron。原始模型请求、响应、阶段产物和界面截图仅保存到 `.runtime/paper-study/live-*`，不自动重试或修改结果。

补齐联系邮箱后的一轮真实模型验收已通过：`live-9DxGMb`，模型 `deepseek-flash`，14 次调用、零重试。真实 PDF 导入及缩放、公开来源哈希核对、分析与证据跳页、私有待审稿生成及逐段引用、刷新重开与退出登录清理均通过。保存了 23 条主张、15 个证据片段和 12 段正文绑定，阅读模式为 `text-only-draft`，人工审阅要求与公开发布禁用标记保持开启。没有人工修改生成结果，没有访问正式 API 或数据库。该记录仅证明当前样本的本地闭环，不能替代其他论文或生产持久化验收。更早的缺配置尝试在调用模型前停止，其失败记录仍独立保留。

处理器复用现有语义与分节文章工作流，模型预算有界，失败即停，不自动重试。扫描件或质量阻断文档不会进入分析；复杂表格、公式、图示不能可靠核验时只使用安全正文，保留阅读范围、人工审阅要求和逐段证据绑定。不以字数作为硬目标。不提供发布操作。草稿只在全文门禁通过后作为当前用户的私有待审稿保存。

当前服务是本地闭环验收实例，不宣称普通用户论文功能已在线，也不自动把未审查的旧论文或 D1 改动纳入安装包。

## 自动成稿 v9 的编辑约束

v9 在生成前按冻结主张组织“依赖关系与距离”等具体主题，未分类内容按原文对象分组和拟题，不再把它们汇入“其他可核对的主张”。标题不会把未出现的序列范围加入空间距离等其他领域的事实。每段保持论文归属，同源事实可由一次归属统领；同段重复以作者/论文为主语的报告式分句会被门禁拒绝。主题和主张集合在生成前确定，生成后不通过文本替换修稿。

旧 v8 录制与不可变产物仍按冻结版本验证；新模型任务默认 v9，段落提示版本为 13。干净目录的 100 项测试及构建通过，覆盖原始录制的重复报告句、跨领域主题拟题、归属缺失拒绝、主张覆盖和逐段绑定。

随后的一轮 v9 真实模型验收 `live-C1Z8bW` 在首节停止：语义分析通过，正文仍包含“论文作者指出…”与“作者提出…”两个报告式分句，触发 `AGENT_PAPER_ARTICLE_REPETITIVE_REPORTING_CLAUSES`。3 次模型调用、零重试，未生成或保存草稿；原始响应完整保留，未人工改写，未继续生成后文。该轮不视为完整成稿验收通过。

段落提示 v14 进一步在生成前提取各条冻结主张中的字面说明对象，给问题—已有安排—提出方案提供对象转接计划；不改写事实或生成结果。未知对象保持未指定，不猜名称。新回归包含 v13 的原始失败响应和非 Transformer 的方案对象案例，干净目录 102 项测试和构建通过。

## 已保存草稿的窗口补验（不调用模型）

若成稿已通过内容门禁而后续窗口验收失败，可使用保存的原始记录补验，不重新生成：

```powershell
node scripts/verify-paper-study-saved.mjs --recording .runtime/paper-study/live-FgvZgS
```

入口只接受本工作区隔离记录目录，核对 PDF 哈希、草稿内容、段落绑定、证据摘录及原始 composition/verification 产物。载入原草稿 ID、内容和证据到独立内存服务；分析、生成和校验处理入口均禁止调用，不读取模型凭据。原始记录保持只读，新验收结果写入独立 `resume-*` 目录。

`UnknownVizError` 的原始失败位于草稿保存后的 `capturePage()` 阶段；窗口补验为截图增加窗口可见状态恢复、两个渲染帧等待和带阶段标签的诊断，仅对此错误允许一次有限重试，其他错误和内容门禁不重试、不吞掉失败。`capturePage` 的可见性及 `stayAwake` 参数参照 [Electron 官方文档](https://www.electronjs.org/docs/latest/api/web-contents#contentscapturepagerect-opts)。本地测试覆盖一次合成失败后恢复、连续失败停止、空图/其他错误拒绝及已保存内容篡改拒绝。未将底层显卡或驱动认定为确定根因。

首次补验 `resume-UTh3lG` 的三张截图均成功，继而发现刷新竞态：论文列表中已有“私有待审稿已保存”，不能证明正文页签已就绪。验收脚本改为等待正文区域的状态与页签同时出现，补齐列表状态不能冒充正文就绪的回归。
