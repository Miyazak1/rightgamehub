# 公开调研发布链路统一整改

本次实现接续 `blog-system-architecture-assessment.zh-CN.md` 的评估。评估中的“未实施”指评估提交时的状态，本文件记录后续实现。生产安装目录仍为 `/www/gamehub`，生产配置仍为 `deploy/.env.prod`；备份目录仅保存上传资产、日志及恢复材料。

## 请求与预算

- 模型请求统一经过 `compileAgentProviderRequest`。验证 JSON、Unicode、NUL、消息数、字节、输入/输出预算和超时；拒绝发生在模型派发前，保留有界诊断元数据，不记录密钥或正文。
- 动作账本仍保留原有 64 KiB 约束。Provider 动作改存产物引用、完整请求哈希和模板/模式版本；新增 0161 的不可变输入产物表保存完整请求。产物与动作在同一事务内创建并绑定当前有效阶段租约。重放比较完整请求及策略摘要，避免相同幂等键被新输入冒用。
- Provider 请求紧凑 JSON 上限 512 KiB，封装请求上限 768 KiB；产物实际 PostgreSQL JSONB 文本上限 1 MiB。工具和领域动作按实际 PostgreSQL JSONB 大小提前校验 64 KiB，不能用 JavaScript 字符数代替。
- 模型输入预算采用消息 UTF-8 字节加每条 64 的保守上界，包含系统指令及纠正内容。选题每次 18,000，写作每次 24,000；两次选题加两次写作至多 84,000，仍在原有 90,000 输入预算内。输出和调用次数上限保持原策略。
- Prompt 是冻结证据的有界视图，保存原始载荷哈希与截取/遗漏信息；不修改完整工具证据。选题保留仓库身份和线索，写作保留材料来源；正文过长按明确边界缩减，仍不能满足预算则明确拒绝。服务端继续用完整冻结证据做选题、引用、冷却和发布校验。
- 引用摘录遵守同一个 900 字符契约。所有截取避免切断 emoji 的代理对。

## 运行控制和界面

- 共享立即运行准入函数，校验启用状态、公开模式和 Worker 心跳（包括异常未来时间）。命令端仍在锁内检查当前状态与活动任务，防止并发重复启动。
- 新客户端使用 `requestNow` 控制立即运行，使用 `activation` 控制恢复计划。保留旧 `manualRun` 能力字段，避免已有桌面客户端失去恢复暂停计划的入口。旧客户端二进制不会因服务器部署自动换新。
- 展开的运行阶段随列表刷新更新；终态按 `updatedAt` 更新缓存，读取失败显示失败，不继续伪装成旧的运行中状态。详情在数据库只读一致快照中读取。
- 阶段取消通过执行上下文传到 Provider、工具及 GitHub 网络请求。派发前取消释放预留；已经派发而没有确定回执的调用保持 uncertain，不当作零调用，也不允许盲目重派。取消不是撤销外部已经发生的操作。

## 部署和恢复

- 迁移只新增 0161，不修改 0001–0160。158/160/161 的受校验基线以事务方式升级；失败不留下半套迁移。应用回滚保留新增表与线上数据，不降级数据库。
- 构建角色从生效的 Compose 配置确定，最后追加本次独有的发行镜像覆盖层。人工配置仍保留，重命名的多层回滚镜像覆盖不能把新版本重新指向旧镜像。
- 激活后检查实际镜像标签，校验六个关键运行模块 SHA-256，再检查 `/ready`、161 迁移、练习工具、鉴权和论文关闭。任一检查失败触发原有回滚。
- 恢复材料保存实际 image ID、标签和验证过的源文件哈希。只有当前运行服务被更新，不自动启动可选任务。配置文件、数据库卷及上传媒体不清理。
- 论文四个开关继续为 false；此次没有启用或恢复论文任务。
