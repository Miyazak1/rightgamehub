# O2：公开作品链接与传播元数据

## 目标

让每个已经公开的作品拥有一个可长期分享、可被搜索引擎和社交平台识别的地址，而不是把带 Hash 的站内路由直接暴露给外部渠道。

## 已完成增量

- 稳定公开地址：`https://mooyu.fun/w/{workId}`。
- 服务端按作品输出 `title`、`description`、canonical、Open Graph 和 Twitter Card 元数据。
- 无论从站外链接还是首页、发现页和其他站内入口进入作品详情，地址栏都使用 `/w/{workId}`；无 JavaScript 时仍提供“打开作品”入口。
- 作品详情页提供使用 GameHub 方形节点图标的统一分享入口，支持系统分享、复制链接和下载分享图。
- 服务端按作品封面、标题、作者及许可证信息生成 `1200×630` PNG 分享图；无封面时使用品牌背景安全降级。
- Open Graph 和 Twitter Card 使用作品分享图，不再直接依赖原始封面比例。
- 创作者中心生成的 README 徽章链接到稳定公开地址。
- 公开地址继续经过目录服务校验，未发布、撤下或不存在的作品不会获得公开页面。

## 架构边界

- 作品浏览和游玩仍属于“发现”，不新增社区游戏馆，也不改变玩家个人游戏库语义。
- `/w/{workId}` 是用户可见的作品详情主地址；站内 React 可以继续使用 `/works/{workId}` 表示内部状态，但不得把 Hash 路由暴露到地址栏。
- 站点来源使用服务端受控的 `GAME_SHARE_SITE_ORIGIN`，不信任请求的 Host 头。
- Caddy 只将 `/w/*` 交给 API，其余 SPA 静态路由保持不变。

## 验收

1. 直接打开 `/w/{publishedWorkId}`，或从首页、发现页进入作品详情，地址栏都保持为该稳定地址。
2. 查看页面源代码能看到作品独立的标题、描述、canonical 和社交卡片字段。
3. 特殊字符经过 HTML 转义，不会形成脚本或属性注入。
4. 作品详情的系统分享、复制链接和 README 徽章均使用 `/w/{workId}`。
5. `/v1/works/{workId}/share-card.png` 返回 `1200×630` PNG，下载动作返回附件文件名。
6. `/w/{workId}`、分享图与徽章一样，只对目录服务允许公开访问的作品返回成功。

## O2 后续增量

完成公开链接与分享图后，再基于实际传播数据依次实施：渠道参数与来源归因、作者可见的访问转化漏斗。现有作者统计不重复建设。
