## 后台入口

在现有“小墨鱼管理”中选择 Agent，身份与头像下方新增“插件管理”。

- GitHub：展示安装版本、本 API 进程的装配／启用状态、交互入口配置检查、已有能力授权及最近5条 GitHub 交互任务故障。
- QQ：通过原签名管理链路读取实际 worker 的插件版本、启用与生命周期状态，另列群回复开关、QQ 登录／连接状态及本进程最近一次轮询故障。
- “管理 QQ 接入”和“管理调用者权限”定位至原表单；原登录、扫码、密码登录、群／用户白名单、任务发起权限、CAS 冲突处理及操作记录继续复用。没有创建第二份权限或插件开关数据库。
- 页面每15秒刷新；失败时清除旧快照，不保留“已连接”假象。切换 Agent 或卸载页面会取消旧请求，晚到响应不能覆盖新 Agent。

`GET /v1/admin/agents/:agentId/plugins` 只读聚合上述信息。使用现有登录鉴权及 `PostgresAgentInteractionRepository.operator` 核查“当前管理员确为该 Agent 操作者”，未授权请求不会触达 QQ 控制服务。响应禁止缓存，不包含私钥、密码、QR 文本、原始错误消息、对话正文或完整 QQ 管理快照。故障只返回规范代码、时间及任务标识。

## 状态与权限边界

“插件已启用”不等于“当前用户获准调用”，已有授权仍受原生效时间、范围、风险策略、预算及发布规则约束。能力授权列表只展示记录的状态和有效期判定，不代替每次执行时的策略检查。

GitHub 卡片读取实际交互服务的宿主对象，不能证明其他进程、定时研究执行器或所有模型／工具均健康；页面明确标注独立执行器未探测。没有配置共享交互服务的 Agent 展示“尚未配置”，不会依据默认 manifest 冒充已经运行。

QQ 元数据由生产 `createQQChannelRuntime` 传给 `startQQControlServer` 的 `pluginStatus` 回调生成，经过既有签名状态协议返回；不依赖此前真实验收包装器特有的状态补丁。旧 worker 缺少插件元数据时，显示版本未确认／需要升级；服务失联时显示状态未知，不推断为插件已停用。轮询故障只保留安全错误码与时间，属本次进程内诊断；历史故障不代表当前仍有故障。

第一版全局插件启停仍通过 `AGENT_PLUGINS_DISABLED` 和对应服务重启生效，不提供会造成 API、QQ、定时执行器状态分歧的单进程热开关。QQ“暂停群回复”继续是原业务设置，与全局插件停用分开显示。现有任务发起权限入口继续管理原渠道参与者；本轮未增加逐插件授权策略、安装／卸载、版本切换、重启按钮或论文插件。
