## 1. 阶段目标

R1.6 只建立安全、私有、可审计的论文资料入口与版面能力声明。管理员可以为同一 Agent：

- 登记 DOI，并只从 Crossref 获取有限书目元数据；
- 上传自己拥有、获授权使用或采用开放许可的 PDF；
- 在后台查看不可变收件记录、阻断原因、解析质量、版面风险和少量证据预览。

本阶段不进行论文发现、不联网补正文、不执行 PDF 中的代码或附件、不调用模型、不生成论文评价，也不把论文或解析结果送入博客公开发布链路。

## 2. 单服务器架构

R1.6 复用现有一台服务器、一个 API、一个 PostgreSQL 和现有 `quarantine` 数据卷，不新增常驻容器或第二套调度系统。

```text
管理员后台
  ├─ DOI → 固定 Crossref HTTPS 端点 → 有界元数据 → 不可变元数据版本
  └─ PDF → quarantine 临时对象
             → 字节 / 魔数 / 活动内容门禁
             → 本地受控 pdfjs 文字层解析
             → 版面与证据质量门禁
             → paper-archive/<agent>/<sha256>.pdf
             → 身份 / 版本 / layout manifest / EvidenceSpan / 收件账本
```

隔离区只用于检查。通过门禁的文件按 Agent 与 SHA-256 进入内容寻址私有归档；目标已存在时必须重新核对哈希，不能覆盖。Linux 上归档文件降为只读。失败文件立即从隔离区删除，但失败原因、大小、哈希和安全报告保留在不可变数据库账本中。

## 3. 安全门禁

### 3.1 输入与资源上限

| 项目 | 上限或规则 |
| --- | --- |
| PDF 大小 | 20 MiB |
| PDF 页数 | 80 页 |
| DOI 元数据响应 | 256 KiB |
| PDF 文字提取 | 既有解析器的总文字上限 |
| 请求 | 必须带 UUID 幂等键 |
| 权利声明 | `user-owned`、`authorized-use`、`open-license` 三选一 |

PDF 必须以 `%PDF-` 开头并包含 EOF 标记。文件名只保留规范化基名，不能形成路径穿越。对象路径只接受服务端生成的 UUID 或内容哈希。

### 3.2 失败关闭项目

进入解析器前确定性拒绝：

- 加密 PDF；
- JavaScript、附加动作、打开动作、启动动作、外部跳转动作；
- 嵌入文件、RichMedia、XFA 和提交表单；
- ZIP/PDF 混合伪装、非法魔数、缺失 EOF、异常对象数量；
- 超过字节、页数或文字上限的文件。

解析器以 `isEvalSupported: false` 和 `stopAtErrors: true` 运行；不会执行 PDF 脚本，不会打开嵌入附件，不会访问 PDF 中的 URL，也不会执行作者提供的第三方程序。

### 3.3 解压炸弹与复杂对象

R1.6 不解压归档附件，也不接受嵌入文件。输入字节、对象数量、页数和解析后的总文字量均有独立上限；解析异常立即失败关闭。扫描件不自动 OCR，因此不会把不可验证的 OCR 猜测交给模型。

## 4. 版面能力声明

每个通过基础安全检查的 PDF 生成版本化 `PaperLayoutManifest`、页面信号、解析质量和 `paper-layout-capability-v1` 报告。

| 版面 | R1.6 行为 | 允许用途 |
| --- | --- | --- |
| 原生单栏文字 | 生成页块与 EvidenceSpan | 继承解析质量门禁 |
| 多栏 | 标记 `multiColumn`，不承诺可靠重排 | 仅限质量门禁允许的私有用途 |
| 表格 | 标记 `tableRisk`，不生成行列语义 | 不得引用为结构化表格结论 |
| 公式 | 标记 `formulaRisk`，不生成公式语义 | 不得声称理解或验证公式 |
| 图片 | 记录图片页风险，不做视觉语义 | 不得依据图片形成结论 |
| 扫描页 | 标记并阻断 | 无 |
| 阅读顺序风险 | 失败关闭 | 无 |

`failClosed` 是能力声明，不等于所有混合版面文件都删除：文本仍可在私有后台作为受限证据查看，但表格、公式、图片和不可靠顺序不会被提升成模型可依赖的结构化事实。扫描或整体质量为 `blocked` 时，文件不进入归档。

## 5. 数据、不变量与权限

迁移 `0149_agent_paper_private_intakes.sql`：

- 为论文身份增加本地内容哈希标识；
- 建立 `agent_paper_private_intakes` 不可变收件账本；
- 用数据库触发器验证收件记录、论文身份和论文版本属于同一 Agent；
- 拒绝收件记录 UPDATE 和 DELETE；
- 接收成功的用户 PDF 必须同时拥有私有归档对象、论文身份和论文版本；
- DOI 只形成 `metadata-only` 版本；用户文件形成 `fulltext-user-provided` 版本。

管理员路由仍先验证真实运营者与 Agent 绑定。列表只按当前 Agent 查询。数据库层再次拒绝跨 Agent 绑定，避免未来新增入口时只依赖应用代码。

## 6. HTTP 与后台

私有管理员接口：

- `GET /v1/admin/agents/:agentUserId/paper-intakes`
- `POST /v1/admin/agents/:agentUserId/paper-intakes/doi`
- `POST /v1/admin/agents/:agentUserId/paper-intakes/pdf`

PDF 接口使用 `application/pdf` 原始流，不接受 multipart 中的额外未知对象。文件名、权利声明和可选 DOI 通过有界请求头传入。所有响应禁止缓存。

后台“安全资料入口”卡片显示 DOI 与 PDF 两条路径、正在处理状态、不可变收件结果、版面风险和最多三个证据片段。该卡片没有“发布”按钮。

## 7. 审计、预算与幂等

- DOI 每次新请求最多一次 Crossref 网络调用；不会跟随重定向；
- PDF 路径网络调用为零、模型调用为零；
- 相同 Agent 与请求 UUID 只生成一条收件记录；
- 同一请求 UUID 改换 DOI、文件名、权利声明或收件类型会以 409 拒绝，不能把幂等重放变成内容替换；
- 来源版本、布局清单、质量评估和 EvidenceSpan 可沿数据库关系恢复；
- 安全报告明确记录网络、模型与第三方代码执行计数；
- 论文收件不会创建 `blog_articles`。

## 8. 部署与运维

R1.6 不新增环境变量。既有 `QUARANTINE_ROOT=/data/quarantine` 卷同时包含临时 `quarantine/` 与私有 `paper-archive/` 子目录。不得把该卷暴露给 Web、公开下载路由或第三方容器；现有 Validator 继续只读挂载。

单服务器更新仍执行：

```bash
cd /www/gamehub
bash deploy/backup.sh
bash deploy/deploy.sh
curl -fsS https://mooyu.fun/ready
```

部署后确认迁移数为 149，再在管理员后台分别进行一条 DOI 元数据登记和一份自有测试 PDF 上传。恶意或扫描样本只应产生红色阻断记录，不能产生公开文章。

回滚应用镜像不会回滚迁移，也不会删除归档。迁移是增加式的；如需撤销入口，回滚 API/Web 即可停止新收件，已存在账本与归档继续保留。资料删除与保留期限需要后续单独的合规工作流，不能通过直接改表或覆盖对象实现。
