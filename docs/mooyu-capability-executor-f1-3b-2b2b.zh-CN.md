# F1.3b-2b-2b：签名多文件组件存储与最小权限目录投影

状态：已完成实现与自动化验证，真实 AppContainer 复验待普通桌面发行环境完成
日期：2026-10-29
边界：本阶段让多文件引擎组件能够安全安装和进入沙箱；不代表 PP-StructureV3 / PaddleOCR 已经下载、运行或达到质量门槛。

## 1. 目标

上一阶段只证明一个 ZIP 可以被安全解开。本阶段补齐生产使用所需的信任链：

```text
签名组件目录 v2
  → 绑定外层归档身份与内部清单身份
  → 内容寻址持久安装
  → 每次使用重新验证归档、清单和全部文件
  → 论文引擎绑定模型目录
  → Windows AppContainer 最小权限投影
```

服务端仍不保存模型或执行论文 OCR。组件归档、展开目录和计算全部留在用户本机。

## 2. 签名目录 v2

`capability-component-catalog-v2` 的每个 release 新增 `content`：

- 单文件组件：`{ kind: "file" }`；
- 多文件组件：`kind=zip-bundle`，并绑定 `manifestSha256`、`fileCount`、`expandedSizeBytes`。

这些字段进入 Ed25519 签名陈述。攻击者不能在保留外层 ZIP 身份的同时替换内部清单，也不能把一个合法小模型包改成文件数或展开体积更大的包。

## 3. 持久多文件组件存储

新增 `createCapabilityComponentBundleStore`。每个安装保留：

```text
component.archive
bundle/component.bundle.json
bundle/payload/**
install.json
```

安装目录按 `componentId / version / archive SHA-256` 内容寻址。存储提供：

- 全局安装锁与陈旧锁回收；
- 原子暂存和切换，失败清理仅限本次暂存目录；
- 原始归档大小 + 展开大小的联合配额；
- 活动版本和上一版本状态；
- 活动、回退及调用方保留集合保护下的清理和删除；
- 不包含本机绝对路径的清单视图。

`install.json` 只是本机索引，不是信任根。每次 `resolve` 都必须携带已经验签选择出的 release，并重新验证：

1. 外层归档大小与 SHA-256；
2. 内部清单原始字节 SHA-256；
3. 文件数和总展开字节数；
4. 实际文件全集、逐文件大小与 SHA-256；
5. 组件 ID、角色和版本。

本机元数据、归档或任意展开文件被改动时，组件不会交给引擎。

## 4. 论文引擎与沙箱投影

论文引擎运行时同时支持原有单文件组件和 `zip-bundle`。多文件组件在生成 binding 前再次完整复验，binding 明确包含归档身份、内部内容身份和逐文件清单。

Windows helper 协议升级为 `windows-sandbox-host-request-v4`，旧 helper 对新请求失败关闭。权限按文件类型分配：

- 模型根目录和必要子目录：只授予非继承的目录遍历权；
- 普通模型与配置：只读；
- 清单明确标注 `executable=true` 的文件：只读并可执行；
- 所有文件启动前核对 Windows 卷序列号、文件 ID 和长度，并在能力进程结束前保持验证句柄；
- 不授予组件目录写入、删除或新增文件权限。

能力进程只得到自己的组件根路径和逐文件相对清单，不得到组件存储根、活动/回退状态或签名 key。

## 5. 验证结果

- 签名目录、包验证、单/多文件存储、论文引擎物化、runner 与 host 协议组合回归：37 项中 31 通过、6 条按默认环境条件跳过、零失败；
- 新增多文件存储、论文引擎与目录权限投影定向回归：18/18 通过；
- C# helper 真实编译成功，本次本地产物 SHA-256：`a6ee79becaebc550c0c59348cbbd173ee98e8e3339f93254b9114ba464a44f75`。该摘要不是生产发布摘要；
- 强制开启真实 AppContainer 验收时，当前受管开发会话在原有单文件场景即统一失败于 `CAPABILITY_SANDBOX_TOKEN_CREATE_FAILED`。因此目录 ACL 的真实进程验收必须在普通桌面会话或签名安装包环境重跑，不能记作通过，也不是本次协议升级引入的特定失败。

2. 接入 PDF 页面渲染器与 PP-StructureV3 / PaddleOCR CPU 适配器；
3. 在用户本机下载官方模型组件，不把模型塞进基础桌面安装包；
4. 对开放论文建立坐标与阅读顺序金标，测量区块、表格、公式、CPU、内存和单页耗时；
5. 真实 AppContainer 目录 ACL 验收通过后才允许标记“本地 OCR 可用”；
6. 质量不达标、组件缺失、资源不足、超时或取消继续失败关闭。

这一步仍没有真实执行 OCR，也没有改变“一台 4 核 8G 服务器只做控制面、用户电脑承担重计算”的总体原则。
