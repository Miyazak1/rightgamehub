# 社区体验整体升级：参与优先的信息架构

状态：代码实施、生产构建、自动化回归与本地界面验收通过（2026-10-12）；尚未合并或部署。

## 评估结论

社区已有动态、项目、贡献任务、活动、游戏组队和“我的参与”完整对象，但此前页面呈现没有充分反映这些能力：

- 所有子页面重复展示大型社区品牌页头，占用首屏空间；
- 首页先讲抽象定位，再展示真实参与对象，用户需要滚动后才能知道现在能做什么；
- 无活动时的空状态面积偏大，进一步放大“社区没人”的感受；
- 动态列表完整展开多个正文块，长内容会淹没作者、主题和操作；
- 动态有点赞、收藏和举报，却缺少明确的“阅读全文”和“分享”动作；
- 桌面端和移动端虽然功能可达，但视觉密度和行动优先级不一致。

本轮不新增评论、私信、聊天、积分、徽章经济或虚假在线状态。升级只重组已有真实能力，并保持原权限、审核和状态机不变。

## 本轮升级

### 1. 社区外壳

- 大型品牌页头只保留在社区首页；动态、一起做、活动、组队和我的参与直接进入各自内容。
- 社区一级导航继续吸顶，发起菜单继续提供四类独立入口。
- 缩短首页页头、导航和正文之间的垂直距离，保留 GameHub 像素视觉但减少装饰性边框与阴影。

### 2. 首页

- 首屏文案改为“今天，可以从一件小事开始”，强调具体参与。
- 增加真实概览：近期活动与队伍数量、开放任务数量和动态入口。
- 游客文案明确“可以直接浏览”，登录只用于报名、申请加入和发起内容。
- 无活动时使用紧凑空状态，不填充虚假热度；仍提供真实组织入口。

### 3. 动态

- 列表页每种正文块最多展示一个预览，文字限制为四行；详情页仍展示完整内容。
- 增加“阅读全文”，把阅读意图和互动操作分开。
- 增加站点风格一致的分享图标；支持系统分享，其他环境复制当前帖子的直接地址。
- 点赞、收藏、举报、作者主页、项目上下文和审核逻辑保持不变。

### 4. 响应式与空状态

- 桌面端首页使用“说明 / 实时概览 / 我的下一步”三段布局，中等宽度自动折为两行。
- 手机端概览卡改为纵向信息行，主操作占据完整宽度。
- “我的参与”游客空状态缩短，避免空页面占据大部分视口。

## 验收标准

1. 社区首页保留品牌识别，子页面不再重复大型页头。
2. 游客在首屏即可判断社区当前是否有活动、队伍或开放任务。
3. 长动态在列表中保持紧凑，进入详情后不丢失任何正文块。
4. 每条公开动态都能复制或系统分享其直接地址。
5. 现有项目、任务、活动、组队、审核、收藏和举报能力没有回归。
6. 460、680、960 和桌面宽度下不存在关键操作溢出或只能 hover 才能发现的动作。

## 暂缓

- 评论和讨论线程；
- 私信、实时聊天和长期群组；
- 积分、通用成就或徽章经济；
- 自动推荐、虚假热度和无限滚动。

这些能力只有在真实用户行为证明需要后再单独设计，不作为本次视觉升级的完成条件。
