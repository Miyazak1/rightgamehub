# 小墨鱼 R1.10：论文研究生产运维生命周期

## 1. 阶段结论

R1.10 把 R1.9 的只读运行快照升级为可持续的服务端运维闭环：同一个论文研究 Worker 定期生成派生指标快照、维护告警打开/恢复状态、生成每周运营报告、投递可选邮件通知，并按策略清理过期的派生快照。

本阶段没有增加第二套任务系统、队列、调度器、数据库或容器。Runtime、论文领域账本和预算账本仍是事实来源；新增表只保存运维策略、派生观测、告警事件、通知 outbox、周报和保留审计。

本阶段仍不开放论文公开发布，不扩大论文来源权限，不执行第三方论文代码。

## 2. 单服务器拓扑

生产仍只有一台服务器：

- API 提供管理员读取、策略修改、保留预览和保留执行接口；
- 既有 `agent-paper-research-worker` 同时消费 `paper.private.research` 阶段并执行运维巡检；
- PostgreSQL 保存全部持久状态；
- 既有 Resend 邮件通道承担可选告警和周报投递；
- 浏览器只负责管理，不参与定时运行和消息投递。

`AGENT_PAPER_RESEARCH_OPERATIONS_INTERVAL_SECONDS` 默认 300 秒，允许 60–3600 秒。进程内防重入保证一次只执行一个巡检；它不是新的调度服务。

## 3. 持久状态

迁移 `0153_agent_paper_research_operations_lifecycle.sql` 增加：

| 数据 | 作用 | 可变性/保留 |
| --- | --- | --- |
| 运维策略 | 心跳、停滞、积压、保留、周报和邮件开关 | 版本递增，可由管理员更新 |
| 告警 episode | 当前打开或已恢复的同一故障段 | 打开时累计观察次数，恢复后终止 |
| 告警事件 | 打开与恢复的时间线 | 不可修改、不可删除 |
| 指标快照 | 健康、阻断、积压和预算的派生观测 | 唯一允许按保留策略删除的数据 |
| 周报 | 每 Agent、每自然周唯一的运营摘要 | 不可修改、不可删除 |
| 通知 outbox | 告警/恢复/周报的发送状态与重试 | 去重、有限退避 |
| 保留运行 | 谁在何时以何理由删除了多少派生快照 | 不可修改、不可删除 |

论文、来源版本、EvidenceSpan、语义结论、运行、阶段、Action、错误、告警事件、周报和人工操作审计都不属于本阶段的自动清理对象。

## 4. 告警状态机

每个确定性 blocker code 是一个 fingerprint：

1. 第一次观察到 blocker：创建 `open` episode、`opened` 事件和可选通知；
2. 后续仍观察到：只增加 episode 次数并更新最后观察时间，不重复打开、不重复通知；
3. blocker 消失：把 episode 置为 `resolved`，写入不可变 `resolved` 事件和可选恢复通知；
4. 将来再次出现：创建新的 episode，保留历史恢复段。

告警只描述平台事实，不声称论文结论正确，也不自动扩大预算、重启进程或抢占健康租约。

## 5. 周报与通知

周报按策略时区、星期和本地时间生成，同一自然周最多一份。内容包括当时健康状态、blocker、积压、当月模型使用与错误分类。重复巡检通过唯一约束保持幂等。

邮件默认在策略中关闭。启用后，论文 Worker 使用现有 `MAIL_PROVIDER=resend`、`RESEND_API_KEY`、`MAIL_FROM` 投递；发送失败留在 outbox，以指数退避重试，不影响研究 Worker 的任务状态。没有配置邮件通道时，巡检和周报仍正常持久化。

## 6. 保留策略

管理员必须先调用预览，看到截止时间和可删除数量，再提供 10–1000 字原因执行。执行请求带幂等键，相同请求不会重复删除或重复写审计。

自动与人工保留均只执行：

```sql
DELETE FROM agent_research_metric_snapshots
WHERE agent_user_id = ? AND observed_at < cutoff;
```

默认保留 90 天，管理员可在 30–730 天内调整。任何未来扩大删除范围的变更都必须新增迁移、审计字段和独立验收，不能复用当前接口静默扩权。

## 7. 管理接口与页面

管理员页面提供：

- 巡检开关与四类阈值；
- 周报星期、时间、时区；
- 邮件通知开关；
- 打开/恢复告警及观察次数；
- 最近周报；
- 派生快照数量、永久保护对象、清理预览和原因门禁。

服务端接口均要求该 Agent 的活动管理员身份。页面关闭不会停止巡检。

## 8. 验收证据

- Node 语法和静态契约测试通过；
- Web/Vite 生产构建通过；
- 隔离 PostgreSQL 17 真迁移与事务测试通过：告警打开、重复观察、恢复、单周唯一周报、outbox 投递、保留预览/执行/幂等、不可变事件与审计；
- Worker 运维巡检有进程内防重入；
- Compose 将巡检间隔和既有邮件配置注入同一个论文 Worker；
- 本阶段已通过 Compose 配置解析以及 API、Worker、Web 三个生产镜像的构建与镜像内文件检查；每次上线前仍需重复执行同一部署验收。

## 9. 后续边界

R1.10 完成后不继续堆叠平行运维设施。下一阶段优先提升论文能力本身：复杂版面/OCR/表格/公式/图像的质量准入与冻结评测，然后才评估多论文可比性。公开论文导读仍需要独立发布治理，不能因运维成熟而自动获得发布权。
