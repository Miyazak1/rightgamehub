# O4.4 小红书图文传播工作台

更新日期：2026-10-12。

## 目标

把公开作品快速整理成一套可以人工审核、直接下载的小红书图文素材。它服务内容运营，不新增社区版块，不改变作品身份，也不代替运营人员登录或操作外部平台。

## 已实现

管理员后台新增“小红书五图传播包”：

1. **封面**：真实作品封面、作品名、开源或免费属性、预计时长和浏览器游玩方式；
2. **推荐理由**：作品封面、简介和发现标签；
3. **快速上手**：从作品玩法说明提取三个步骤，不足时使用保守的通用指引；
4. **作者与来源**：发布者、公开仓库、许可证和游玩方式，缺失数据明确显示“未关联”或“以详情页为准”；
5. **行动页**：站点地址、作品搜索词和匿名试玩说明。

五张图片固定为 `1080×1440` PNG，采用同一像素网格、紫色强调、编辑部式层级和页码系统。现有 `1200×630` 链接预览图继续保留，两类素材各司其职，不相互裁切替代。

工作台同时生成可复制的小红书标题和正文：

- 只使用作品目录里的真实标题、简介、时长、标签、仓库和许可证；
- 没有公开仓库时不会声称“开源”；
- 链接使用正式 `/w/:workId` 地址；
- 自动加入 `gh_src=campaign` 与按日期、作品生成的活动代号，沿用已有隐私保护聚合统计；
- 运营人员逐张预览、下载，复制标题和正文后再人工审核发布。

## API

```text
GET /v1/works/{workId}/promo/xhs/{slide}.png
```

`slide` 只允许 `cover`、`overview`、`play`、`source`、`cta`。`download=1` 返回附件下载头，`v` 用于作品版本缓存隔离。作品读取仍经过公开目录门禁，封面缺失或处理失败时生成品牌占位，不让传播包失效。

## 设计原则

- 首图只解决“为什么停下来”，不堆砌完整介绍；
- 每页只有一个叙事任务，字号层级与站内导航、正文保持独立但一致的比例；
- 来源页不是装饰，而是平台“免费游玩、来源透明、尊重作者”的可信证据；
- 不直接在图片中生成不可点击的长链接，行动页使用短域名与作品搜索词；
- 所有文字做长度限制和 XML 转义，封面做安全解码、裁切与尺寸限制。

## 自动化边界

当前只自动完成“从真实作品资料生成草稿和视觉素材”。以下动作刻意保留人工确认：

- 检查封面裁切、事实、许可和平台敏感词；
- 根据当期内容调整标题和正文语气；
- 登录小红书或其他平台并发布；
- 回复评论、联系作者和处理撤稿。

这条边界避免批量垃圾推广、账号风控和错误授权声明。后续若接入平台官方发布 API，也应采用“生成草稿 → 人工批准 → 单次发布 → 记录结果”的流程，而不是浏览器 RPA 批量代发。

## 验收清单

1. 五个合法页面均生成 `1080×1440` PNG；非法页面名被接口拒绝。
2. 有封面的作品在封面页和推荐页正确呈现；无封面时仍可生成全部页面。
3. 标题和正文只引用真实作品字段，开源状态不会被猜测。
4. 正文链接进入正式作品页并带有有界活动代号。
5. 后台可切换作品、逐页预览、逐页下载、复制标题和正文。
6. 界面明确说明不会自动发布或自动联系作者。
