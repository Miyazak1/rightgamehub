# 小墨鱼 QQ 密码登录（本地实现）

基线为 `codex/xiaomoyu-qq-admin` 的 `73fb1d8b`。开发分支为 `codex/qq-password-login`；独立工作树位于 `E:\CODE\Right\.codex-work\qq-password-login`。原工作树及其未跟踪的 `deploy/qq/compose.no-packet-hook.yml` 保留。

后台「QQ 接入」新增专用 QQ 号和密码输入，保留原有二维码显示、刷新、白名单和预算管理。登录成功与是否完整在线仍以现有状态检查为准，不把提交请求当作已连接。

网站通过现有管理员与机器人运营者鉴权、内部签名链路调用 QQ 管理服务。管理服务校验账号与配置中的 `botId` 一致，并调用当前 NapCat 4.18.42 已提供的 `POST /api/QQLogin/PasswordLogin`，参数为 `uin`、`passwordMd5`。不修改 NapCat、QQ 原生组件或登录数据。

密码仅保留在输入框和单次请求所需的内存中，提交时立即清空输入框；权限失效、账号切换及卸载时也清空。网站与 worker 不保存密码或其摘要，不放入设置、审计、日志、浏览器存储或持久重试记录。发送给 NapCat 的 MD5 摘要仅按现有接口要求临时生成，不用于存储。密码路由使用静默请求日志及固定错误码，JSON 解析错误也不向响应回显原文。网站 API 需沿用 HTTPS 部署；内部控制链路沿用原有隔离网络。

登录操作与二维码刷新共用登录版本号和数据库互斥。操作记录只保存账号、操作者、请求 ID、登录版本和有限结果，不计算或保存密码衍生的持久指纹。同一请求 ID 的重新提交不会再次登录；不同密码复用同一请求 ID 也只返回原结果，不比较密码内容。想进行新的尝试必须使用新请求 ID 和最新版本。请求结果不明确时保留待核对意图，只查看状态，不自动重发。网站会话过期时也不自动刷新会话并重发密码。每位操作者每分钟最多 5 次密码操作。

腾讯可能要求验证码或新设备验证。本轮只接入基础密码登录；额外验证返回固定类型提示，用户通过保留的扫码入口完成登录。没有内嵌滑块验证码、保存挑战 URL/签名或自动完成验证。密码错误显示通用提示，不回显 NapCat 的原始错误消息。

`control-schema.sql` 仅扩展现有操作类型约束，允许 `password`。本地真实 PostgreSQL 测试覆盖从旧约束升级、保留已有消息、审计、请求记录、预算和登录版本。没有清空或恢复数据库、登录卷的操作。

本地验证使用合成账号/密码、独立无持久卷 PostgreSQL 容器、实际 Fastify HTTP 服务和 Edge 浏览器。覆盖成功、错误密码、额外验证、超时、签名拒绝、账号不匹配、频率限制、版本冲突、重复请求、历史/预算保留、日志与数据库不包含凭据、提交即清空、权限失效、原二维码流程及手机布局。未使用真实 QQ 凭据，也未验证腾讯侧实际登录成功。
