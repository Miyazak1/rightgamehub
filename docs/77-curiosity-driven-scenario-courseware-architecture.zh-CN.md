# 好奇心驱动的情境化互动课件架构

状态：A0 产品与架构基线；场景契约仍处于验证期，不冻结学生兴趣假设
版本：A0.2
日期：2026-10-15
关联文档：[74 Agent 原生互动课件插件平台](./74-agent-native-interactive-courseware-platform.zh-CN.md)、[75 课件托管与外部嵌入](./75-courseware-embed-service-roadmap.zh-CN.md)、[76 中国普通高中知识地图](./76-china-high-school-knowledge-map.zh-CN.md)

## 1. 决策

墨鱼工坊不再把“一个知识簇对应一个实验页面”作为结构化课件的默认产品模型。科学实验仍然重要，但实验只是理解世界的方法，不是学习者必须面对的唯一界面。

新的产品目标是：

> **把可靠的科学模型放进学习者愿意进入、愿意改变、愿意追问的具体场景中，让好奇心先发生，再用实验、测量和解释把直觉变成知识。**

这带来六项架构调整：

1. `Learning Cluster` 不再直接生成单一 `Scene`，中间增加“现象候选、场景族和兴趣验证”；
2. 科学规则与场景叙事分离，同一确定性引擎可以支持多个情境；
3. “有趣”不由作者、Agent 或平台单方面宣布，而作为需要教师审校和学习者试玩验证的假设；
4. 课件质量不仅检查公式、目标和可访问性，也检查是否存在有意义的选择、可见后果、反直觉发现和回到学科解释的路径；
5. 适合实验的场景必须提供开放建构路径，让学习者能添加、移除、组合、连接、运行、测量和比较，而不只调整作者预设的几个滑块；
6. 游戏挑战必须由同一科学状态产生目标、约束、成功、失败与重试，形成真实玩法，而不是在实验外层附加积分、徽章或倒计时。

当前的标准小车、函数画布和反应容器继续保留，但定位为：

- 引擎校准样本；
- 经典实验场景；
- 无装饰的可访问性回退；
- 教师需要直接演示时的基线视图。

它们不再自动等于面向学生的旗舰体验。

## 2. “有趣”不等于故事皮肤

把小车换成赛车、加一段对白或发放积分，不足以构成情境化学习。一个有效场景必须同时满足：

- **真实因果**：场景中的关键结果确实由正在学习的模型决定；
- **有意义的行动**：学习者的操作改变系统，而不是按提示点亮预设动画；
- **可见后果**：变化能通过运动、形态、声音替代、数据或关系图立即被观察；
- **可追问性**：结果会自然引出“为什么”“如果再改变什么会怎样”；
- **解释回路**：课件最终能用模型、证据和表征解释刚刚发生的现象；
- **诚实边界**：为了可玩性做出的简化必须可见，不能让故事覆盖科学限制。

趣味主要来自控制感、预测、惊讶、比较、设计与发现，而不是来自排行榜、连续签到、虚假奖励或高刺激视觉。游戏化可以存在，但不得替代学习者对因果关系本身的兴趣。

这里必须区分“游戏化”与“有玩法的学习”：前者可能只是发分，后者必须具有可理解的目标、真实规则、有限资源或条件、不确定但可解释的结果、多种可行策略、即时反馈以及低成本重试。学习者赢得挑战的原因必须能回到科学模型，而不是因为点击更快或记住了界面套路。

## 3. 从知识地图到场景组合

新的生产链为：

```text
Knowledge Nodes
  → Learning Cluster
  → Phenomenon Candidates（哪些现象最能暴露模型和误区）
  → Interest Hypotheses（哪些话题可能让目标学习者愿意探索）
  → Scenario Family（共享同一学科引擎的场景族）
  → Scene Portfolio（一个知识簇的互补场景组合）
  → Prototype + Playtest
  → Courseware Release
```

知识地图回答“应该学什么、依赖什么、容易错在哪里”；场景设计回答“学习者为什么愿意开始、能改变什么、会看到什么、如何形成解释”。两者互相约束，但不能混为一个字段。

### 3.1 场景组合而不是唯一场景

一个成熟知识簇可以拥有以下互补角色，不要求每个知识簇机械地凑齐所有类型：

| 场景角色 | 作用 |
| --- | --- |
| 经典实验 | 建立标准操作、测量和教材联系 |
| 生活或工程情境 | 说明模型为什么有用 |
| 反直觉现象 | 暴露误区并制造认知冲突 |
| 设计挑战 | 在真实目标、资源和边界下设计方案，允许多种解法与反复优化 |
| 自由沙盒 | 添加、移除、摆放、连接和测量对象，保存多组试验并检验自己的“如果”问题 |
| 迁移任务 | 在新表面特征下检查是否真正理解 |

首个可发布的场景组合至少应包含：一个达到 F2 的建构式自由实验入口、一个由科学规则驱动的挑战入口，以及一个能把观察连接回模型和证据的分析路径。两种入口共享同一状态和工具，可以在“自己研究”和“接受任务”之间切换。若某个知识簇不适合建构或挑战，必须记录学科理由，不能用制作成本作为豁免理由。经典实验可以作为其中之一，但不能是唯一依据。

## 4. 分层架构

```text
Course / Learning Cluster
  ├─ Scientific Model
  │    ├─ state variables
  │    ├─ invariants
  │    ├─ deterministic solver
  │    └─ observable quantities
  ├─ Scenario Family
  │    ├─ world objects and roles
  │    ├─ model-to-world mapping
  │    ├─ allowable simplifications
  │    └─ reusable visual / audio assets
  ├─ Scene Experience
  │    ├─ curiosity hook
  │    ├─ learner role and meaningful goal
  │    ├─ choices, constraints and consequences
  │    ├─ discoverable surprises
  │    └─ debrief bridge
  ├─ Construction Sandbox
  │    ├─ object catalog and assembly rules
  │    ├─ place / connect / configure / remove
  │    ├─ undo / reset / snapshots / comparison
  │    └─ learner-authored trials
  ├─ Challenge / Game Rules
  │    ├─ goals, resources and constraints
  │    ├─ success / failure / retry
  │    ├─ science-derived scoring
  │    └─ level and scenario variants
  ├─ Instruments
  │    ├─ probe / trace / vector / graph / table
  │    └─ comparison / annotation / replay
  ├─ Journey and Checkpoints
  └─ Presentation and Embed Adapter
```

### 4.1 Scientific Model

科学模型是事实层。它不包含“赛车”“救援”或“太空运输”等品牌化对象，只描述质量、力、约束、反应速率、函数关系等可验证状态和规则。

### 4.2 Scenario Family

场景族把模型变量映射为世界对象。例如同一个二维力学引擎可以支持仓库机器人、冰面救援、无人机抗风和轨道拖船。场景适配器只能：

- 选择或限制模型能力；
- 将模型对象映射为可理解的物体与单位；
- 声明近似条件和有效范围；
- 提供视觉、声音替代和文本描述。

它不能覆盖求解结果，也不能为了剧情编造与引擎不一致的运动。

### 4.3 Scene Experience

体验层负责学习动机和行动结构，包括：

- 开场的现象、冲突或问题；
- 学习者在场景中的身份和目标；
- 可以自由改变的量与受到的约束；
- 操作后立刻可感知的反馈；
- 可能出现但不提前剧透的关键发现；
- 从场景语言回到学科语言的复盘。

体验状态与科学状态分开保存。`goalReached`、提示和叙事进度不能成为质量、速度或浓度等科学变量的第二套事实来源。

### 4.4 Construction Sandbox

自由实验不是“滑块数量更多”，而是学习者可以在受控科学边界内构造自己的系统：添加或移除对象、拖动和旋转、连接部件、设置初始条件、选择测量点、运行、暂停、撤销、保存快照并比较方案。引擎负责校验命令和有效范围；学习者获得组合自由，但不能注入任意代码、绕开安全边界或制造科学状态的平行真相。

平台使用以下自由度等级，避免把参数调节误报成开放实验：

| 等级 | 能力 |
| --- | --- |
| F0 | 观看预设演示 |
| F1 | 修改预设对象的有限参数 |
| F2 | 从受控组件中添加、移除、摆放、连接并运行系统 |
| F3 | 自定问题、保存多组试验、定义比较指标并形成自己的证据记录 |
| F4 | 创作者扩展新对象、规则或场景包；不直接开放给学习者运行时 |

官方“自由实验”至少达到 F2；旗舰课件应在合适知识簇中提供 F3。自由度越高，撤销、复位、有效范围、单位、碰撞/连接提示、键盘路径和 reduced-motion 回退越必须完整。

### 4.5 Challenge / Game Rules

挑战层把科学模型变成可玩的任务，但不另造一套物理或化学规则。每个挑战至少声明：目标、资源或边界、允许动作、成功条件、可解释的失败状态、重试方式、多种策略以及完成后的学科复盘。

评分只能来自科学上有意义的量，例如准确度、能量/材料消耗、稳定性、安全余量、时间或方案鲁棒性；不能用点击次数、停留时长或装饰性代币冒充学习成效。挑战可以采用运送、救援、诊断、建造、优化、预测或对抗环境等结构，但必须满足：

- 学习者能在失败后立即重试或修改方案；
- 至少存在两种合理策略，或明确标记为技能练习而非开放挑战；
- 难度来自变量关系与设计取舍，而不是隐藏规则或操作刁难；
- 胜负、得分和反馈均可由同一 `CourseState` 重放；
- 成功后能解释“为什么有效”，失败也能提供可测量证据。

### 4.6 Instrument 与 Journey

工具不是始终展开的仪表盘。课件应先让学习者看到现象，在需要解释时逐步提供测量工具。Journey Engine 负责“何时提出问题、何时开放工具、何时比较和复盘”，但不操纵科学结果。

## 5. 场景体验规格草案

下一版结构化课件契约需要为每个旗舰场景表达以下内容。字段名是设计草案，在完成首轮原型与试玩前不冻结为公共 Schema：

```text
SceneExperience
  id
  scenarioFamilyId
  objectiveIds[]
  phenomenon
  audience
  curiosityHook
  learnerRole
  entryModes[]
  goal
  stakes
  worldObjects[]
  modelBindings[]
  availableCommands[]
  constructionKit
  experimentSnapshots
  learnerQuestions
  constraints[]
  challengeRules
  successMetrics[]
  failureStates[]
  retryPolicy
  solutionDiversity
  observableConsequences[]
  discoveryMoments[]
  instrumentUnlocks[]
  debriefBridge
  simplifications[]
  accessibilityFallback
  interestHypothesis
  playtestStatus
```

其中：

- `phenomenon` 说明希望学习者亲眼发现的现象，不能只写章节标题；
- `curiosityHook` 是一个可观察问题，不是宣传口号；
- `goal` 必须允许多种尝试，不能等同于“点击下一步”；
- `entryModes` 声明 `sandbox`、`challenge`、`guided` 中实际存在的入口，不用空标签冒充能力；
- `modelBindings` 明确每个场景对象对应哪些科学状态；
- `constructionKit` 声明可建构对象、连接规则、命令和自由度等级；
- `challengeRules`、`successMetrics` 与 `failureStates` 只引用可重放的科学状态和可观察量；
- `solutionDiversity` 说明挑战预期允许的不同策略，避免把唯一操作序列伪装成游戏；
- `discoveryMoments` 记录可被探索出来的关键转折，但运行时不保证强制触发；
- `debriefBridge` 把场景对象重新对应到变量、图表、公式和证据；
- `interestHypothesis` 明确“我们为什么认为目标学生可能在意”，并注明依据仍是猜想、访谈还是试玩证据；
- `playtestStatus` 不能由生成 Agent 自动提升为已验证。

## 6. 兴趣发现与场景选择

### 6.1 不建立永久的“青少年兴趣清单”

学生群体、年龄、地区和时间都会改变。平台维护的是可修订的候选与证据，不把电竞、航天、偶像、短视频或任何当下话题永久写入学科 Schema。

场景候选可以来自：

- 课程中的经典现象和教师观察；
- 学习者访谈、共创和匿名试玩反馈；
- 日常生活、体育、交通、工程、自然和公共议题；
- 科学史中的真实问题与思想实验；
- 公开文化趋势，但必须通过安全、版权、寿命和教学相关性评估。

平台不得收集未成年人不必要的身份、聊天原文或跨站行为来推断兴趣。

### 6.2 两类门禁

**科学与教学硬门禁**，任何一项失败都不能发布为官方推荐：

1. 学习目标对齐；
2. 关键因果由确定性模型产生；
3. 简化与适用范围明确；
4. 学习者有至少一个会改变结果的有意义选择；
5. 结果可观察、可测量并能回到解释；
6. 适合实验的旗舰入口达到 F2；不适合时有明确学科理由；
7. 挑战的成功、失败和评分来自科学状态，支持安全重试且不依赖装饰性积分；
8. 安全、版权、文化表达和可访问性通过检查。

**兴趣假设维度**，使用 0—3 的证据等级记录，但首轮不设置伪精确总分：

- 开场问题是否会引发追问；
- 目标学习者是否理解并在意场景目标；
- 操作是否产生清晰、及时且可能出乎预料的反馈；
- 是否支持多种策略与重复尝试；
- 是否允许学习者提出自己的“如果”；
- 建构过程是否会促使学习者动手组合、排错和改进方案；
- 挑战是否会产生“再试一次”的内在动力，而不是奖励驱动的机械重复；
- 话题是否具有年龄与文化相关性；
- 场景与科学模型是否自然，而非硬贴皮肤；
- 同一引擎是否能迁移到其他知识簇。

证据等级：`0 未评估`、`1 团队假设`、`2 教师/小规模访谈支持`、`3 学习者试玩支持`。视觉完成度不能提升证据等级。

## 7. 学习体验节奏

推荐的旗舰 Journey 是一个循环，而不是固定的三页向导：

```text
Notice       看见一个具体、可理解但未解释的现象
  → Predict  作出承诺并说明依据
  → Build    组装系统、设置条件或选择方案
  → Act      运行场景并实施方案
  → Observe  看到连续反馈和关键结果
  → Measure  在需要时调用工具收集证据
  → Redesign 根据证据修改结构、参数或策略
  → Explain  把对象与行为映射回模型
  → Transfer 在变式场景中再次判断
  → Wonder   留下可继续探索的开放问题
```

Explore、Model、Analyse 仍然有效，但它们是上述循环中的能力视图，不要求始终以三个顶部标签同时出现。

## 8. 首轮场景假设

下表只是待验证候选，不是“学生一定喜欢”的结论：

| 学科引擎 | 候选场景族 | 自由实验能力 | 挑战玩法 |
| --- | --- | --- | --- |
| 牛顿动力学 | 仓储机器人、冰面救援、无人机抗风、轨道货运 | 自由组合小车、载荷、推力、轨道和测量工具 | 在有限推力、能量或安全余量下抵达目标区，比较不同设计 |
| 曲线与优化 | 滑板轨迹、投篮窗口、无人机航线、包装与材料 | 调整控制点、函数族、约束和取样方式，自建比较方案 | 在平滑度、材料、最高点或误差约束下设计可行曲线 |
| 化学平衡与速率 | 碳酸饮料、密闭生态箱、工业合成、空气净化 | 在安全虚拟边界内配置物质、浓度、温度、压强和检测工具 | 用有限原料与能耗达到产率、速率、纯度或安全目标 |

选择首发场景时优先考虑模型映射自然、反馈清晰、风险低且可以形成自由探索的问题。不能为了热门话题强行引入超出当前引擎能力的变量。

## 9. 创作与验证流程

```text
1. 从已审校 Learning Cluster 提取核心模型、误区和可观察量
2. 生成多个现象与场景候选，而不是直接制作第一个想法
3. 完成科学映射和兴趣假设说明
4. 分别制作 F2 自由建构原型和挑战回路原型，验证“能否自己研究”与“是否愿意反复解决”
5. 教师检查目标、简化、开放边界、挑战规则和解释路径
6. 学习者试玩，记录困惑、主动建构、不同策略、失败后重试和自发提问
7. 保留、重写或淘汰场景；不能只优化按钮文案掩盖无趣机制
8. 才进入高保真制作、无障碍、双语、固定 Release 和双宿主验收
```

试玩记录只保存完成设计判断所需的最少聚合信息。首轮重点观察：学习者是否理解目标、是否主动改变变量、是否能描述看到的因果、是否愿意尝试第二种方案，以及哪些时刻产生了自发问题。正式阈值在获得真实样本后确定，文档不预设虚假的行业基准。

## 10. 路线图

### A0：架构校准（当前）

- 冻结科学模型与场景体验分离的原则；
- 将好奇心、场景组合和试玩证据纳入产品质量定义；
- 保留现有 Courseware v1 兼容，不静默改变已发布 Release；
- 在原型验证前不把体验规格草案升级为强制公共 Schema。

### A1：牛顿动力学场景族

- 把现有小车课件标记为“经典实验/引擎基线”；
- 从同一力学状态和求解器派生 3 个低保真情境候选；
- 把当前 F1 参数控制升级为至少一个 F2 建构沙盒，并提供撤销、复位和方案快照；
- 至少制作两个共享同一状态的挑战变体，验证多策略、失败反馈与重试；
- 每个候选必须包含目标、自由建构、结果反馈、测量与复盘；
- 通过科学审校后再开展小规模学习者试玩。

### A2：第一组旗舰场景

- 根据试玩保留至少 1 个高兴趣场景，并记录淘汰理由；
- 旗舰场景同时提供“自由实验”和“挑战任务”入口，二者共享模型、对象、工具与快照；
- 完成场景资产、触控、键盘、reduced-motion、双语和外部嵌入；
- 验证经典实验和情境场景共享同一模型结果；
- 发布时分别显示科学质量与体验验证状态。

### A3：数学与化学场景族

- 数学先验证“形状—约束—优化”的场景复用；
- 化学先验证“微观过程—宏观现象—控制条件”的场景复用；
- 不复制力学课件的控制面板布局，也不把所有学科做成参数滑块。

### A4：场景目录与 Agent 创作能力

- 插件能够按模型能力、年龄、话题、互动方式和证据等级查询场景族；
- Agent 从多个候选中说明选择理由，不默认使用第一个模板；
- Doctor 检查科学映射、体验回路和证据状态，但不让自动评分冒充学生兴趣；
- 第三方场景包经过签名、来源、版权、科学和安全审核后进入目录。

## 11. 当前实现的迁移关系

现有 `causal-simulation` 不删除，也不继续被包装成完整旗舰产品。它目前属于 F1 参数实验，承担三项近期职责：

1. 验证力、质量、时间轴、图表和控制变量是否共享同一状态；
2. 作为经典小车实验和无障碍基线；
3. 为 A1 的多个场景适配器提供科学引擎输入与验收断言。

下一步不应继续无限精修小车外观，而应抽离其中的力学状态、命令、求解与测量能力，加入可建构对象、连接规则、撤销与试验快照，将其提升到 F2；再用同一状态制作挑战规则，验证“同一引擎、自由实验、多种好奇情境和真实玩法”。

## 12. 尚未冻结的决定

以下内容必须经过原型和试玩后再决定：

- 场景体验公共 Schema 的最终字段；
- 不同年龄和学科的场景组合最低数量；
- 兴趣证据等级是否需要量化阈值；
- 场景资产采用 Canvas、SVG、WebGL2 或组合组件的默认策略；
- 哪些候选话题进入首批官方目录；
- 自由沙盒与引导挑战在不同知识簇中的默认比例。

保持这些决定可修订不是缺陷，而是防止平台把团队想象误当成学生兴趣的必要边界。
