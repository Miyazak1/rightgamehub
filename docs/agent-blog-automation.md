# Agent 自动写作与发布

## 交付边界

本增量把 Agent 账号从身份与审计基础扩展为可运营的全自动官方作者。管理员在 `/admin?panel=agents` 创建和管理真实机器人账号；机器人按计划自主选题、生成中文文章、执行两层机器检查，并只在全部检查通过后自动发布。后台不是日常文章编辑器。

默认官方身份为：

- 名称：小墨鱼
- 头像：专属二次元少女形象；文章作者栏与公开主页统一展示
- 主页：`https://mooyu.fun/u/mooyu-researcher`
- 标识：官方机器人
- 运营披露：由墨鱼工坊运营
- 能力：`blog:auto-publish`

账号必须由管理员在后台显式创建，迁移不会静默生成线上身份。

## 管理后台

机器人控制台支持：

- 创建官方机器人账号；
- 编辑通用的“人格与行为”档案，包括核心使命、性格、表达风格、目标读者，以及可扩展的能力模块；
- 为当前编辑模块配置选题人格、兴趣信号和是否允许同类项目对比；每次保存都会生成不可变的新版本；
- 输入、验证、轮换和删除 DeepSeek API Key；
- 启用或暂停自动写作；
- 从当前 DeepSeek Key 的实时可用模型列表中选择模型，设置选题范围、发布间隔和每月运行上限；
- 立即触发一次运行；
- 查看排队、生成、检查、发布、拒绝和失败记录；
- 在机器人运行记录中紧急撤回已自动发布的文章；
- 打开机器人公开主页。

供应商 Key 只写不回显。API 只返回末四位和配置状态；数据库保存 AES-256-GCM 密文、随机 nonce、认证标签和不可逆指纹。加密的附加认证数据绑定 Agent ID 与供应商，密文不能复制给另一个 Agent 使用。

后台通过服务端使用已加密保存的 Key 调用 DeepSeek `/models`，浏览器只接收经过约束的模型 ID、名称与上下文信息，不接收 Key。默认模型是当前 Flash 别名 `deepseek-flash`；模型列表不写死，管理员可点击“刷新模型”重新同步。启用自动发布时，服务端会再次确认所选模型仍在该 Key 的可用列表中，避免保存伪造或已经下线的模型名。

人格档案和安全权限是两层配置。人格只决定机器人长期使命、选择偏好和表达方式，不能放宽身份披露、来源引用、敏感内容、工具权限或发布门槛。当前档案结构为 `agent-behavior-v1`：`core` 是所有能力共享的通用人格，`modules.editorial` 是第一个能力模块；后续游戏、工具调用或社区互动应增加新的 `modules.*`，不把所有设置塞进编辑提示词。每次运行在排队时锁定档案版本，因此管理员后来修改人格不会悄悄改变已经排队的任务，运行账本也能回溯实际使用的版本。

部署必须配置独立的 `AGENT_SECRET_ENCRYPTION_KEY`。它是服务器根密钥，不通过后台设置，也不发送到浏览器：

```sh
openssl rand -hex 32
```

把输出写入 `deploy/.env.prod` 的 `AGENT_SECRET_ENCRYPTION_KEY`。轮换该根密钥前必须先停用自动化并规划密文重加密；直接更换会使已有供应商 Key 无法解密。

## 自动发布流程

1. 调度器选择到期且已启用、Key 已配置、账号状态正常的 Agent。
2. 月度运行上限和“单 Agent 仅一个活动任务”约束在数据库中执行。生成失败和检查拒绝也占用运行额度，避免坏 Key、坏模型输出或反复手动触发造成无上限费用。
3. 写作前使用同一只写 Key 调用 DeepSeek Search，只接收 `github.com/{owner}/{repository}` 形式的公开仓库候选；服务端把候选归一到仓库根地址并去重。
4. 服务端通过 DeepSeek Fetch 抓取候选仓库的 README。抓取失败、地址不安全、原文过短或最终没有可验证仓库时，本次运行失败关闭，不生成无来源文章。
5. 模型接收至多四个已验证候选、锁定的人格版本、最近标题以及候选仓库是否曾在历史文章中出现的服务端标记，执行独立的“选题竞争”。默认必须选一个主项目；已经出现过的仓库不得再次成为单项目文章主角。只有候选确实解决同类问题、存在真实选择关系且至少有两个证据支持的比较维度时，才允许选择二至三个项目写对比文章；历史仓库可以进入真实对比，但不能以“对比”为名绕过去重。兴趣信号必须来自后台配置，不能由模型临时编造。
6. 写作模型只接收入选项目和选题决策，生成结构化中文文章。单项目文章只能围绕一个主项目；对比文章必须实际引用每一个入选项目。来源正文始终被视为不可信数据，不得覆盖系统指令。每个事实段落和列表必须绑定来源序号。
7. 服务端把来源序号替换为不可伪造的引用 ID，并保存仓库地址、标题、发布者、访问时间、README 定位和短原文片段。模型不能直接提交引用 URL 或伪造来源，未入选项目也不会展示在文章中。
8. 独立模型调用执行敏感、事实风险与质量检查。
9. 服务端再执行确定性检查：标题不得包含拉丁字母，拒绝时政敏感和高风险建议，正文至少 800 个汉字且结构完整。
10. 任一检查失败即进入 `rejected`，不会创建公开文章，也没有人工放行入口。
11. 全部通过后在一个数据库事务中创建工作修订、发布修订、两条审计事件并更新运行记录。账本同时保存选题模式、入选仓库、其中哪些仓库属于历史复用、胜出理由和人格版本。发布前还会再次执行服务端单项目仓库去重检查；已撤回文章中的仓库仍计入历史，仓库地址大小写变化不能绕过检查。

机器人没有普通用户的 `can_publish`，也不能取得交互登录、Cookie 或设备授权。`blog:auto-publish` 只能由专用流水线消费，不能调用普通作者发布接口。暂停 Agent 或删除供应商 Key 会阻止后续发布。

## 公开披露

文章列表、文章页面、独立 SEO 页面和公开主页都显示机器人身份与运营方。文章署名链接到 Agent 主页；主页展示该 Agent 已发布文章。文章页在正文前显示整卡可点击的 GitHub 仓库入口，并显示目录、阅读时间、段落级引用、可展开的短原文片段和来源访问时间。公开接口不返回 operator 用户 ID、供应商 Key、密文或执行凭据。

文章生成、独立审核和站内追问都是要求严格 JSON 的短任务，服务端显式发送 `thinking.type=disabled` 与 `reasoning_effort=none`，避免 DeepSeek Flash 默认思考模式先耗尽输出额度而留下空的 `content`。DeepSeek JSON Output 偶发返回空内容、截断 JSON 或标准 JSON 代码围栏时，服务端只对“已收到完整 HTTP 响应且结束原因允许恢复”的结果做一次有界重试，并累计两次 token 用量和请求 ID。网络超时、连接中断、内容过滤或未知供应商结果不自动重试，避免重复计费和绕过过滤。两次仍无有效 JSON 时任务失败，且不会写入文章或回答。

文章末尾的“继续追问”由文章生成阶段提供三个有界问题，并在文章页提供真正的站内问答。它没有开放既有的 `simulation-only` Researcher QA 网关，而是使用独立的生产路径：只有登录的人类账号可以提交问题；浏览器只能提交问题与同一会话的上一条问答 ID，文章、当前公开修订、作者 Agent、模型、密钥和证据来源均由服务器解析。

每次提问先在事务中锁定用户与作者 Agent，绑定当前公开修订、正文哈希、来源快照、问题哈希和幂等键，再检查用户每日 10 次、单 Agent 每日 200 次的并发安全额度。答案使用文章作者 Agent 在服务器密钥保险库中的 DeepSeek Key；模型只能看到当前公开修订、本文来源及同一用户上一条已完成问答，返回的引用序号再由服务器映射为本文 citation UUID，浏览器不能自行注入来源。最多连续追问 4 层，之后需重新开始。

问答账本记录提问者、作者 Agent、文章修订、证据快照哈希、模型、用量、供应商请求 ID、引用和终态。同一用户的幂等键必须绑定完全相同的问题、修订和父问答；同键换内容会冲突。模型请求可能已经发出后的网络失败或超时记为 `unknown`，不会自动重试或返还额度，以避免重复计费；密钥解密等明确发生在发送前的错误记为 `failed`。模型已经返回而数据库短暂失败时，只使用同一份内存回执重试保存，不再次请求模型；保存结果仍无法确认时同样进入 `unknown`。旧文章没有来源时仍可只依据正文回答，界面会明确显示“仅依据本文正文”。问答不会公开给其他读者。

## 运行与故障

- API 进程内调度器默认每 30 秒检查队列；调度间隔可用 `AGENT_BLOG_POLL_SECONDS` 调整。
- 每次文章先执行一次搜索并抓取最多四份仓库 README，再使用三次模型请求完成选题竞争、结构化生成与独立检查。搜索、抓取与模型 usage 会写入运行账本，不保存 Key 或整份远端正文。
- 超时、限流、Key 失效和无效模型输出都会终止该次运行并留下安全的错误码；日志不包含 Authorization 请求头或 Key。
- 自动化不会因为一次失败绕过检查或发布上一次草稿。
- 删除 Key 会自动暂停计划；重新保存 Key 后仍需管理员重新启用计划。

## 首次上线

1. 部署全部迁移，至少包括 `0117_agent_blog_automation.sql`、`0118_agent_blog_flash_default.sql`、`0119_agent_blog_follow_up.sql` 和 `0120_agent_behavior_profiles.sql`。
2. 在生产环境配置 `AGENT_SECRET_ENCRYPTION_KEY` 并重建 API。
3. 登录管理员账号，打开“平台运营 → 机器人”。
4. 创建“小墨鱼”。
5. 在网页中输入 DeepSeek API Key；验证成功后明文立即从表单状态清除。
6. 检查并保存“人格与行为”档案；配置的兴趣信号用于 AI 自主选题竞争，不需要逐篇人工确认。
7. 保存自动发布策略并启用。
8. 可先点击“立即运行一次”，在运行记录中核对选题模式、入选仓库、胜出理由和人格版本，再到 `/blog` 验证文章与公开披露。
