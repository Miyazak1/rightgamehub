候选试验仅设置网关的 `NAPCAT_DISABLE_BYPASS=1`。这个开关用于跳过 NapCat 可选 Bypass 初始化；不是关闭 QQ 协议、Packet 适配器、OneBot 或小墨鱼问答，也不是已验证的永久修复。仍需专用账号扫码后观察原生崩溃是否复现，再做问答和持续运行验收。

`deploy/qq/try-native-compat.py` 依赖已安装且校验匹配的 QQ 管理部署辅助模块。只适用于本轮已核验的四份原生文件和已有安装状态；QQ 已在线或正在完成登录时不打断会话。新建独立覆盖文件而不改原 .env。冻结原镜像和环境，只允许一个开关变化；校验原数据卷、只读挂载、网络、端口、权限和资源限制保留。

应用前记录原环境、配置校验和与其他服务实例 ID，并保留镜像标签。仅停止 NapCat，在停止状态下以同一镜像、隔离网络和只读卷执行 tar 备份整个 /data，备份留在私有日志目录；不恢复旧卷快照、不清空登录资料。成功备份后只重建 napcat，不重启网站、worker 或数据库。检查原八份配置文件和其他服务实例没有变化。

启动检查失败时尝试恢复原网关镜像/环境，继续使用当前数据卷。`rollback.sh` 同样不恢复旧数据快照，且检测其他操作者的新环境或配置变更时会停止，避免覆盖。私有快照和 command 日志可能包含凭据，排错仅分享 deploy.log 和脱敏观察报告。
