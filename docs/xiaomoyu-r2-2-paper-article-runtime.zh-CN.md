# 小墨鱼 R2.2：论文证据到私有科普草稿运行时

版本：v1.0
状态：代码完成；三样本生产验收已由 R2.3 编排接管
更新日期：2026-10-29

## 1. 阶段目标

把已经完成语义分析的单篇论文接入小墨鱼现有写作基座，而不是新建论文机器人或平行任务系统。输入是一个属于小墨鱼的、已冻结且通过证据核验的 `analysisId`；输出只能是现有博客草稿库中的私有草稿，不能公开发布。

本阶段复用同一套：

- Agent 身份、人格版本和模型 Key；
- Durable Run / Stage / Action、租约、幂等和预算；
- Provider Gateway 与结构化响应校验；
- 统一研究证据账本、文章合同和私有草稿库；
- 单服务器 Docker Compose 部署方式。

没有增加常驻容器或新定时器。只有显式执行时才启动一次性容器。

## 2. 新增合同

- 只读工具：`research.paper.analysis.read@1`；
- 私有工作流：`paper.article.draft-shadow@1`；
- 输入：`paper-article-draft-input-v1`；
- 模型结构化输出：`paper.article.composition@1`；
- 最终运行输出：`blog.private-draft`。

工作流固定为：

```text
freeze-input
  → collect-evidence
  → compose
  → verify
  → persist-draft
```

工作流没有 `publish` 阶段，也不持有 `blog.article.publish` 能力。

## 3. 证据与失败关闭

论文工具只读取属于当前 Agent 的已核验分析，禁止网络和文件系统访问。写作输入保留论文版本、分析哈希、逐页证据、作者主张、观测结果、限制和后续问题。

确定性验证要求：

- 输入分析和证据属于同一 Agent；
- 证据片段带真实页码；
- 所有事实段落或列表绑定论文引用；
- 文章只有一个已实际读取的论文主来源；
- 文章正文和来源经过现有博客合同归一化；
- 任何校验失败都不产生草稿，更不会尝试发布。

相同 `analysisId + requestId` 可幂等重放；如果运行已经成功，命令直接返回既有草稿，不重复调用模型。

## 4. 单服务器立即运行

先部署本提交并完成常规数据库迁移。随后在 `deploy` 目录显式执行：

```sh
./agent-blog-public-ops.sh paper-draft <已核验的-analysis-uuid>
```

命令会先注册/核对论文只读工具和私有工作流，再启动一次性执行容器。成功结果必须同时满足：

- `publicationState` 为 `draft`；
- `publicationAttempted` 为 `false`；
- 返回 `articleId`；
- 后台草稿列表可打开并显示论文来源及页码。

该命令不受每日公开文章数量限制，因为它不公开发布；模型调用仍进入统一月度预算和熔断账本。

## 5. 验收与后续

代码回归覆盖工具边界、证据包、结构化生成、确定性验证、私有持久化、幂等恢复和生产 Compose/运维入口。

R2.3 不扩大架构，专注真实闭环：选择三篇不同的开放论文，完成“发现/收件 → 全文解析 → 语义分析 → 私有科普草稿 → 引用回跳”的整组生产验收，并写入不可变收据。执行说明见 `docs/xiaomoyu-r2-3-paper-article-acceptance.zh-CN.md`。通过后再决定论文公开发布治理和自动选题计划。

桌面端 D1 在 R2.3 稳定后启动。D1 只做用户可安装、可登录、可查看任务、可调用本地能力和可更新的最小产品；现有 Windows 安装/更新/托盘/本地执行代码是安全内核，不等于图形桌面版已经交付。
