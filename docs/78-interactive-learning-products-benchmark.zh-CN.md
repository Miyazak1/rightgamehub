日期：2026-10-15
关联文档：[74 Agent 原生互动课件插件平台](./74-agent-native-interactive-courseware-platform.zh-CN.md)、[75 课件托管与外部嵌入](./75-courseware-embed-service-roadmap.zh-CN.md)、[76 中国普通高中知识地图](./76-china-high-school-knowledge-map.zh-CN.md)、[77 好奇心驱动的情境化互动课件架构](./77-curiosity-driven-scenario-courseware-architecture.zh-CN.md)

## 1. 结论先行

本轮调研覆盖中国与海外的教材同步虚拟实验、开放式科学/数学沙盒、情境化与游戏化学习产品、课件作者工具，以及可嵌入内容基础设施。最重要的判断是：

> **市场上已经有很多优秀的“实验”“沙盒”“课程”或“游戏”，但尚未看到一个公开产品同时把中国高中知识覆盖、可靠科学引擎、自由建构、场景挑战、Agent 作者工具和开放外站嵌入做成统一系统。**

因此，墨鱼工坊不应把目标收缩成另一个虚拟实验室，也不应逐知识点手工制作孤立网页。正确方向是建立一套“可组合互动知识运行时”：

1. 用中国普通高中数学、物理、化学知识地图决定覆盖范围；
2. 用少量可复用的确定性学科引擎覆盖大量知识簇；
3. 同一引擎至少能装配成经典教材实验、自由沙盒和情境挑战三种体验；
4. 作者或外部 Agent 用声明式课件包组合模型、场景、工具、目标和讲解，而不是重写运行时；
5. 每个课件都是可托管、可固定版本、可嵌入、可暂停/恢复、可交换状态和学习事件的独立组件；
6. 趣味来自真实因果、可失败的目标、多种策略和可见结果，而不是实验外层的积分皮肤。

这条路线与 [77](./77-curiosity-driven-scenario-courseware-architecture.zh-CN.md) 的 A0.2 判断一致，但本报告进一步确认了两个优先级：

- **开放嵌入和组合协议必须从第一天进入内核**，不能在内容做完后补；
- **自由建构能力必须由共享引擎提供**，不能为每个场景单独伪造几个滑块。

## 2. 调研方法与证据边界

本报告优先使用产品官网、官方帮助中心、官方技术文档和官方许可说明。评价分为三类：

- **已核实能力**：公开页面、可访问产品或官方文档明确展示；
- **官方主张**：厂商官网描述，但本轮没有独立验证全部交互和教学效果；
- **本报告判断**：基于公开能力对产品架构、自由度和适配性的分析，不代表厂商自我定位。

自由度沿用 [77](./77-curiosity-driven-scenario-courseware-architecture.zh-CN.md) 的分级：F0 观看、F1 调参、F2 受控组件建构、F3 自定问题与多轮证据、F4 创作者扩展对象或规则。表格中的“外部调用”区分普通链接、`iframe` 嵌入、双向 API/消息协议与可自托管，避免把“能打开网页”误报成平台能力。

本次对格物匣的公开抛体实验进行了实际页面检查；其自由力学沙盒需要登录，本报告只评价官方描述，不把未进入的交互写成实测。商业产品的后台、付费内容、内部作者工具和合同能力也不在公开核验范围内。

## 3. 产品版图

### 3.1 四条成熟路线

| 路线 | 代表产品 | 最强能力 | 常见缺口 |
| --- | --- | --- | --- |
| 教材/概念模拟 | 格物匣、PhET、CK-12、Gizmos、Physics Classroom | 单知识点清晰、启动快、教师容易采用 | 多数为 F0/F1，学习者难以真正建构系统 |

| 作者/嵌入基础设施 | Concord Lab Framework、CODAP、H5P、Open Source Physics/EJS、LabXchange | 组合、复用、嵌入、作者生态或学习路径 | 视觉品质、现代交互和中国课标覆盖不统一 |

没有一条路线可以单独成为墨鱼工坊的完整答案。我们的产品应把四条路线在运行时层汇合，而不是把四种网站简单放进同一目录。

### 4.1 中国市场：覆盖和课堂工作流已经不是空白

[NOBOOK](https://www.nobook.com/index.html) 已覆盖物理、化学、生物和小学科学，其公开购买页明确描述电学、力学、光学引擎、器材组装和参数设置；官方应用页还声称拥有 2000+ 教材同步实验，并开始加入 RPG、知识闯关和 AI 伴学。[矩道](https://www.judaoedu.com/aspx/main/index.aspx) 则把同步实验、开放探究平台、实验器材库、操作训练、评分和数据分析组合进 VR/3D 产品。[NOBOOK 产品页](https://www.nobook.com/price.html)、[矩道高中实验室](https://www.judaoedu.com/gzvr3dsys/)

这意味着“支持中国教材”“有 3D 器材”“可以拖动物体”都不足以形成竞争壁垒。墨鱼工坊必须把优势建立在：

- Web 原生和低摩擦外站调用；
- 学科引擎、情境和挑战规则解耦；
- 外部 Agent 可生产但不能绕过科学与质量门禁；
- 同一课件既能无账号直接体验，也能在授权后回传学习事件；
- 学生能够保存方案、比较试验并解释证据，而不只是走完步骤。

格物匣值得作为视觉和课堂体验参考。其公开实验目录按高中教材组织，抛体实验的实际页面提供装置、分步导航、视角控制、标签、原理、数据处理和全屏展示；但其[服务条款](https://gewuxia.top/terms)同时说明实验文件不提供 API，公开体验之外的内容需要账户。因此它与“让其他网站稳定调用课件”的平台目标不是同一产品路线。[格物匣实验室](https://gewuxia.top/labs)

新出现的 [PhysiLab](https://www.physilab.cn/) 和 [TensorPhys](https://www.tensorphys.cn/) 也在强调高中物理模型、参数联动、数据图像、编程或传感器，说明“浏览器里的物理工作台”正在变成国内独立赛道。当前公开资料还不足以确认其作者协议、开放嵌入和大规模课标覆盖，因此列入持续观察，不据此调整核心架构。

### 4.2 PhET：最值得学习的是克制，不是数量

PhET 的优势不是把真实实验室全部搬到屏幕，而是只保留能暴露关键因果的对象、变量和多重表征。模拟可以直接嵌入或下载离线运行；但其当前普通 HTML 模拟采用 CC BY-NC 4.0，收费、广告或商业产品集成需要商业许可，不能直接作为墨鱼工坊商业内容库复制。[PhET 嵌入说明](https://phet.colorado.edu/cs/teaching-resources/virtual-workshop/introduction-to-phet)、[许可说明](https://phet.colorado.edu/en/licensing)、[离线访问](https://phet.colorado.edu/en/offline-access)

应借鉴：

- 首屏即实验，几乎不需要读说明；
- 拖动、滑块、向量、图像和微观表征同步响应；
- 视觉服务于因果，不把 3D 和写实当默认质量指标；
- 一个模拟围绕少量强问题，而不是展示全部功能。

不应照搬：每个模拟仍是相对固定的产品单元，普通版本并不是开放的通用课程运行时。

### 4.3 Algodoo、Polypad、GeoGebra：自由来自对象和关系

[Algodoo](https://www.algodoo.com/what-is-it/) 允许学习者用绘图工具构造物理世界、发明装置甚至设计游戏；[Polypad](https://mathigon.org/teachers) 把 50+ 数学学具、几何和图表放进同一自由画布；[GeoGebra](https://help.geogebra.org/hc/en-us/articles/16147990896797-App-Embedding) 则以数学对象、依赖关系和脚本 API 支撑庞大的材料生态。三者共同说明：

> 真正的沙盒不是“有很多滑块”，而是学习者能创建对象、建立关系、改变结构、运行系统、撤销并保存自己的产物。

墨鱼工坊的 F2/F3 必须落到命令级能力：`add`、`remove`、`place`、`connect`、`configure`、`measure`、`run`、`pause`、`step`、`snapshot`、`compare`。只有参数变化、没有结构变化的页面仍是 F1。

### 4.4 ChemCollective 与 Labster：场景必须改变问题，而不只是换背景

[ChemCollective](https://chemcollective.org/about_us/introduction) 从一个可复用湿化学实验室出发，再用现实和游戏场景提出任务；其教师指南把开放探究定义为学习者用化学知识设计并执行自己的实验。[场景活动](https://chemcollective.org/scenario_based)、[教师指南](https://chemcollective.org/teachers/teacherGuide)

[Labster](https://help.labster.com/en/articles/3905261-what-is-labster) 将 3D 实验、角色对话、现实联系、故事、评分和任务结合，官方明确把叙事与游戏化作为提高动机的组成部分。但 Labster 的体验通常更重、更封闭，并且官方设备说明不支持手机完成模拟，说明高沉浸 3D 会带来明显的运行与适配成本。[设备要求](https://help.labster.com/en/articles/1077008-can-my-device-run-labster-simulations)

对我们的启示是：

- 场景要给学习者一个模型可以解决的真实目标；
- 胜负、资源和失败原因必须来自科学状态；
- 3D 只在空间关系、装置操作或沉浸角色确有收益时使用；
- 旗舰体验可以丰富，但每个课件都要保留轻量、可键盘操作和 reduced-motion 的回退。

### 4.5 Concord、CODAP 与 H5P：外站调用是一种产品内核

[Concord Lab Framework](https://lab-framework.concord.org/) 把模型、滑块、按钮和图表定义为 JSON 交互组件，并明确支持分享与嵌入；其 [Interactive API](https://concord.org/newsletter/2014-spring/interactive-api/) 允许外层页面控制模拟、获取/设置状态、记录事件和导出数据。这是与墨鱼工坊最接近的架构先例。

[CODAP](https://codap.concord.org/how-to/embed-codap-in-a-website/) 进一步证明数据工作台可以作为独立、可嵌入、仍可交互的组件；插件可以接数据库、传感器和模拟输出。[CODAP 插件开发](https://codap.concord.org/developers/plugin-development/)

[H5P](https://h5p.org/) 则证明了另一件事：内容类型注册、浏览器作者工具、导入导出、`iframe` 和 LTI 生态能比单个优秀课件产生更大的分发价值。H5P 自身不是高质量科学引擎，因此适合参考包格式与集成方式，不适合作为我们的求解器层。[H5P 内容类型](https://h5p.org/content-types-and-applications)

由此确认，墨鱼工坊的嵌入能力不能只返回一个 URL，至少需要：

- 固定版本的 `iframe` URL 与响应式尺寸契约；
- `postMessage` / `MessageChannel` 握手、来源白名单和能力协商；
- `ready`、`play`、`pause`、`reset`、`setLocale`、`getState`、`restoreState`；
- `interaction`、`measurement`、`checkpoint`、`challengeResult`、`completed`、`error` 事件；
- 匿名运行默认不发送可识别学习者信息；进度回传必须显式授权；
- 宿主不可覆盖科学求解结果，只能选择允许的预设、模式和展示参数。

## 5. 值得借鉴与必须避免

### 5.1 应直接进入产品基线的能力

| 能力 | 最佳参考 | 墨鱼工坊落点 |
| --- | --- | --- |
| 首屏可理解、直接操作 | PhET、Brilliant | 课件打开后 5 秒内出现可操作对象和因果反馈 |
| 教材装置与课堂展示 | 格物匣、NOBOOK、矩道 | 经典实验模式、装置标注、步骤与全屏讲解 |
| 自由对象建构 | Algodoo、Polypad、GeoGebra、ChemCollective | 统一对象目录、连接规则、撤销、快照和方案比较 |
| 场景任务与角色 | Labster、ChemCollective、Gizmos STEM Cases | 场景包、目标/资源/约束、科学状态驱动成功失败 |
| 真正游戏玩法 | Legends of Learning | 同一知识目标允许多种挑战原型，不只加分数 |
| 短回合教学节奏 | Brilliant、CK-12 PLIX | 3–7 分钟微课件，预测—操作—反馈—解释 |
| 声明式作者系统 | Concord Lab Framework、EJS | `model + view + instruments + journey + challenge` 清单 |
| 数据与证据工作台 | CODAP | 图表、表格、探针和实验记录作为共享仪器层 |
| 内容组合与分发 | H5P、LabXchange | 可复用课件包、学习路径、导入导出、嵌入和版本固定 |

### 5.2 不应复制的模式

1. **逐页手工开发**：知识点越多，重复 UI、重复状态和质量漂移越严重。
2. **写实 3D 等于高级**：如果变量关系更难看清，3D 反而降低学习效率和设备覆盖。
3. **步骤完成等于理解**：按顺序点击器材不等于能提出问题、控制变量和解释证据。
4. **滑块数量等于自由**：只能改变预设参数仍是 F1。
5. **积分等于游戏**：没有策略、失败、重试和真实规则，只是奖励层。
6. **`iframe` 等于平台接入**：没有版本、状态、事件、权限和错误契约，外站无法可靠集成。
7. **资源数量等于覆盖质量**：同一知识点的重复页面不能替代依赖、误区、迁移和证据覆盖。
8. **AI 直接生成科学运行时**：Agent 可以组合经过验证的引擎与组件，不应自由生成未经校验的求解事实。

## 6. 对墨鱼工坊的产品方案调整

### 6.1 产品单位从“实验页”改为“互动知识单元”

一个可发布单元应由以下部分组成：

```text
Interactive Knowledge Unit
  ├─ Knowledge Contract       知识节点、先修、误区、学习证据
  ├─ Scientific/Math Engine   状态、约束、求解器、有效范围
  ├─ Object & Relation Kit    可创建对象、端口、连接与参数
  ├─ Scene Pack               世界对象、角色、视觉与叙事映射
  ├─ Modes
  │    ├─ Textbook Lab        标准实验和教材连接
  │    ├─ Free Sandbox        自定问题与建构
  │    └─ Challenge           目标、资源、成功、失败、重试
  ├─ Instruments              探针、轨迹、向量、图表、表格、比较
  ├─ Learning Journey         预测、操作、观察、解释、迁移
  ├─ Embed Adapter            宿主握手、状态和事件
  └─ Evidence & QA            来源、假设、测试、可访问性、性能
```

三种模式不是三套实现。它们共享同一科学状态和对象系统，只改变允许的组件、初始场景、目标、提示和展示层。

### 6.2 建议的三种发布规格

| 规格 | 典型时长 | 目标 | 必需能力 |
| --- | --- | --- | --- |
| Concept Widget | 3–7 分钟 | 在任意文章或题解中解释一个关键关系 | 立即可操作、一个核心因果、响应式嵌入、状态/完成事件 |
| Guided Lab | 10–20 分钟 | 完成教材实验、测量和解释 | 步骤、装置、数据记录、误差/边界、自由探索出口 |
| Sandbox Challenge | 15–40 分钟 | 自建系统、完成情境目标、比较策略 | F2/F3、规则驱动胜负、快照/重试、证据与复盘 |

不是每个知识簇都要同时制作三种规格，但一个引擎族必须证明它能支持三种规格，才能认为架构可复用。

### 6.3 覆盖率不能只数页面

建议把三科覆盖度定义为：

```text
Coverage = Knowledge Node Coverage
         × Engine Validity
         × Representation Coverage
         × Mode Coverage
         × Evidence Quality
```

其中：

- `Knowledge Node Coverage`：课标知识节点及依赖是否覆盖；
- `Engine Validity`：公式、单位、边界、数值稳定性和参考来源是否通过；
- `Representation Coverage`：对象、图像、表格、符号、微观/宏观表征是否联动；
- `Mode Coverage`：是否至少有解释、实验/建构、迁移或挑战中的合理组合；
- `Evidence Quality`：学习者是否留下预测、测量、方案比较和解释，而不只有完成标记。

## 7. 三科优先引擎族

### 7.1 物理

优先建立能被最多场景复用的引擎，而不是按章节制作页面：

1. 二维运动、力与约束；
2. 能量、动量、碰撞与弹簧；
3. 直流电路与测量；
4. 电场/磁场中的粒子和导体；
5. 波、振动、声与光线；
6. 实验测量、误差、拟合和传感器数据。

每个引擎先用无装饰经典实验校准，再装配生活/工程场景、反直觉现象、自由建构和挑战。

### 7.2 数学

数学不应只有函数滑块，应建立对象与依赖系统：

1. 函数、参数、变换、采样和多表征；
2. 平面几何约束与轨迹；
3. 向量、解析几何和空间投影；
4. 数列、递推与算法过程；
5. 概率试验、统计抽样和数据推断；
6. 微积分变化率、累积与极限的动态模型。

参考 GeoGebra 和 Polypad，让学习者构造对象、关系和反例；参考 Brilliant，把形式化推导放在直觉操作之后。

### 7.3 化学

化学应避免把每个反应做成独立动画，先建立：

1. 物质、容器、取用、混合、加热与分离；
2. 计量、浓度、气体和溶液平衡；
3. 酸碱、氧化还原、电化学和反应速率；
4. 粒子/结构/宏观现象多尺度联动；
5. 安全、有效范围、异常操作和证据记录；
6. 通用湿化学工作台上的教材实验、鉴别任务和开放设计题。

ChemCollective 证明了“一个可靠实验室 + 多个任务”比“一个题目 + 一个动画”更可持续；NOBOOK 和矩道证明了中国教材器材与操作语境必须进入对象库。

## 8. 路线图调整

### 阶段 B0：基线与协议，先于扩内容

- 冻结三种发布规格和 F0–F4 自由度定义；
- 完成 Embed Protocol、状态快照、事件词汇和匿名隐私基线；
- 建立统一课件壳、工具栏、仪器层、键盘与 reduced-motion 规范；
- 为现有三个模板补“经典实验 / 自由实验 / 场景挑战”模式声明，而不是立即制作大量皮肤。

完成标准：同一固定版本课件可在平台页和独立第三方样例页运行；宿主能暂停、恢复、切换语言、取回快照并接收检查点事件。

实施状态（2026-10-15）：

- [x] 新增严格的 `mooyu.courseware-experience` v1 契约，统一实验引擎、三种体验模式、F0–F3、对象命令、仪器和挑战成功条件；
- [x] Doctor 0.2.0 会拒绝缺少对象增删、放置、配置、运行、复位、记录或快照能力的“伪自由实验”；
- [x] `causal-simulation` 已用同一牛顿小车引擎跑通教材实验、F2 自由实验和“救援补给投送”挑战，并在平台宿主与课件直连页完成浏览器验收；
- [x] `concept-explorer` 已用同一二次函数引擎跑通教材探索、F2 曲线沙盒和“命中目标点”挑战；`algorithm-stepper` 已用同一化学平衡引擎跑通教材实验、F2 反应器沙盒和“安全生产批次”挑战；两者均完成真实浏览器交互验收；
- [x] 在不破坏冻结的 Embed v1 前提下实现 Embed v2 的快照读写和体验模式控制；已在两个独立宿主间完成数学沙盒状态导出、跨来源粘贴与恢复验收。

### 阶段 B1：三科最小引擎证明

- 物理：二维力学与约束；
- 数学：函数/对象依赖与动态图表；
- 化学：容器、物质、计量、混合与测量；
- 每个引擎制作一个教材实验、一个 F2 自由沙盒、一个真实规则挑战；
- 为每个引擎建立数值、单位、边界和回归测试。

完成标准：九个体验不是九套孤立代码，而是三个引擎、三种模式的组合证明。

### 阶段 B2：场景与玩法生产线

- 为一个引擎建立多个 Scene Pack；
- 建立挑战规则模板：设计达标、诊断故障、资源优化、预测拦截、反例构造；
- 允许多种解法，评分由科学状态、资源、稳定性和解释质量组成；
- 进行目标学生试玩，验证兴趣假设、理解路径和失败可读性。

完成标准：替换场景包不会复制求解器；挑战结果可由确定性重放验证。

### 阶段 B3：Agent 作者与知识覆盖工厂

- Agent 根据知识地图生成 `courseware brief`，选择经过验证的引擎、对象和场景模板；
- 工具自动检查知识依赖、单位、有效范围、文案、多语言、可访问性、嵌入和旅程测试；
- 人工集中审核科学事实、教学意图、兴趣假设和视觉体验；
- 按知识簇扩展，不以网页数量作为产能指标。

完成标准：新课件的大部分工作是配置、场景资产和教学设计，而不是重新发明状态机与嵌入桥。

### 阶段 B4：外站生态与课程编排

- 提供复制嵌入代码、固定版本、域名白名单和可选签名会话；
- 提供 WordPress、普通 HTML、React/Vue 和 LMS 接入样例；
- 建立类似 LabXchange 的 Pathway，把微课件、实验、挑战、讲解和题目编排为学习序列；
- 允许外部站点只嵌入所需单元，不要求迁移课程或账户体系。

完成标准：至少两个非墨鱼工坊页面完成无账号嵌入，一个授权宿主完成进度恢复和事件回传。

## 9. 产品验收评分卡

每个旗舰课件发布前建议按 100 分评审；任何红线失败都不能用总分抵消。

| 维度 | 分值 | 核心问题 |
| --- | ---: | --- |
| 科学/数学正确性 | 20 | 状态、单位、边界、近似和结果能否验证 |
| 直接操控与反馈 | 12 | 操作是否立即改变对象、数据或表征 |
| 自由建构 | 12 | 是否达到声明的 F 等级；能否改变结构而非只调参 |
| 情境与好奇心 | 10 | 目标是否让模型变得必要；是否产生可追问结果 |
| 挑战与重试 | 10 | 成败是否来自同一引擎；是否允许策略和低成本重试 |
| 多表征与证据 | 10 | 现象、图表、符号、表格和解释是否互相连接 |
| 教学路径 | 8 | 是否有预测—操作—观察—解释—迁移闭环 |
| 嵌入与互操作 | 8 | 固定版本、响应式、状态和事件是否可靠 |
| 可访问性与性能 | 6 | 键盘、文本替代、reduced-motion、设备预算是否通过 |
| 视觉与声音 | 4 | 层级、一致性、状态可读性是否服务于学习 |

红线：求解错误、未声明的科学近似、无法复位、状态不可重放、宿主可篡改结论、强制采集身份、键盘无法完成核心路径、把 F1 宣称为自由实验。

## 10. 最终定位

建议将这条产品线定义为：

> **面向中国高中数学、物理、化学的可嵌入互动知识运行时。它把课本中的模型变成可观察、可建构、可挑战、可解释的场景；课件托管在墨鱼工坊，但可以被任何获准网站以固定版本调用。**

它不是：

- 只供教师演示的虚拟实验播放器；
- 只展示动画的电子教材；
- 只有积分和闯关外壳的题库；
- 让 AI 任意生成公式和求解逻辑的网页生成器；
- 要求合作方迁移到墨鱼工坊内部的封闭 LMS。

它的核心护城河应是：**中国课标知识图谱 + 经验证的三科学科引擎 + 场景/玩法装配系统 + Agent 作者工具链 + 开放而安全的嵌入协议 + 持续积累的学习证据。**
