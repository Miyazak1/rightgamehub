# 自动调研与公开发布全流程审查

基线：无论文发布提交 `d2c08194`。独立分支：`codex/audit-blog-public-pipeline`。本轮不修改论文开关、历史运行、线上配置、密钥、迁移文件或其他工作区。

## 发现并修复

1. **调研契约不完整。** 规划请求声明最多 3 次搜索，但空结果回退按硬编码 5 次分配剩余额度。现改为计划搜索与回退共享被冻结的 maxQueries，并在候选集最终校验时再次核对。公开调研的 3 次搜索、5 个候选、每仓库 8 次请求、总计 43 次上限保持一致。规划提示词升级到 v3，明确数量、至少两个具体能力词及逐字使用配置兴趣标签；带冒号解释的既有标签与选题模块一样规范化为唯一配置标签，虚构及重复标签仍拒绝。
2. **阶段重试被误报成失败。** 旧公开执行器固定调用 4/7 次 runOnce，遇到 retry-scheduled 就退出，导致数据库仍待重试而外层宣告失败。现从共享工作流 manifest 获取阶段数、总尝试数和时间预算，等待数据库确定的 availableAt，再继续领取同一运行；重试不计入已完成阶段。未决外部结果、租约丢失、等待确认等状态不会被盲目重试；时间和尝试上限仍生效。
3. **长任务期间调度心跳过期。** 旧调度器只在整个调研/写作前后写心跳。现执行期间每隔不超过 30 秒写入 busy 心跳，避免长模型调用造成“执行器离线”误报；慢心跳不堆积，任务结束先清理定时器和在途心跳，再写 idle/suspended。心跳错误会记录诊断，不覆盖已提交的发布结果。
4. **发布成功后的确认丢失被误报失败。** 增加按当前机器人、当前运行 ID 限定的只读终态回查。只有持久状态确认为 succeeded、输出类型正确且输出 UUID 有效时，才确认完成；不重新执行发布。缺记录、其他运行、其他输出、uncertain 和非法 UUID 均不能据此认定成功。

## 逐段核查

| 环节 | 本轮核查边界 |
| --- | --- |
| 准入 | Foundation 唯一发布归属、旧链路停用、冻结人格、模型配置、能力/工具/工作流版本、GitHub 凭据存在性、预算和运行状态 |
| 自动调研 | 只输出查询计划；英文关键词与兴趣标签验证；搜索及回退总额度；查询来源与去重 |
| 候选交接 | 已成功发现运行的候选集、同一 Agent、内容摘要、输入版本、唯一交接及公开工作流版本 |
| 证据采集 | 固定仓库版本、资料哈希、合法来源、时间契约适配、不可变原始工具产物与证据绑定 |
| 选题 | 许可/归档/风险门禁、已发布项目复用规则、人格标签、比较数量与维度、冷却记忆及编号映射 |
| 写作与引用 | 仅已选仓库、显式局部来源编号、至多一次受治理纠正、原始输出/费用保留、规范 JSON 幂等请求 |
| 确定性校验 | 中文标题、正文长度与结构、事实段落引用覆盖、全部来源被引用、引用来源与选题一致 |
| 草稿 | 原始证据/选题/写作/校验血缘、内容哈希一致、同一运行与 Agent、引用证据覆盖及幂等保存 |
| 发布 | 归属行锁与代次、权限、当前草稿版本、内容哈希、事务内唯一回执/发布事件/编辑记忆、提交后只读对账 |
| 调度 | 北京时间每天 10 点、实际发布次数配额、连续失败暂停、显式恢复、长任务心跳及未决结果阻断 |

## 验证

真实 PostgreSQL 全链路使用任务专属数据库及本地 GitHub/模型夹具，实际执行发现工作流、候选交接、证据归档、公开文章工作流、引用证据落库与发布事务，并注入：

- 规划阶段在模型派发前发生一次可恢复失败；同一运行成功重试，审计中保留 retry-scheduled 事件。
- 首次文章含 `[1,3]` 越界引用；受治理纠正后继续通过证据校验、草稿与发布。
- 发布阶段数据库已经提交后丢失确认；只读对账确认成功，没有第二次发布。

最终发现和文章两个运行都 succeeded，只有 1 条公开发布回执和 1 条发布事件，所有引用有证据绑定，实际模型费用为 4 次（发现 1、选题 1、写作 1、纠正 1），没有创建论文任务。

另行实跑发现、原文章影子验收、草稿证据、发布故障恢复、引用纠正计费/重放、版本预检及计划恢复，共七个数据库测试文件、16 项测试通过。相关单元测试 18 项通过，包含假时钟验证心跳、重试等待、限额和无效对账阻断。日志保存在 `.runtime/blog-pipeline-audit/`，保留早期失败结果。

最终完整串行回归：365 个文件、1693 项测试，1611 项通过、0 失败、0 超时取消、82 项因依赖条件跳过，耗时约 4 分 56 秒。相关数据库 16 项已另行实际运行。报告为 `.runtime/blog-pipeline-audit/full-verified/result.json`、`results.tap`；数据库公开全流程（包含发布提交后确认丢失）的最终报告为 `public-pipeline-commit-loss-db.tap`。早期网页 load 等待超时记录保留，已修正对应夹具的 DOM 就绪等待及 Windows 原生日志句柄行为，断言和时限未放宽。

## 边界

这是本地确定性故障注入和代码审查，没有使用生产模型 Key，没有对线上发起调研或发布。真实服务不可用、模型连续输出不合格、预算不足或外部结果未决时，仍会按既有门禁停止并保留账本，不能保证外部服务永不失败，也不会通过新增任务或修改历史绕过检查。论文继续关闭。
