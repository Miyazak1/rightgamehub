# 作者指南：从 GitHub 导入作品

状态：适用于 G1 只读导入与 G2 受控静态构建
更新日期：2026-10-01

## 能做什么

GitHub 导入会帮你建立作品资料和可追溯来源，减少重复填写。它会读取你明确授权的仓库名称、介绍、默认分支、README、许可证，以及当时的固定 commit。

它不会运行仓库脚本、安装依赖或自动发布。对于不需要构建工具的纯静态 HTML 仓库，G2 可以在无网络隔离 Builder 中生成 Web ZIP；其他项目仍需由你在本地构建后手动上传 ZIP。

## 操作步骤

1. 进入“我的作品”，选择“从 GitHub 导入”。
2. 点击“连接 GitHub App”，在 GitHub 只选择准备导入的仓库。
3. 返回平台，选择连接和仓库，再点击“只读预览”。
4. 检查仓库、固定 commit、许可证和 README 摘要。
5. 修改作品名称、介绍和类型，创建私有草稿。
6. 如果仓库是纯静态站，填写可选子目录并发起“受控构建”；目录中必须有 `index.html`，且不能含 `package.json` 或其他构建描述文件。
7. 如果项目需要 Vite、React、Vue 或其他工具链，选择“手动上传 ZIP”，在本地完成构建后上传产物。
8. 两种方式得到的 ZIP 都会经过同一个平台安全校验；通过后由你明确点击发布。
9. 补充封面和资料。

## 权限与隐私

- GitHub 登录和仓库导入是两套独立授权。
- GitHub App 只需要 Metadata 和 Contents 只读权限。
- 平台不会显示或保存 installation token。
- 私有仓库可用于建立草稿，但仓库地址不会出现在公开作品资料中。
- 你可以在平台断开连接，也可以在 GitHub 中撤销 App 或移除某个仓库。
- 撤销后平台不再读取仓库；既有作品和必要来源审计不会被偷偷改写。

## 许可证提示

自动识别的 SPDX 标识只是证据，不是法律意见。没有许可证、许可证无法识别、素材来源不清或多许可证冲突时，请先确认你拥有发布和再分发权。受控构建可以生成待校验产物，但许可证未被识别时不能发布。

## Web ZIP 要求

- 上传构建后的静态文件，不要上传源码仓库本身。
- `index.html` 位于 ZIP 根目录。
- JS、CSS、图片、模型、WASM 等资源使用相对路径并包含在 ZIP 内。
- 当前流程不依赖仓库构建脚本，也不会读取 GitHub Actions 的产物。
- 大型网页 3D 项目仍受平台压缩包、解压后体积、单文件和文件数量上限约束。

## 受控构建限制

- 当前只有 `static-v1` 可执行：它只复制选定目录中的静态文件并重新封装，不执行任何作者命令。
- Builder 没有网络、GitHub 凭据、数据库凭据或 Docker Socket。
- `package.json`、锁文件、Vite 配置、自定义脚本、原生可执行文件和嵌套压缩包会被拒绝。
- 每次构建固定到导入时的 40 位 commit SHA；仓库出现新 commit 后，旧构建不能发布。
- Vite 项目目前只能被识别为后续计划，不会安装依赖或自动构建。

如果 GitHub 导入暂未开放，可以继续使用“新建作品”并手动填写公开仓库与许可证；上传发布能力不受影响。
