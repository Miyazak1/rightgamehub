# 小墨鱼 R1.7：论文发现、统一身份解析与私有研究队列

状态：已实现，等待整体验证与生产部署。

## 阶段目标

R1.7 不把“搜索到一个标题”当作论文研究入口。它在 R1.6 私有收件基座之上建立三个基础能力：

1. 受控发现：支持 DOI、arXiv、标题与作者、已接收私有资料四种入口；只读取有边界的元数据，不下载未经授权正文。
2. 统一身份：DOI、arXiv ID、用户文件内容哈希形成稳定别名；同一论文或同一文件不会重复进入研究队列。
3. 私有队列：确定性匹配和新候选进入待研究队列；模糊匹配或冲突进入阻断态，不进入公开文章链路。

## 不可妥协的规则

- 一个 Agent 只能看到和操作自己的发现批次、候选、身份别名与队列。
- DOI、arXiv ID、内容 SHA-256 可以形成精确身份依据。
- “标题＋作者＋年份”只能形成 `possible-match`；不得自动合并。
- 多个稳定标识指向不同身份时必须 `conflict` 并失败关闭。
- 模型不参与身份合并；判定账本明确记录 `modelUsed: false`。
- 发现链路没有博客发布、论文公开发布或第三方代码执行权限。
- 同一幂等键只能对应同一规范化查询。
- 队列删除被数据库禁止；状态变化必须追加不可变事件。

## 数据模型

- `agent_paper_discovery_runs`：不可变发现批次、规范化查询、提供商请求数。
- `agent_paper_discovery_candidates`：不可变候选及来源、指纹、元数据。
- `agent_paper_identity_resolutions`：不可变身份判定与依据。
- `agent_paper_identity_aliases`：DOI、arXiv、内容哈希到统一身份的映射。
- `agent_paper_research_queue_items`：运营队列状态；同 Agent 的 `queue_key` 唯一。
- `agent_paper_research_queue_events`：不可变状态变更审计。

所有跨表引用由数据库触发器再次核对 `agent_user_id`，不只依赖 API 条件。

## 发现与判定流程

```text
管理员私有请求
  -> 输入规范化与幂等校验
  -> Crossref / arXiv 元数据（最多一次请求）或私有收件账本
  -> 候选规范化与冻结
  -> 稳定别名 / 内容版本 / 标题作者年份核验
  -> 不可变判定
  -> 唯一私有研究队列或阻断队列
```

判定优先级：

1. 内容哈希命中已有版本：`exact-version`。
2. DOI / arXiv / 内容别名唯一命中：`exact-identity`。
3. 稳定标识互相冲突：`conflict`。
4. 标题、作者、年份唯一相似：`possible-match`，阻断等待更多稳定证据。
5. 没有既有身份：`new-identity-candidate`。

## 安全与预算边界

- 元数据响应上限 512 KiB，超时 15 秒，拒绝重定向。
- 标题作者搜索最多返回 8 个候选；一次发现最多 1 次远程请求。
- 私有收件发现零网络请求。
- 不获取 Crossref 或 arXiv 正文；正文仍必须走 R1.6 授权收件或既有开放论文工具。
- 所有管理 API 都在 `/v1/admin/agents/:agentUserId/` 下并复核运营者归属。

## 后台能力

机器人后台新增“论文发现与统一身份队列”：

- DOI 精确发现；
- arXiv 精确发现；
- 标题作者搜索；
- 最近候选与判定原因；
- 私有队列状态；
- 暂停与恢复，并写入审计事件。

后台不提供“强制合并”按钮。未来如需解决 `possible-match`，必须先加入新的、可验证的标识证据工作流。
