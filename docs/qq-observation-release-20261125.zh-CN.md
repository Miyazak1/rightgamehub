# QQ 观测修复：仅更新 worker

## 已确认的原因

现场分阶段计时显示：登录查询 97ms、账号 5ms、群信息 3ms，均成功；群成员查询约 7898ms 后触发整个采样 deadline。旧代码因此返回 `available=false`、`verifiedAt=null`，没有机会执行群列表备用查询。另一次受限读取已确认 QQ 原生在线、账号正确、管理令牌一致。本次修复针对 worker 的观测缺陷，不需要重新扫码或重启登录网关。

## 更新内容

运行侧只替换 `apps/qq-channel/src/napcat-control.mjs`：保留登录/账号的已验证进度；为次要查询划分短预算；成员超时后读取同一账号的群列表，并冷却坏掉的成员接口五分钟；每轮仍核对账号、群信息与当前成员关系。明确拒绝、错误账号、退群或无法验证仍关闭业务门禁。没有永久缓存群权限或取消 TTL。

上传包是经校验的源码补丁和操作工具，不含待加载的整套镜像。服务器以已经部署的独立 QQ worker 镜像为基础只 COPY 这一份文件，保留原镜像配置与层、完整 Compose 链、环境、卷、网络、入口、健康检查和权限。完整基础镜像 ID 取自既有独立插件部署回执并与当前容器、四份旧源码哈希同时核对，不凭截图猜测 ID。

此次不更新 API、Web、执行器、日调度、QQ 网关、数据库或桌面；不修改守护器配置和恢复次数上限，不迁移/恢复数据库，不重试旧任务。两套论文保持关闭，旧锁定记录和旧发布包不改写。之前本地修正的 Web 扫码错误显示属于另一项源码变更，不包含在本 worker 包里。

## 宝塔操作

1. 执行交付目录的 `server-create-upload-directory.txt`。
2. 将 `qq-observation-worker-20261125-r1.tar.gz` 和同名 `.sha256` 上传到 `/www/backup/gamehub/qq-observation-release-20261125-r1`，不要自行预先解压。
3. 执行 `server-update-worker.txt` 的完整内容。命令先校验原包与内部清单，核对现有部署回执、配置、空闲窗口、原生网关身份和私有 Node；候选镜像构建及非 root 读取校验通过后，才停止 worker。
4. 保持既有 QQ 网关运行，等待 70 秒管理鉴权冷却，创建新的 QQ 数据库备份，校验目录和完整解码。随后仅重建 worker，并验证新快照、连续推进和至少三次稳定观测。

成功标记为 `QQ_OBSERVATION_WORKER_UPDATED_VERIFIED`。它证明容器与后台采样验收通过，不冒充真实 QQ 新消息回执。网关容器 ID、启动时间、重启次数以及其他服务应保持不变。worker 会短暂停止收发；此窗口不要发送验收消息，等命令成功后再发送。

如果门禁发现新任务、定时窗口过近、配置/服务漂移或其他异常，会停止审核，不自动重试或自动回退。终端会给出新维护记录。`server-rollback-worker.txt` 从本包的新记录入口回退原 worker 镜像；不恢复数据库，不删新历史，不停用或重置守护器，也不重启网关。回退后会重新带回旧采样缺陷，只用于撤回本次 worker 变更。

## 新消息验收

更新成功后手动在原群发送：

```text

```

随后执行 `server-check-new-message.txt`。只有本次部署完成之后、指定群内的这条新请求，以及最终预期回复已确认送达，才返回 `QQ_OBSERVATION_NEW_MESSAGE_CONFIRMED`；“任务已保存”、旧成功记录、未送达回复都不算通过。没有工具主动向 QQ 发消息。
