# 部署、运维与验收技术规范

版本：TD-1.1 · 状态：部署设计与待执行验收清单 · [技术总纲](./13-technical-design.zh-CN.md)

2026-09-24 已启动 M0；初步 Harness 安装与样本结果见 [20](./20-execution-status.zh-CN.md)。以下完整矩阵仍需逐项验收，不能用子集结果勾选整个里程碑。

正式首版验收同时包含 [18 的多宿主闭环](./18-multi-host-client-spec.zh-CN.md)与 [19 的 Windows 分发](./19-windows-package-spec.zh-CN.md)。网页平台成本和测试不能替代新增范围。

## 1. 环境与部署单元

开发、测试、生产隔离数据库、桶、发信服务和凭据，可选 OAuth 应用也分别配置。测试邮箱不发真实验证码，Windows 检测/动态实验使用专用环境，不接生产作者资料。

首版沿用 [06 的 S 档](./06-server-sizing.zh-CN.md)：海外 2 vCPU / 4 GB / 80 GB Linux 主机，外接 R2 和 Worker。此前 30—40 USD/月是低用量规划预算，本轮未重新报价，不能据此承诺任意流量免费。单机故障会影响作者管理与发布；运行网关无法取得新鲜允许状态时也会拒绝服务。

| 部署单元 | 首版位置 | 资源安排 |
| --- | --- | --- |
| Caddy | 业务机容器 | HTTPS、静态网站、API 反向代理；上传不整包缓冲 |
| API | 业务机容器 | 初始内存上限 384 MiB，进程退出自动恢复 |
| PostgreSQL | 业务机容器和独立持久卷 | 约 1 GiB 内存预算，连接池 API/worker 各至多 5 |
| 协调 worker | 业务机专用非 root 主机服务 | 约 256 MiB，能启动固定的 rootless 解析容器；访问业务数据库的专用账号 |
| 解包容器 | 每个检查任务临时创建 | 16 定义的 512 MiB、1 CPU 等限制，单并发 |
| runtime-edge | Cloudflare Worker | 发布状态门禁、私有 R2 binding、内部缓存 |
| 备份与清理任务 | 业务机定时任务 | 与上传/检查错峰，独立备份凭据 |
| Windows 包扫描 | 独立受限资源或受控服务 | 按实际引擎测容量，不能套网页解析 512 MiB 限额；费用另计 |
| 登录邮件 | 受控发信服务 | 验证码限流、投递失败处理、测试/生产隔离；费用另计 |

上述限额为初始值，压测后调整并为 OS、缓存和短时峰值留余量；不是吞吐量证明。解析不能占满数据库内存。磁盘空闲低于 15 GiB 告警，低于 8 GiB 暂停新上传与检查，保留查询和管理能力。

API/数据库/代理可用 Compose 管理；协调进程使用 systemd，解析容器采用 rootless Podman。系统服务只允许固定镜像和任务目录组合，不提供任意 shell 参数。Podman 的网络、文件系统、内存和 rootless 限制按部署机器核验，不能仅凭写了配置就认为已生效。[Podman run 参考](https://docs.podman.io/en/latest/markdown/podman-run.1.html)

## 2. 配置与密钥

| 配置 | 使用者 | 要求 |
| --- | --- | --- |
| `APP_ORIGIN` | API、网站 | 固定 HTTPS origin，认证回调和 CSRF 校验使用 |
| `PUBLIC_API_BASE` | 插件、网站 | 公开非秘密配置；不允许游戏消息覆盖 |
| `RUNTIME_DOMAIN` | API、网关、播放器 | 单一运行域根，发布前验证 wildcard DNS/证书和 Worker 路由 |
| `MEDIA_ORIGIN` | 目录/网站 | 只返回处理过的图片 |
| `DATABASE_URL` | API/worker | 分角色凭据，仅私网/本机可达；migration 用单独高权限角色 |
| `MAIL_PROVIDER_* / OTP_HMAC_KEY` | API/发信模块 | 插件内验证码依赖，密钥不进 UI/日志；配置发送配额 |
| `GITHUB_CLIENT_ID/SECRET`、`GITHUB_CALLBACK_URL` | API 认证 | Web OAuth 主流程；Callback 必须是 GitHub App 中精确登记的 HTTPS 地址，本地开发可用 `127.0.0.1` 回环地址；Device Flow 仅作后备 |
| `SESSION_CSRF_SECRET/CURSOR_HMAC_KEY` | API | 强随机、独立用途；不得进前端包或日志 |
| `R2_ENDPOINT/QUARANTINE_BUCKET/RUNTIME_BUCKET` | API/worker | endpoint 和桶名不是秘密，凭据按桶和操作最小授权 |
| `R2_ACCESS_KEY_ID/SECRET_ACCESS_KEY` | API/worker | API 只写隔离区；worker 读隔离区、写运行区；不交给解析容器 |
| `INTERNAL_STATE_TOKEN` | Worker/API | 独立只读服务身份、可轮换、拒绝浏览器 Origin 和凭据泄露 |
| `PARSER_IMAGE_DIGEST` | 协调 worker | 固定 digest，不按浮动 latest 拉取 |
| 各配额、TTL 与超时 | 对应服务 | 使用 14—16 默认值，范围校验，变更留审计 |

生产使用受控 secret 文件或服务端密钥存储；示例配置只填占位符。插件发布物不得包含数据库、OAuth secret、R2 key 或内部状态 token。正常日志对 Cookie、Authorization、OAuth code、CSRF token 和正文做脱敏。

## 3. 网络与存储暴露面

- 业务机对公网仅开放 HTTPS；SSH 仅允许运维来源。数据库不映射公网端口。API 监听内部地址，代理负责外部访问。
- 业务上传域第一版不套入未经验证的 CDN 请求体限制；游戏运行域走 Worker，原始桶和 runtime 桶不启用绕过网关的公开域。
- Worker 仅使用 R2 binding 读运行资产，不能读原始隔离包；内部状态请求用独立凭据，不复用作者 session。
- 运行域不托管管理页面、不写认证 Cookie；业务域不直接服务作者 HTML。清理、备份文件和数据库快照不能通过静态路由访问。
- rootless 解析容器禁止外网、localhost 服务和元数据地址；启动验收用测试请求验证，而不是只检查命令参数。

## 4. 构建与发布顺序

1. 从确定的应用提交构建，安装锁定依赖，生成共享 Schema/类型/OpenAPI；记录构建 Node、pnpm、提交和镜像 digest。
2. 完成契约、隔离、上传发布、Windows 下载和玩家流程测试；分别打包 Harness tgz 与 VS Code/Cursor VSIX，并核对制品内容。
3. 部署测试数据库迁移、API/worker、运行网关和网站；创建测试作者及管理员，完成整条验收链路。
4. 备份生产数据库；先做向后兼容的新增迁移，再更新服务。迁移失败停止发布，不能启动不匹配的代码。
5. 先更新兼容旧插件的 API/运行协议，再更新网站和插件；插件发布独立版本和兼容矩阵。
6. 用已知样本做线上只读和专用测试作品冒烟验证，观察错误与资源指标。真实作者作品不作为破坏性测试目标。

目录/API 修改优先保持旧插件工作；破坏性协议升级用 `/v2` 或新的消息版本。数据库采用先增加、迁移、最后删除的步骤，至少跨一个回滚窗口；不可逆数据转换必须有备份和恢复方案。

不声称本轮已经提供这些镜像、脚本或 OpenAPI 文件。它们是实施阶段的明确交付物。

## 5. 回滚与停用

| 故障 | 处置 |
| --- | --- |
| 新 API 版本故障 | 回退上一镜像，前提是当前 migration 与旧版本兼容；暂停新发布任务避免状态继续变化 |
| 解包服务异常 | 暂停上传/处理，保留公开查询；已发布作品不依赖重新解包 |
| 单一作品有问题 | 管理禁用 Work/Release，确认门禁传播；不直接删库或破坏其他作品 |
| Worker 新策略误拦 | 回退已测策略版本，仍保留数据库禁用判断，不能关闭所有门禁 |
| Harness 插件故障 | 停用或安装上一兼容包；保留用户其他配置及会话 |
| 数据库或运行状态服务不可用 | 返回明确维护/重试状态；没有未过期允许结果时停止运行资产放行 |

游戏暂停、卸载和更新不应触发对作者的重新发布，也不能自动执行作者脚本来迁移存档。

## 6. 备份、保留与恢复目标

免费试运行的内部恢复目标先设为 RPO 24 小时、RTO 4 小时，待演练验证；长期付费方案里的 RPO 15 分钟不自动适用于当前部署。每天加密备份数据库，保留 7 个日备份和 4 个周备份，放在独立于业务盘的私有备份位置。

备份同时覆盖对象清单、运行策略配置、迁移版本、插件制品和必要的密钥恢复流程。R2 持久化不是对误删的完整备份：每个已发布不可变 release 的清单及资产至少保留一份独立备份副本，删除权限与运行凭据分开。上线前实测从空数据库和备份对象恢复可玩样本。

恢复过程中暂停发布与 GC，并默认停止公开分发。重建数据库后核对 current_release、版本状态和资产哈希，再核对备份时间之后的禁用操作；无法确认状态的作品继续停用，经明确复核后才恢复，不能直接把旧备份中的 published 全部放行。RPO 窗口内尚未备份的新数据可能丢失，不能承诺从旧快照重建不存在的记录。完成抽样和全量引用检查后才恢复写入。

业务日志建议保留 14 天，操作审计 90 天，匿名限流标识最长 24 小时，测试原包按 16 清理。具体个人数据保留策略在正式上线准备中确认；日志默认不采集游戏输入、聊天内容、源码或长期跨站游玩轨迹。

## 7. 监控与成本控制

| 信号 | 初始动作阈值/处理 |
| --- | --- |
| API 5xx | 5 分钟内超过 5% 且不少于 20 个请求时告警，区分发布和公开读取 |
| 队列延迟 | 最老 queued 超过 10 分钟告警；显示排队，不重复创建任务 |
| lease 过期 / 解析超时 | 逐任务记录，重复出现暂停新检查并排查 |
| 上传/处理成功率 | 分合法样本、格式拒绝、基础设施失败统计，避免把合法拒绝当宕机 |
| 游戏启动 | 区分 API 成功、frame load、SDK READY、用户确认可玩；没有 SDK 时不伪造成功率 |
| 资产 404/410/503 与缓存命中 | 按 release 聚合；404 激增说明包或路径问题 |
| CPU/内存/磁盘 | 连续高负载或低磁盘触发告警和上传降载，不能让解析进程挤死数据库 |
| 流量/存储/Worker 请求 | 设置月预算及 70%/90% 告警；必要时限速或暂停高消耗作品 |

匿名试运行不自动收集游戏内遥测；客户端诊断默认本地展示 requestId。向平台发送诊断时只包括版本、错误码与经用户确认的必要环境，不附工作区路径或游戏数据。

数字属于初始运维设置，试运行按实际基线调整。费用监控应覆盖对象操作、回源、API 主机带宽、备份及日志，不只计算主机租金。

## 8. 验收矩阵

所有下列项目当前状态为**待执行**。报告必须写明应用提交、插件版本、Harness 提交、OS/浏览器、设备和样本哈希，并保存可复核结果；不能把“文档检查通过”填成产品测试通过。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| H01 | 独立包安装 | 干净受管 Web profile 安装同一 tgz 后出现游戏大厅，无需修改宿主源码 |
| H02 | 启用、停用、卸载、重启 | 无残留 frame/声音/监听；原有配置与会话保留；重启不自动开游戏 |
| H03 | 基础游戏生命周期 | 收起、切会话、切设置均释放；回来明确重新打开，不能假称进度已保存 |
| H04 | SDK 游戏生命周期 | 1 秒暂停超时回收、5 分钟超期回收、恢复确认、重复 ACK 和迟到消息正确处理 |
| H05 | 多 tab/多个会话 | 全窗口至多一个 iframe；新游戏开始时旧实例先释放 |
| H06 | 实际输入与画面 | 360/480/800 宽度、键鼠焦点、Esc、指针锁、音频用户操作和展开均验收 |
| H07 | 第二台设备与升级 | 同一发布包能安装；至少一个新的目标 Harness 版本通过回归后才标支持 |
| P01 | 作者 A → 玩家 B | A 在宿主功能区上传发布，B 在另一兼容宿主发现、游玩/下载，无作者网站或免费领取必经步骤 |
| P02 | 三类作品 | Canvas、WebGL2、互动创意项目各至少一份；WASM 另测独立样本 |
| P03 | 更新失败与并发 | 旧版仍可用；晚完成的旧任务不覆盖新意图；新游戏使用新版、已开保持原版 |
| P04 | 幂等和进程崩溃 | create/complete/发布重试没有重复效果，worker 失租不能写结果 |
| P05 | 草稿与撤下 | 草稿无公共资产；作者撤下/管理禁用后 60 秒内新网络请求被拒绝 |
| P06 | 配额与保留 | 两个并发请求不突破作者配额；退休版本按宽限期处理，GC 不删活动任务资产 |
| S01 | ZIP 攻击集 | 路径穿越、链接、重复、炸弹、坏 CRC、大小谎报被拒绝；业务主机保持可用 |
| S02 | 解析环境 | 无网络/凭据、路径边界、CPU/内存/时间/磁盘限制实际生效 |
| S03 | 认证与归属 | A 无法改/读 B 私有对象；OTP/refresh 重放、grant 越权、Cookie CSRF 被拒绝；可选 OAuth 另测 |
| S04 | 消息攻击 | 错 origin/source/launchId、超长、未知类型、伪 ACK 不触发操作 |
| S05 | iframe 与来源 | 作品读不到平台登录态和宿主服务；顶层导航、设备权限、弹窗及 Worker 受限制 |
| S06 | 缓存绕过 | 命中资产缓存仍检查状态；直出桶和前置 CDN 不能绕过门禁；API 故障 fail closed |
| S07 | 路径与响应 | 编码路径歧义被拒绝；JS/WASM MIME 正确；404、Range、HEAD 和安全头一致 |
| F01 | 网络和兼容错误 | 超时、离线、CSP 拒绝、旧协议、WebGL 缺失有可解释界面和安全重试 |
| F02 | 清理幂等 | 重复关闭/停用、加载中切换、旧请求迟到不重建 frame 或覆盖界面 |
| O01 | 备份恢复 | 从空环境恢复作品、状态、资源和配置；禁用作品不会意外重新公开 |
| O02 | 负载与预算 | 2 路上传+1 检查+20 个公开元数据读取并发下无 OOM/数据损坏，记录延迟和费用估算 |

O02 是最小合成测试负载，不代表可支撑 20 个玩家或某个 DAU 承诺；游戏分发还需要按真实包大小、资源数量和并发首载独立测量。3D 报告记录设备与 FPS，不能推导“所有 3D 游戏流畅”。

## 9. 分阶段交付物

| 阶段 | 必须交付 |

| M0：宿主与播放器验证 | Harness tgz、VS Code/Cursor VSIX、2D/3D 样本、文件选择/保存探针、生命周期与来源通道记录 |

每阶段只把实际通过的版本和作品类型标为支持。M0 不能用外部网页截图替代功能区；M1/M2 必须包含 EXE 分发和三宿主闭环。原生侧栏实验可以先用自有样本独立推进，不等待完整后端；付费、云存档和云 GPU 串流均不作为前置条件。

## 10. 开发完成的判定

交付不止代码：必须有可安装包、可部署服务、Schema/OpenAPI、migration、配置模板、测试样本、安装/回滚/恢复说明和真实验收报告。线上域名、账号、管理员与预算由部署配置确定；不得在代码里写死开发者电脑路径或样本端口。

当前已按 M0 启动实施，基础 Harness 原型的具体结果见 20；以上完整产品验收尚未通过，后续逐项附证据更新。
