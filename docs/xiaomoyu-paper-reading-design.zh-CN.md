# 小墨鱼论文阅读机制设计

版本：v1.0  
状态：目标设计，尚未实现，不得对外宣称已经具备论文全文阅读能力  
更新日期：2026-10-24  
上位路线：[小墨鱼能力升级路线](./xiaomoyu-capability-roadmap.zh-CN.md)  
关联基础：[墨鱼变更雷达自主长期研究系统](./change-radar-autonomous-research-design.zh-CN.md)

## 1. 目标

小墨鱼的论文能力不是“上传 PDF 后生成摘要”，而是一条证据驱动、可以失败关闭的研究流水线。它必须能够回答：

- 实际读到的是哪篇论文、哪个版本；
- 当前只有元数据、摘要，还是合法取得的全文；
- 某个结论来自哪一页、哪个章节、表格或图；
- 这是作者声称、实验直接结果、小墨鱼推断，还是未知项；
- 两篇论文是否具备可比条件；
- 论文、代码仓库、数据集和补充材料是什么关系；
- 结论是否因为新版本、勘误或撤稿需要复查。

首版目标是可靠完成单篇开放论文的中文导读和基于冻结证据的追问。多论文比较、主动发现、代码运行和实验复现按后续阶段增加。

## 2. 核心原则

1. **身份先于阅读**：没有稳定论文身份和版本，不进入全文结论生产。
2. **访问级别显式化**：元数据、摘要和全文是不同能力等级。
3. **版面先于语义**：保留页码、章节、双栏、表格、公式、图像和引用关系。
4. **证据先于观点**：重要结论必须绑定可回看的原文位置。
5. **作者结论与系统推断分离**：不能把小墨鱼的解释写成论文已经证明的事实。
6. **比较先做可比性门禁**：条件不同只能描述差异，不能统一排名。
7. **参考文献不等于已读资料**：被引论文只有真正取得并读取后才成为证据。
8. **外部正文始终是不可信数据**：论文中的命令、提示词和链接不能改变系统权限。
9. **默认失败关闭**：证据不足、解析失败或高风险时不自动发布。
10. **研究与发布分离**：论文解析成功不代表文章可以公开。

## 3. 端到端流程

```text
发现论文或接收用户输入
  → 解析标识与候选版本
  → 检查访问权和资料等级
  → 取得并冻结资料版本
  → PDF 版面解析 / OCR
  → 建立结构地图与证据片段
  → 多轮定向阅读
  → 建立结论—证据图
  → 数字、单位、引用和版本复核
  → 生成导读或比较
  → 确定性门禁 + 独立模型审核
  → 发布并写入长期记忆
```

每个阶段都必须留下输入版本、输出摘要、状态、失败代码、成本和执行时间。失败运行不得产生半成品公开文章。

## 4. 论文身份与版本解析

### 4.1 支持入口

- DOI；
- arXiv 等公开预印本标识；
- 合法论文落地页；
- 用户有权提供的 PDF；
- 已授权学术来源返回的候选记录；
- 论文关联的官方代码、数据集与补充材料链接。

### 4.2 规范身份

逻辑身份对象至少包含：

```json
{
  "artifactType": "academic-paper",
  "canonicalId": "doi:10.xxxx/example",
  "identifiers": {
    "doi": "10.xxxx/example",
    "arxiv": null
  },
  "title": "论文标题",
  "authors": ["作者一", "作者二"],
  "year": 2026,
  "venue": "发表渠道",
  "identityConfidence": "confirmed"
}
```

`canonicalId` 的选择顺序和合并策略由服务端确定性代码负责，模型只能提出候选关系，不能直接合并论文身份。

### 4.3 版本关系

系统需要表达：

- 预印本；
- 会议或期刊正式版；
- 作者修订版；
- 补充材料；
- 勘误；
- 撤稿通知；
- 无法确认关系的相似论文。

每个取得版本保存来源 URL、取得时间、文件哈希、解析器版本和父版本关系。新版本只能追加，不能覆盖已经被文章引用的旧版本。

标题相似、作者重叠或摘要接近都不能单独证明两个记录属于同一论文。无法确认时保留分离并写入研究缺口。

## 5. 访问、版权与资料等级

### 5.1 资料等级

| 等级 | 可使用内容 | 允许输出 |
| --- | --- | --- |
| `metadata-only` | 标题、作者、年份、标识和发表信息 | 仅介绍论文身份，不评价方法和结果 |
| `abstract-only` | 元数据和摘要 | 研究问题及作者摘要中的有限主张 |
| `fulltext-open` | 合法开放全文 | 方法、实验、限制和页码级引用 |
| `fulltext-user-provided` | 用户有权提供的全文 | 在授权范围内阅读，不自动公开全文 |
| `fulltext-restricted` | 无权持久化或无法验证权限 | 不读取或仅保留获准的最小元数据 |

文章和追问必须继承资料等级。只有摘要时，模型不能讨论正文中的实验设置或限制。

### 5.2 获取策略

- 不绕过登录、付费墙、验证码或访问控制；
- 不通过其他转载站规避原站权限；
- 不自动下载来源不明的可执行附件；
- 长期保存以元数据、内容哈希、结构信息和必要证据片段为主；
- 完整 PDF 的保存期限、访问范围和删除规则由来源许可及用户权限决定；
- 文章只展示合理长度的证据片段，不镜像论文全文。

## 6. PDF 解析机制

### 6.1 解析产物

解析器输出的不是一段连续纯文本，而是 `PaperLayoutManifest`：

```json
{
  "artifactVersionId": "uuid",
  "pageCount": 14,
  "parserVersion": "paper-layout-v1",
  "pages": [
    {
      "page": 1,
      "width": 612,
      "height": 792,
      "readingOrder": ["block-1", "block-2"],
      "blocks": [
        {
          "id": "block-1",
          "kind": "paragraph",
          "bbox": [72, 110, 286, 320],
          "text": "原文",
          "confidence": 0.99
        }
      ]
    }
  ]
}
```

### 6.2 必须识别的对象

- 页面和章节层级；
- 单栏与双栏阅读顺序；
- 正文、摘要、脚注、页眉和页脚；
- 公式、算法和代码；
- 表格、行列、表题、单位和脚注；
- 图片、图号和图注；
- 参考文献条目；
- 正文中的引用标记；
- 补充材料边界。

### 6.3 OCR 回退

只有检测到页面缺少可靠文本层时才启动 OCR。OCR 产物必须记录：

- OCR 引擎与版本；
- 页面和对象级置信度；
- 原始页面渲染；
- 疑似错序、缺字和不可识别区域；
- 是否允许该页面进入自动发布证据。

低置信度数字、公式和表格不能由语言模型自行“纠正”。它们进入未知项或阻断发布。

### 6.4 分块策略

分块按章节、段落和版面对象进行，不使用任意固定 token 窗口切断上下文。每个块保留：

- 论文版本；
- 页码范围；
- 章节路径；
- 页面坐标；
- 前后相邻块；
- 表格、图形和脚注关系；
- 内容哈希与解析置信度。

模型读取时可以按问题取得相关块，但引用必须回到原始块，不能引用中间摘要。

## 7. 多轮阅读策略

### 7.1 第一轮：结构地图

目标是定位，不形成最终评价：

- 研究问题；
- 作者声称的贡献；
- 方法、实验、限制和结论所在章节；
- 关键表格、图形和补充材料；
- 需要进一步阅读的证据位置。

### 7.2 第二轮：方法阅读

抽取：

- 输入、输出和任务边界；
- 方法整体流程；
- 关键模块及依赖关系；
- 训练、推理或实验步骤；
- 方法成立所依赖的前提；
- 与论文明确列出的已有方法差异。

方法描述找不到原文支撑时保持未知，不使用模型常识补齐。

### 7.3 第三轮：实验阅读

抽取并校验：

- 数据集、样本或研究对象；
- 训练、验证和测试划分；
- 评价指标、单位和方向；
- 比较基线及版本；
- 主要结果；
- 消融实验；
- 失败案例；
- 统计区间和重复次数；
- 计算资源和实验预算。

表格数字必须绑定单元格、行列标题和脚注。正文转述和表格不一致时保存冲突，不能任选一个当作事实。

### 7.4 第四轮：限制与反证

专门查找：

- 作者明确承认的限制；
- 没有覆盖的任务、数据或人群；
- 依赖的假设；
- 缺失的重要基线；
- 只在单一数据集成立的结论；
- 结果与结论之间的过度外推；
- 勘误、撤稿和后续版本信号。

### 7.5 第五轮：读者表达

最后才根据目标读者生成：

- 大众导读；
- 方法拆解；
- 实验阅读；
- 多论文比较；
- 论文与代码实践指南。

不得通过逐层摘要反复压缩全文后再引用最后一层摘要。文章观点可以来自结构化结论，但事实引用必须落回原始证据片段。

## 8. 证据和结论模型

### 8.1 证据片段

```json
{
  "artifactVersionId": "uuid",
  "evidenceKind": "table-cell",
  "page": 7,
  "sectionPath": ["实验", "主要结果"],
  "objectLabel": "表三",
  "bbox": [82, 214, 515, 622],
  "excerpt": "合理长度的原文片段",
  "contentHash": "sha256",
  "extractionMethod": "layout-parser",
  "confidence": 0.97
}
```

### 8.2 结论类型

- `author_claim`：作者在论文中明确声称；
- `observed_result`：表格、图形或实验段落中可定位的结果；
- `xiaomoyu_inference`：小墨鱼根据证据作出的有限推断；
- `unknown`：现有资料不能回答；
- `conflict`：不同位置或不同版本的证据不一致。

### 8.3 结论—证据关系

每条结论可以有：

- `supports`：支持；
- `weakens`：削弱；
- `contradicts`：反对；
- `context`：背景，不足以支持结论。

发布时的重要结论至少需要一条有效支持证据。出现未解释的反对或冲突证据时，文章必须呈现限制或停止发布。

### 8.4 与现有研究账本的关系

论文能力优先复用现有：

- `tool_research_topics` 与研究契约；
- `tool_research_runs` 与运行状态；
- `tool_research_sources`、`tool_research_source_versions`；
- `tool_research_evidence`；
- `tool_research_claims`、修订和证据关系；
- 研究缺口、预算、供应商熔断和质量抽样。

需要增加的是论文特有扩展，例如规范学术标识、论文版本关系、PDF 版面清单、版面对象、解析状态和论文—代码—数据关系。最终迁移前必须先完成现有表约束映射，不新建语义重复的平行账本。

## 9. 数字、单位与表格校验

论文最容易出现“文字读对、数字写错”。服务端需要确定性校验：

- 原始字符串和解析后的数值同时保存；
- 百分比、小数、倍数和百分点分开；
- 指标方向保存为 `higher-is-better`、`lower-is-better` 或未知；
- 数值绑定数据集、任务、模型、行列标题和脚注；
- 正负号、上下箭头、最佳值加粗不能由模型单独解释；
- 单位换算必须使用白名单规则并保留原值；
- 比较结论使用的数字必须能在证据单元格中重新计算。

自动检查失败时不允许模型用自然语言绕过。

## 10. 多论文比较门禁

### 10.1 对齐维度

比较前建立 `ComparisonEligibility`：

```json
{
  "sameResearchQuestion": true,
  "taskCompatible": true,
  "datasetCompatible": false,
  "splitCompatible": false,
  "metricCompatible": true,
  "baselineCompatible": "unknown",
  "budgetCompatible": "unknown",
  "decision": "describe-only"
}
```

### 10.2 决策

- `rankable`：关键条件一致，可以进行有限结果比较；
- `describe-only`：可以比较方法和实验设计，不能统一排名；
- `incomparable`：研究问题或证据不足，不生成对比结论。

只要数据集、划分、指标定义或实验预算存在关键差异，就不能仅凭摘要中的最佳数字排名。

## 11. 参考文献与引用网络

参考文献条目首先只是 `citation-candidate`。它只能证明当前论文引用了某个条目，不能证明：

- 被引论文的具体内容；
- 当前论文对它的概括准确；
- 小墨鱼已经读过被引全文；
- 多篇论文构成相互独立的证据。

被引论文只有经过独立身份解析、访问检查和实际阅读后，才能成为新的 `ResearchArtifact` 和证据来源。引用网络可用于发现候选，不用于自动计算真实性或权威性。

## 12. 论文与代码、数据关系

关系类型包括：

- `official-code`：论文或作者明确提供的官方代码；
- `official-data`：官方数据集或数据说明；
- `supplementary-material`：补充材料；
- `third-party-implementation`：第三方实现；
- `claimed-reproduction`：外部声称复现，尚未由平台验证。

首版只验证链接关系和静态资料。以后进入隔离执行阶段时，才允许固定 Commit、安装依赖和运行最小示例。

“代码可以启动”不等于“论文已复现”。复现状态至少区分：

- 未运行；
- 安装成功；
- 示例成功；
- 部分指标验证；
- 在冻结环境中达到预先定义的复现门槛；
- 结果未知或不一致。

## 13. 模型与确定性程序分工

### 13.1 确定性程序

- 标识、URL 和文件哈希；
- 版本追加和不可覆盖；
- 页码、版面坐标和阅读顺序；
- 表格行列、数字和单位；
- 字段、长度、枚举和引用边界；
- 访问权、预算、频率和权限；
- 引用是否属于实际取得的论文版本；
- 状态机和幂等。

### 13.2 阅读模型

- 识别研究问题与章节职责；
- 提取候选结论；
- 解释方法；
- 发现限制、冲突和知识缺口；
- 判断普通读者可能关心的角度；
- 形成结构化中文表达。

### 13.3 独立审核模型

- 是否夸大结论；
- 是否混淆作者观点和小墨鱼推断；
- 数字、数据集和指标是否对应；
- 是否遗漏关键限制；
- 是否引用错误版本；
- 是否把不可比较的论文做成排名；
- 是否出现时政、医疗、投资或其他高风险误导。

阅读和审核使用分离的调用与提示，审核不能仅重复写作模型的自评。

## 14. 文章产品

### 14.1 大众导读

- 为什么值得关心；
- 研究问题；
- 核心思路；
- 主要证据；
- 能说明什么；
- 不能说明什么；
- 如何继续阅读。

### 14.2 方法拆解

- 输入输出；
- 流程和关键模块；
- 训练或推理过程；
- 与已有方法差异；
- 前提和限制。

### 14.3 实验阅读

- 数据和任务；
- 指标与基线；
- 主结果；
- 消融与失败案例；
- 结论边界。

### 14.4 多论文比较

- 共同问题；
- 可比性判断；
- 方法差异；
- 实验条件对齐表；
- 可以比较与不能比较的部分；
- 尚未解决的问题。

论文标题、模型名、数据集名可以在正文首次出现时保留原文。当前博客“标题不得含英文字母”的规则不能未经设计直接套用到论文产品；论文产品需要独立的中文标题与原始论文标题展示规则。

## 15. 追问机制

### 15.1 本文内回答

- 只读取已发布文章和冻结论文证据；
- 不联网、不查新论文；
- 引用回到实际论文页码；
- 证据不足时直接说明缺失项。

### 15.2 继续研究后回答

- 创建新的异步研究运行；
- 可以寻找新版本、补充材料或其他论文；
- 使用独立预算和幂等键；
- 新证据形成新版本，不静默改写旧文章；
- 完成后显示新增资料和结论变化。

两个模式在界面、费用、状态和审计上必须分开。

## 16. 状态机与失败关闭

建议运行状态：

```text
queued
  → resolving_identity
  → checking_access
  → acquiring
  → parsing
  → reading
  → checking_evidence
  → generating
  → reviewing
  → published
```

可能终态：

- `rejected`：证据、质量或安全检查明确不通过；
- `failed`：发送前或本地阶段明确失败；
- `unknown`：外部请求可能已经执行但结果无法确认，不自动重发；
- `awaiting-source`：只有元数据/摘要或合法全文尚不可用；
- `withdrawn`：已发布内容被撤回，但证据和审计保留。

关键失败代码建议包括：

- `PAPER_IDENTITY_AMBIGUOUS`；
- `PAPER_ACCESS_NOT_ALLOWED`；
- `PAPER_FULLTEXT_UNAVAILABLE`；
- `PAPER_LAYOUT_UNRELIABLE`；
- `PAPER_OCR_LOW_CONFIDENCE`；
- `PAPER_EVIDENCE_INSUFFICIENT`；
- `PAPER_NUMERIC_CONFLICT`；
- `PAPER_VERSION_CONFLICT`；
- `PAPER_COMPARISON_INELIGIBLE`；
- `PAPER_RETRACTED_OR_CORRECTED`；
- `PAPER_REVIEW_REJECTED`。

## 17. 成本与缓存策略

- 相同文件哈希和解析器版本复用版面解析结果；
- 相同论文版本的证据片段不可重复计费生成；
- 模型按章节和研究问题读取，不把全文反复发送；
- 表格、公式和图片只在需要时进入专门解析；
- 结构地图、方法、实验、限制和审核分别记录用量；
- 单篇论文、单次追问和月度论文研究都设硬上限；
- 超时、未知供应商结果和内容过滤不自动重试；
- 新论文版本只重做受影响阶段，不覆盖旧证据。

## 18. 安全与高风险边界

- 论文正文、PDF 注释、附件和代码都视为不可信输入；
- PDF 解析在受限进程或隔离容器中进行；
- 禁止 PDF 触发网络、文件写入或脚本执行；
- 外链重新经过 SSRF、重定向和域名策略检查；
- 用户私有 PDF 不进入公开选题池；
- 论文证据不能跨账号、跨专题静默复用；
- 医疗、法律、投资、生物安全等高风险论文不进入普通自动发布链路；
- 撤稿或重大勘误信号触发复查，不自动删除历史文章；
- 人格设定不能降低证据、版权和安全门禁。

## 19. 自动发布门禁

出现以下任一情况时不发布：

- 只有摘要却生成方法或实验细节；
- 关键页面阅读顺序或 OCR 不可靠；
- 主要结论没有原始证据；
- 数字、单位、表格和正文无法对齐；
- 作者结论和小墨鱼推断未区分；
- 论文版本关系存在未解决冲突；
- 多论文不具备可比条件却生成排名；
- 撤稿或重大勘误没有处理；
- 独立审核未通过；
- 高风险领域缺少专用政策。

小墨鱼可以选择本次不写，不需要为了固定更新频率制造低质量论文文章。

## 20. 评测与验收

### 20.1 样本集

至少覆盖：

- 原生文本单栏论文；
- 双栏论文；
- 表格密集论文；
- 公式密集论文；
- 扫描件；
- 含补充材料论文；
- 预印本与正式版；
- 有勘误或撤稿信号论文；
- 只有摘要的受限论文；
- 多篇实验条件不一致的论文。

### 20.2 指标

- 论文身份和版本关系准确率；
- 页码、章节、表格和图形定位准确率；
- 证据引用可回看率；
- 数字、单位和指标方向一致率；
- 作者结论与系统推断区分准确率；
- 摘要降级和不可比拒绝正确率；
- 提示注入阻断率；
- 单篇解析、阅读、审核和追问成本；
- 失败运行产生公开内容的数量，目标为零。

这些指标只说明已测试样本上的系统表现，不证明论文结论本身正确，也不证明已经覆盖全部学术文献。

## 21. 分阶段交付

### P0：契约和样本冻结

- 冻结论文身份、资料等级、版面清单和证据契约；
- 盘点现有研究表与需要的增加式扩展；
- 建立 PDF、版本、表格和失败样本集；
- 明确版权与保存策略。

### P1：单篇论文阅读最小闭环

- DOI/arXiv/PDF 身份解析；
- 开放全文与用户文件权限检查；
- 页码和章节解析；
- 结构地图、方法、实验和限制阅读；
- 大众导读；
- 本文内追问。

### P2：复杂版面和可靠引用

- 双栏、表格、公式、图片和 OCR；
- 数字和单位校验；
- 原文片段与页面区域查看；
- 预印本、正式版和勘误关系。

### P3：多论文比较与继续研究

- 可比性门禁；
- 多论文证据矩阵；
- 引用网络候选发现；
- 异步继续研究后回答；
- 结论修订和新版本复查。

### P4：论文与代码验证

- 官方代码、数据和补充材料关系；
- 仓库静态检查；
- 一次性沙箱运行；
- 安装、示例、部分指标和复现状态分级。

## 22. 第一实施包建议

开始编码时先交付 P0，不直接接自动发布：

1. 输出现有研究表到论文领域对象的映射文档；
2. 冻结 `PaperIdentity`、`PaperVersion`、`PaperLayoutManifest` 和 `EvidenceSpan` JSON Schema；
3. 准备至少十类真实开放论文与失败样本；
4. 实现文件哈希、资料等级、页码和章节最小解析；
5. 建立页码引用回跳的内部预览；
6. 运行离线评测并记录无法解析的情况；
7. 只有达到身份、定位和失败关闭门槛后，才接入小墨鱼的生成与发布流程。

第一版宁可稳定阅读少量合法论文，也不以不可靠的全文总结换取表面覆盖量。
