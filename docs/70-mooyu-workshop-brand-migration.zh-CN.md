# 墨鱼工坊品牌命名与迁移规范

## 1. 正式品牌

- 中文名：**墨鱼工坊**
- 英文与域名品牌：**MOOYU.FUN**
- 中英文首次并列：**墨鱼工坊（MOOYU.FUN）**
- 品牌主张：**打开就玩，也一起创造。**
- 正式站点：<https://mooyu.fun>

“墨鱼工坊”强调玩家可以直接游玩，也强调创作者、开源作者和社区成员共同完善作品。面向中文用户时优先使用中文名；面向国际用户、协议元数据和来源标识时优先使用 `MOOYU.FUN`。

品牌图标使用紫色像素墨鱼：对称身体、方形双眼和三组触手构成核心轮廓。网站导航、favicon 和编辑器 Activity Bar 必须使用同一轮廓；允许根据宿主使用彩色版或单色版，但不要重新使用手柄、抽象字母或不相关的方块图标。

## 2. 公共界面规则

以下位置必须使用新品牌，不再把 `GameHub` 作为面向用户的产品名：

- 网站标题、导航、登录、邮件、分享图、SEO 与结构化数据；
- 社区、发现、作品详情、创作者中心和推广内容；
- VS Code / Cursor 扩展的显示名称、命令标题和用户提示；
- Codex / Claude 插件的展示名称、技能说明和安装提示；
- 安装器、更新器中用户可见的成功、失败和操作指引；
- 对外邀请、作者联络、README 与当前产品文档。

文案中不要写“墨鱼工坊平台”来重复表达，也不要在中文名两侧留下无意义空格。紧凑位置只显示“墨鱼工坊”，需要来源识别或国际传播时使用“MOOYU.FUN”。

## 3. 暂不迁移的兼容标识

本轮是公共品牌迁移，不是底层协议重命名。下列已有标识必须继续保留，避免破坏旧版本更新、登录、存档、插件安装和部署：

| 类型 | 保留示例 | 原因 |
| --- | --- | --- |
| 包名与作用域 | `@gamehub/*`、`gamehub-agent` | 已被构建、发布和依赖关系引用 |
| 插件与命令 ID | `gamehub`、`gamehub.open` | 宿主按稳定 ID 查找和升级插件 |
| API 请求头 | `X-GameHub-Session`、`X-GameHub-Save-Schema` | 属于客户端与服务端协议 |
| 环境变量 | `GAMEHUB_*` | 生产配置和运维脚本正在使用 |
| 本地目录 | `%LOCALAPPDATA%\GameHub`、`.gamehub` | 保留现有凭据、更新状态与草稿 |
| 服务与容器名 | `gamehub-production-*` | 避免部署时创建重复服务和数据卷 |
| 代码符号 | `createGameHubClient`、`GameHubSDK` | 属于公开或内部 SDK 接口 |
| MCP 资源 URI | `ui://gamehub/*` | 宿主缓存和已安装插件依赖该 URI |

面向开发者的兼容标识可在代码、日志或技术文档中继续出现，但用户界面的显示名称必须使用新品牌。

## 4. 数据与账号

本轮不执行数据库批量改名，也不改已有用户、作品或活动的内容。历史数据中若包含旧品牌，应通过管理员工具或后续的可回滚数据迁移处理，不在应用启动时静默改写。

GitHub App、OAuth、Webhook、回调地址和域名继续使用 `mooyu.fun`，不因中文品牌变化而改变。若 GitHub 后台显示名称仍为旧名，应单独更新显示名称和说明，但不得重新生成密钥或修改现有回调路径。

## 5. 后续迁移顺序

1. 完成网站、邮件、分享图、扩展和插件的公共文案统一。
2. 构建 Web、VSIX 与 Agent 插件包，确认生成物中显示新品牌。
3. 验证旧插件可以通过原 `gamehub` ID 自动升级，旧登录和存档仍可使用。
4. 部署后抽查首页、发现、作品详情、社区、创作者中心、登录、安装页和 MCP App。
5. 最后更新外部平台的展示名称、头像、简介和推广素材。

除非另立协议版本并提供完整迁移工具，不对第 3 节的兼容标识做机械替换。

## 6. 验收标准

- 用户主要页面不再把 `GameHub` 当作当前正式品牌展示；
- 浏览器标题、邮件、分享卡和安装提示统一为“墨鱼工坊 / MOOYU.FUN”；
- `X-GameHub-*`、`GAMEHUB_*`、插件 ID、命令 ID、本地目录和服务名保持不变；
- 已安装插件可以继续自动更新，已有账号、草稿和游戏存档无需迁移即可使用；
- `mooyu.fun` 的站内链接、OAuth 回调、Webhook 和 MCP 连接不受影响。
