# P0.7：猜百科官方题库供给

日期：2026-09-29。范围：把猜百科从随前端打包的静态选题，升级为数据库驱动的官方题库与每日发布管线。本阶段不做在线抓取；内容仍来自已核验的中文维基百科完整导言，避免运行时依赖外部网站。

## 发布规则

- 题目必须是中文维基百科条目的完整序言，正文至少包含 180 个汉字；
- 来源必须为 `zh.wikipedia.org/wiki/`，许可必须为 `CC BY-SA 4.0`；
- 启动本地 API 时会幂等导入内置题库，但不会擅自重新启用管理员已停用的题目；
- 管理员可以预览完整导言、启用或停用题目，并把合格题目排到今天或未来日期；
- 当天有人工排期时优先使用该题；没有排期时，只在可发布池中做按日期稳定的确定性轮换；
- 若排期题后来被停用，日题会安全回退到其他可发布题，不让当天游戏失效。

## 数据与接口

- `0025_guess_baike_content_pipeline.sql` 新增 `guess_baike_puzzles` 和 `guess_baike_schedule`；
- 公共日题接口从数据库读取发布结果；提交成绩时同时校验中国时区日期和当天题目 ID，拒绝过期或伪造题目；
- 新增管理员题库列表、题目状态修改和日期排期接口；
- OpenAPI、TypeScript 声明和共享 API 客户端同步更新；
- 管理后台新增「猜百科官方题库」区域，包含质量信息、原文预览、来源、状态和排期操作。

## 2026-10-21 严格自动选题补充

题库采用“默认拒绝”而非人工审核：自动候选只有在所有信号明确通过时才进入 `ready`；任何规则失败、信号缺失或判断不确定的条目直接进入 `rejected`，不能由管理员人工恢复。

- 展示标题只允许 2 至 10 个汉字，可含间隔点，禁止拉丁字母；
- 拒绝政治、时政、在世人物、选举、外交争议和不稳定事件；
- 主题必须明确归入人文、历史、地理、娱乐、科学、体育或生活；
- 自动候选需要至少 30 天访问数据，近 60 天访问量合计不少于 3,000；
- 中文正文比例不得低于 72%，完整导言仍需至少 180 个汉字；
- 自动候选的分类、访问量、中文比例和规则版本写入 `selection_signals`，便于审计；
- 旧规则导入且缺少当前规则证据的自动题目会转为 `rejected`，其未来排期会被移除；
- 内置人工精选题只免除外部访问量依赖，仍必须通过标题、主题、中文比例、敏感性、来源和许可检查。
