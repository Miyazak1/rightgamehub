# 小墨鱼 GitHub 项目问答

分支：`codex/github-research-qa`，从已验收的 `73b44ddd` 建立。仅本地实现与验证，没有部署线上。

## 行为

网站 Chat 和 QQ 使用同一小墨鱼、模型 Key、授权及预算账本。找候选项目用 `github_search_projects`；针对实现、亮点、限制和总结的问题用新增的 `github_answer_question`；明确要求写文章才进入 `github_write_article`。明确“只回答／只总结／不写文章”的请求还有服务端防误建文章检查。

问答作为独立持久任务接收，先回受理消息，执行完成后通过原有页面或 QQ 发送账本回到原会话。默认文字，整条回复限制为 7800 UTF-8 字节，避免经过 QQ 的既有截断逻辑。该能力不新增文章、不发布文章，也不读取其他用户草稿；本轮不实现图片生成。

有明确仓库链接时使用该项目；省略链接的追问，仅从同一 Agent、渠道、提问者和会话的最近项目任务继承项目。继承上次已完成问答的固定提交、问题和回答；切换仓库不携带旧项目版本或回答。最近任务产生多个候选且没有唯一项目时，要求提供链接，不回退猜测更早的项目。

## 研究与证据

工作流 `agent.github.question@2` 分为目录读取、文件规划、初次读取、补读规划、补充读取、回答六阶段，分别受原有只读工具或模型能力约束。最多三次研究模型调用、九次工具调用（另有对话入口选择工具的一次模型调用）。关键函数仅有调用点时，根据已读片段和词法符号位置补读一次；信息已充分时不再补读。符号表只提供定位提示，不能替代读取函数体的证据。每阶段独立账本、租约及证据引用，重放成功任务不再调用外部服务。旧 v1 四阶段合同和真实结果保留，恢复时沿用原版本，不将已完成任务自动重新研究。

新增 `research.github.code.read@1`，沿用 `research.github.read` 授权，只访问 GitHub API，不执行仓库代码。每次重新检查仓库公开状态。第一次解析默认分支到完整提交 SHA，目录、文件和后续追问均按 SHA 读取；目录排除符号链接和子模块。文件规划只能选择已返回目录中的路径，不能自行构造其他下载地址。

目录 API 的行为与截断标志参考 [GitHub Git Trees 文档](https://docs.github.com/en/rest/git/trees)；固定版本文件读取参考 [Repository Contents 文档](https://docs.github.com/en/rest/repos/contents)。网络请求禁止重定向，沿用已有请求头和凭据处理。

本轮查询有明确边界：目录响应最大 1 MiB，交给模型的路径最多 500 项、约 20 KiB，优先源码与测试；初读及补读各最多四个片段，每段最多 140 行、4 KiB，单个文件只读取前 256 KiB。截断明确记录。大型仓库或跨很多模块的问题可能不足以确定结论，需在回复中说明，并通过缩小问题或追问继续研究，不声称全库审计或执行了测试。

回答模型只能输出带来源编号和行号的结构化结论，分为代码事实、作者说明、分析推断，另列尚未确认的事项。服务端核对来源存在、行号落在实际读取范围、引用 URL 属于同一仓库和提交。README 等 Markdown 文档不能作为“代码事实”的依据。链接和编号由服务端生成，模型不能提供任意引用 URL。引用范围验证不等于自动证明自然语言结论完全正确，仍需阅读者判断其推断是否成立。
