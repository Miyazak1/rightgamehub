# 墨鱼工坊中英文国际化实施规范

状态：I1— I4 已实施，等待发布验收 · 制定日期：2026-10-13 · 默认语言：简体中文 · 首个新增语言：English

当前已交付统一语言上下文、浏览器语言识别、本地持久化、语言切换入口、数字/日期 formatter 与双语目录一致性测试；公开玩家路径已覆盖全局导航、发现、登录入口、作品详情核心信息、分享面板、播放器外壳和游戏库。I2 已覆盖社区壳层、首页、参与收件箱、动态阅读/筛选/收藏/分享/发布编辑/举报，项目、活动与组队的列表/创建/详情/参与和管理操作，以及贡献任务的领取、提交、验收与历史记录。I3 已覆盖创作者工作台、新建/编辑作品、上传发布、GitHub 导入与受控构建、反馈、认领、贡献任务、作者数据、开发日志、AI 接入任务、多人与排行榜开发文档。I4 已覆盖验证码邮件、作品与专题 SEO/OG、双语分享图、MCP App 语言传递、安装页、VS Code/Cursor 清单本地化与首批英文公开文档。用户创作内容保持原文；管理员后台与社区审核管理明确保持中文。

## 1. 目标

墨鱼工坊必须支持 `zh-CN` 与 `en`，并保证网页、插件侧栏和公开分享入口使用同一语言语义。首轮不要求翻译用户创作的标题、介绍、帖子和游戏内容；平台生成的导航、按钮、状态、表单、错误说明、邮件和分享文案必须可本地化。

## 2. 语言决策

语言优先级固定为：用户主动选择并持久化的语言 → 已登录账号语言偏好 → 宿主或浏览器语言 → `zh-CN`。只识别受支持语言，`en-US`、`en-GB` 等统一回退到 `en`；未知语言回退到 `zh-CN`。

语言切换入口放在全局导航的账号/设置区域，并在未登录状态可用。切换后立即更新当前界面、`<html lang>`、日期、数字和无障碍标签，不改变当前路由，也不要求重新登录。

## 3. 技术边界

- 建立单一 `LocaleProvider`、`useI18n()` 和类型稳定的 key 目录，业务组件不得继续新增裸写的平台固定文案。
- 文案目录按领域拆分：`common`、`navigation`、`discover`、`work`、`account`、`community`、`creator`、`admin`、`errors`。
- 日期、时间、数字和列表统一经过 locale formatter；不得在组件里固定调用 `toLocaleString('zh-CN')`。
- API 错误以稳定 `code` 为主，客户端按 code 本地化；服务端中文 `message` 只作为兼容回退，不能作为业务判断条件。
- 用户内容不做机器翻译。平台内置游戏或运营专题如需双语，数据模型增加显式的本地化字段或内容版本。
- SEO、Open Graph、邮件、分享图、MCP widget、VS Code/Cursor 扩展和安装器纳入后续阶段，不能声称网页切换完成即代表全平台国际化完成。

## 4. 实施阶段

### I1：基础设施与公开玩家路径

建立语言解析、持久化、上下文、formatter 和缺失 key 测试；完成全局导航、发现页、作品详情、播放器外壳、登录/注册和基础错误页。此阶段完成后，未登录海外玩家可以全程使用英文发现并开始游戏。

### I2：社区

覆盖社区首页、动态、项目、活动、组队、参与记录、发布与举报流程。帖子、项目目标和用户昵称保持原文，平台状态和操作使用当前语言。

### I3：创作者中心

覆盖我的作品、上传发布、GitHub 导入、版本与构建、反馈、认领、贡献任务、作者数据和 AI 接入任务。管理员后台、审核队列、平台运营和系统状态不做国际化，继续使用中文。

### I4：站外与宿主

覆盖登录邮件、SEO/OG、分享卡片、MCP App、Codex/Claude 插件、VS Code/Cursor 扩展、安装器和公开文档。根据入口携带的语言生成站外内容，不从 IP 推断语言。

## 5. 验收要求

- `zh-CN` 和 `en` 各完成一次“发现 → 详情 → 立即游玩”及“登录 → 设置 → 退出”浏览器验收。
- 语言切换刷新后保持，深链接不丢失，嵌入宿主与普通网页行为一致。
- 自动测试阻止缺失 key、两个语言目录 key 不一致以及新增固定中文的平台文案进入已迁移模块。
- 英文按钮在 320、768、1440 px 宽度下不溢出；日期、复数、数字和屏幕阅读器标签随语言变化。
- 未完成 I2— I4 前，发布说明必须明确当前覆盖范围，不使用“全平台已支持英文”的表述。
