# QQ 原生反向 WebSocket 本地修复验收（2026-11-27）

当前状态：本地验收通过。真实扫码、worker 重连、会话失效后的重新扫码、10 分钟连续观察，以及观察结束后的新消息均已核验；共四条真实回复。仅同步非论文源码及验收证据，不包含线上部署或服务重启。

## 已复现的问题

针对保留网关镜像中的原始 `napcat.mjs`（SHA-256
`7967149b1c4f3d30e0506c842f84b7b925c2d361e3c9c75ebf0d4ff24dbdedaa`），
直接提取其反向 WebSocket 类复现了连接所有权竞争：重新配置连接后，旧连接延迟到达的
`close` 或 `error` 回调会清空新连接引用。新套接字可能仍连接着，但原生事件无法经该引用发送。
另一个问题是旧请求的异步响应会使用当前连接，可能把旧连接的响应发送到新连接。

这证明原始代码存在此缺陷，尚不能证明它是线上所有无回复现象的唯一原因。
原生内核不再接收新消息、QQ 会话失效、群权限以及业务执行失败仍需分别观察。

## 修复范围

`scripts/patch-napcat-websocket-owner.mjs` 只接受上述固定原始文件的完整哈希，
仅替换已审计的反向 WebSocket 类。每个回调和异步响应绑定创建它的套接字；
过期连接不能清除当前连接，也不能把响应串入当前连接。当前连接错误会结束该连接并安排重连。
消息监听器捕获异步处理失败，避免未处理的 Promise 拒绝，日志不输出请求及凭据。

补丁不修改 QQ 登录、内核、数据库、权限、定时计划、论文开关或历史锁记录。
原文件不被覆盖；输出必须位于新的本地构建目录。

自包含的回归入口：

```powershell
node --test tests/platform/napcat-websocket-owner.test.mjs tests/platform/napcat-websocket-wire.test.mjs
```

原生真机验收工具另需本机已有的固定依赖镜像及审计过的原始文件。启动命令须显式提供
`--vendor-source <原始 napcat.mjs 路径>` 和 `--authorized-live-account`，构建目录必须全新。
`scripts/start-qq-owner-local-lab.mjs` 不是线上更新入口，不可用于连接线上数据库或复用线上登录卷。
页面进程中断后，可对同一测试目录执行 `scripts/qq-owner-local-observer.mjs`，只重新附加观察页，
不创建另一套 QQ 会话。验收私有目录、登录文件和数据库记录不得提交到 Git。

## 后续自动恢复的边界

套接字重连只能修复传输断开。QQ 内核停止接收消息但仍报告在线时，仅检查 `loggedIn` 或 TCP 连接
不能证明收信可用。长时间无群消息本身也不能作为重启依据，安静群不能被误判。
有界恢复必须依据明确故障或受控新测试的证据、使用互斥和冷却、记录次数，达到上限后提示人工处理。
本补丁不扩大现有守护器权限，不把“未观察到消息”直接改为循环重启。
