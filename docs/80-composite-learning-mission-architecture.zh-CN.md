# 综合学习任务总体架构

状态：M1 架构基线与首个纵向样板
版本：v1.0
日期：2026-10-16
关联文档：[74 Agent 原生互动课件平台](./74-agent-native-interactive-courseware-platform.zh-CN.md)、[77 好奇心驱动的情境化互动课件](./77-curiosity-driven-scenario-courseware-architecture.zh-CN.md)、[79 模块运行时与可控热插拔](./79-modular-courseware-runtime.zh-CN.md)

## 1. 决策

平台采用六个职责平面，而不是把知识、游戏规则、页面和发布逻辑继续堆进单体课件：

```text
Curriculum / Knowledge
        ↓
Atomic Learning Capabilities
        ↓
Mission / Scenario Orchestration
        ↓
Experience / Presentation
        ↓
Evidence / Assessment
        ↓
Platform / Distribution
```

现有结构化课件 Runtime Kernel、模块清单、能力依赖、模块锁、快照和 Embed 协议继续使用。综合任务是新的 `scenario` 模块组合，不创建第二套运行时，也不通过 iframe 串接多个课件。

## 2. 六个平面的职责

| 平面 | 权威内容 | 禁止承担 |
| --- | --- | --- |
| 知识 | 知识点、先修关系、教材映射、学习目标 | 页面布局、剧情、得分 |
| 原子能力 | 学科状态、公式、约束、求解器、测量 | 任务故事、通关状态 |
| 任务 | 节点、分支、任务时钟、资源、行动成本、结局 | 重写学科公式、直接操作 DOM |
| 体验 | 横版世界、工作台、HUD、计算输入、动画与无障碍 | 判断科学答案、保存权威事实 |
| 证据 | 预测、计算、配置、测量、比较、解释、迁移证据 | 用通关结果冒充掌握程度 |
| 分发 | 目录、固定 Release、嵌入、存档、进度、权限和完整性 | 在线任意下载并执行未知模块 |

依赖只能向下读取公开能力。Domain 不知道任务故事；Scenario 只读观察声明过的 Domain；Component 不决定正确性；宿主网站不接触课件内部可写状态。

## 3. 三类产品对象

| 对象 | 内容规模 | 典型用途 |
| --- | --- | --- |
| 原子实验 | 一个主要知识关系，5–15 分钟 | 教材实验、自由沙盒、局部挑战 |
| 综合任务 | 2–5 个原子能力，15–40 分钟 | 计算、配置、模拟、决策组成的有压力任务 |
| 主题路线 | 多个综合任务，多次学习 | 课程进度、先修开放和能力成长 |

综合任务直接绑定原子能力，不把原子实验的完整页面嵌入另一个页面。主题路线由平台组织，不制作一个无限增长的课件包。

## 4. 模式与工作阶段是正交维度

- `教材 / 自由 / 挑战` 是体验模式，决定约束、提示、压力和失败规则；
- `探索 / 建模 / 分析` 是工作阶段，决定学习者当前观察、构造或复盘什么。

教材模式可以冻结任务压力，自由模式不产生不可恢复失败，挑战模式启用完整任务时钟、资源与结局。三个工作阶段可以出现在任意体验模式中，不作为六个同级页面展示。

## 5. 时间与压力

系统严格区分：

1. **模拟时间**：由 Domain 求解器拥有；
2. **任务时间**：由 Scenario 拥有，随声明过的行动成本推进；
3. **现实时间**：由体验或平台用于界面与匿名统计，默认不决定任务结果。

任务压力必须成为确定性状态。计算、实验、重试、等待和使用帮助可以消耗不同任务时间或资源；相同 Release、初始快照和命令序列必须产生相同结局。倒计时动画只是任务状态的投影，不是权威时钟。

## 6. 机器契约

首轮新增四个严格协议：

- `mission-v1.schema.json`：任务图、任务时钟、资源、行动、条件、证据发射和结局；
- `capability-binding-v1.schema.json`：把任务中的逻辑能力槽绑定到 Release 内的模块、能力、查询和可观察量；
- `evidence-model-v1.schema.json`：把过程证据映射到学习目标，独立于任务胜负；
- `mission-replay-v1.schema.json`：固定 Release 下的初始快照、命令序列和最终状态摘要。

`experience-v1` 继续描述体验模式、工作视图和工具，不吸收任务逻辑；`course-v1` 继续描述课程目标与检查点，不成为所有状态的容器。

## 7. 运行时规则

`@mooyu/courseware-mission-engine` 把 Mission 定义编译为普通 `scenario` 模块：

- 界面只提交 `mission.start`、`mission.act`、`mission.advance`、`mission.reset`；
- `mission.act` 只接受行动 ID，不接受界面计算出的 `success`；
- Scenario 通过已声明依赖只读观察 Domain，并在内部判断条件；
- 行动无论成功或失败，都可以消费声明过的时间和资源；
- 结局按失败、部分成功、成功的优先级解析，避免“资源归零同时通关”；
- 状态、证据与命令历史均可进入 Kernel 快照和确定性回放。

## 8. 首个纵向样板

`samples/courseware-mission/energy-train.mjs` 验证一个有边界的三阶段综合物理任务：

1. 用牛顿第二定律配置牵引加速度；
2. 用功—能关系判断能否通过坡道；
3. 用匀减速关系配置制动距离；
4. 完成跨阶段解释与复盘。

任务具有通行窗口和电量，两者由每次行动消耗。失败尝试不会凭空撤销成本。三个阶段分别读取 `physics.newton-cart`、`physics.work-energy`、`physics.braking` 的权威观察量，Mission 自身不复制公式。

该样板先验证架构和可回放因果链，再由 `@mooyu/courseware-mission-workbench` 接入可替换的横版体验层。体验层提供路线、HUD、任务压力、计算工作台、阶段反馈和证据结算，但不计算学科答案，也不自行决定成败。首个呈现配置位于 `samples/courseware-mission/energy-train-experience.mjs`，可在不修改 Mission 或 Domain 的情况下替换题材、文案和控件组合。

## 9. 内容生产与发布

```text
知识目标
  → 选择原子能力
  → 定义任务图与压力
  → 绑定能力槽
  → 定义证据模型
  → 选择体验壳与场景资产
  → Doctor 校验
  → Builder 固定模块锁
  → 试玩与学科审校
  → 发布不可变 Release
```

Agent 可以生成组合计划和候选任务，但不能自动把兴趣假设提升为已验证，也不能把未审校远程代码加入教学 Release。

## 10. 后续完成顺序

已完成：四个协议与 Doctor 校验、确定性任务编排、证据聚合，以及保持 Domain/Scenario/Component 分离的单屏横版能量列车样板。

后续顺序：

1. 在学习目录中区分原子实验、综合任务和主题路线；
2. 把通用任务壳接入外部 Embed，并补齐键盘、触控、reduced-motion 与双语验收；
3. 经教师审校和学习者试玩后校准计时、行动成本和提示策略；
4. 再扩展数学、化学综合任务，避免在首个样板未经验证时批量复制。

## 11. 明确不做

- 不建立一个包办所有学科和现实细节的“万能模拟器”；
- 不用装饰性分数、强制倒计时或快速点击代替知识行动；
- 不允许 Renderer 或宿主页面自行判定正确答案；
- 不让综合任务复制学科公式形成第二套事实来源；
- 不为了热插拔在正式会话中下载未知代码；
- 不把完整救援、工业或工程系统的名称贴在单公式演示上。
