# 墨鱼工坊 Windows 原生能力运行安全边界 F1.2b-1

版本：v1.0
状态：JavaScript 侧安全边界与宿主合同已实现并通过伪宿主验收；Windows 原生沙箱宿主尚未实现
更新日期：2026-10-28

## 1. 本阶段解决什么

F1.2a 解决了能力包是否可信、如何安装和如何交接 Runtime 租约。F1.2b-1 继续解决“可信包里的原生程序可以看到什么、如何输出、失控时由谁终止”。

本阶段没有用 Node 普通 `spawn` 冒充沙箱。新增 runner 只有连接到墨鱼工坊随桌面端分发、且声明完整安全原语的宿主时才运行。缺少任一能力即失败关闭：

- Windows 受限 Token；
- Job Object；
- 文件系统授权投影；
- 网络隔离；
- 设备隔离；
- 整个进程树终止。

这些声明是桌面应用内部可信组件的接口门禁，不是远程第三方进程可以自行提交的“证明”。F1.2b-2 负责实现并签名真正的 Windows 原生宿主。

## 2. runner 不变量

`windows-native-runner.mjs` 在调用沙箱宿主前完成：

1. 重新读取已安装入口文件，校验普通文件、精确大小和 SHA-256；
2. 从冻结 Placement 取得资源、文件、网络、设备和数据策略，不允许 runner 自行扩大；
3. 通过桌面授权代理取得本机文件授权；服务端输入不能直接指定任意本机路径；
4. 文件权限为 `none` 时禁止出现任何授权；其他授权必须绑定 UUID 和真实存在的非链接文件/目录；当前合同没有独立写权限，因此一律只读；
5. 请求协议有 4 MiB 上限，不写入租约 Token、节点 Token、模型 Key 或平台环境变量；
6. 宿主只收到三个专用环境变量：请求文件、结果文件和输出目录；
7. 超时、资源、诊断输出上限和取消信号必须下发给沙箱宿主。

能力进程输出 `capability-native-result-v1`，只能引用专用输出目录中的相对普通文件。runner 逐层检查路径组件，拒绝 `..`、绝对路径、符号链接和目录联接，阻断输出路径逃逸。

## 3. 本地产物

`artifact-store.mjs` 把结果流式复制到内容寻址仓库：

- 复制时计算 SHA-256 并执行大小上限；
- 按哈希隔离目录并复验既有内容，检测本地仓库损坏；
- 对相同内容自然去重；
- 只向服务端返回 `capability-output-ref-v1`、内容哈希、大小、媒体类型、合同和不含绝对路径的本地键；
- 绝对本机路径只留在执行器内部，不能进入服务器审计数据。

临时运行目录无论成功失败都会清理。内容寻址产物保留，供同设备后继阶段读取；跨设备仍按既有数据局部性政策等待或请求用户同意。

## 4. 已完成验收

`tests/platform/capability-executor-native-runner.test.cjs` 覆盖：

- 缺少任一沙箱原语时拒绝创建 runner；
- 最小环境变量和冻结权限投影；
- 请求中不出现租约秘密；
- 结果形成内容寻址本地产物并返回严格输出引用；
- 入口文件安装后被篡改时，在宿主启动前拒绝；
- 文件授权超过 Placement 上限时拒绝；
- 在合同尚无写权限字段时拒绝 `read-write` 授权；
- 结果路径穿越与诊断输出超限时拒绝；
- 临时运行目录在成功和失败后清理。

F1.2a 的签名安装、DPAPI、租约和崩溃恢复测试继续作为回归门禁。

## 5. 后续阶段 F1.2b-2（现已完成 MVP）

实现 Windows 原生沙箱宿主，而不是继续扩充 JavaScript 模拟层：

- 使用受限 Token 去除管理员能力和无关 SID；
- 使用 Job Object 限制内存、CPU、活动进程数、超时并保证进程树统一终止；
- 为每次运行建立最小 ACL 工作目录与文件授权投影；
- 默认阻断网络，按冻结域名策略通过受控代理开放，不直接放行任意目的地址；
- 默认拒绝摄像头、麦克风和 GPU，只有显式授权才投影；
- 与桌面端签名、版本和宿主哈希绑定，不能由能力包替换；
- 原生故障码稳定映射到 `safe-failure` 或 `uncertain`；
- 在标准用户、管理员账户和系统重启场景执行真实进程树验收。

上述 MVP 已实现并通过真实 Windows 子进程验收，详见 [Windows 原生沙箱宿主 F1.2b-2](./mooyu-capability-executor-f1-2b2.zh-CN.md)。生产启用仍须经过桌面安装器、代码签名与受信安装清单交付，不能直接使用开发目录二进制。
