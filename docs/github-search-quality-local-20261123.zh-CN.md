## 交付行为

新接收的无指定仓库 `github_search_projects` 任务冻结 `searchProtocol=2` 与用户完整原文，避免模型缩短 topic 时遗失条件。新工作流 `agent.github.search@1` 包含规划、检索、材料读取、核验四阶段。文章、指定仓库读取、源码追问、定时文章和不带新协议标记的历史任务继续走原路径。

规划器提取用途与条件、硬要求和偏好，多组查询默认按相关性，不自动设置 Stars 门槛。支持语言、许可证标识、Stars、仓库创建/推送时间的类型化限定符；功能、平台、部署方式、中文支持、硬件、许可范围等通过通用 documented 条件核验。模糊时间需说明范围；影响结论的歧义、过多条件或矛盾应澄清，不能偷偷放宽条件。

新后端工具 `research.github.repository.search-conditions@1` 使用搜索输入/输出 schema v2，仍要求原 `research.github.discover@1` 权限。保留原搜索工具与 schema v1，定时选题逻辑不变。新工具使用 GitHub 官方公开仓库搜索 API，返回真实查询 URL、抓取时间、去重候选、创建时间、推送时间和 `incomplete_results` 标记。

每次最多3组查询、每组20项、最多核验5个候选和8项条件；2次模型调用、最多8次网关工具调用。仍受原全局权限、预算、并发、运行时预检和调度协议门禁限制，不能借新流程超出原账户总预算。材料读取复用原只读工具，读取固定 revision 的 README、许可证、文档及正式 Release。模型输入按 UTF-8 字节截断，完整工具材料留在原有证据账本，输出说明未覆盖全仓库。

语言、SPDX 标识、Stars、创建/推送日期、最新正式 Release 日期由服务端根据实取元数据重新计算，不能由模型覆盖。其他条件标记为作者材料支持、明确不符或未确认；非元数据结论必须带本仓库实际材料的连续原文引用，源码文件链接附固定版本与行号。引用不存在、跨候选、漏条件或凭元数据证明功能时拒绝该输出。第二次核验还对照原始请求审查规划遗漏；报告未覆盖要求时不能标为全部符合。

结果区分“符合条件（资料核验）”“待确认”“不符合”，给出逐项理由、证据链接、查询/抓取时间、搜索范围和限制。硬条件未确认的项目不进入已确认推荐列表。无匹配如实说明，不自动用热门旧项目补齐。过长回复缩小正文展示数量并明确说明，全部逐项结果仍留在任务证据中。

四阶段通过现有网关及不可变阶段证据恢复，已完成任务重放复用同一回执，不再次调用模型或 GitHub。普通材料缺失可保留未确认；权限、预算拒绝和不确定的工具结果必须停止，不能当作缺资料继续。
