# F1.3b-2b-2c-2a：论文引擎本地进程管理器

状态：代码与故障注入回归已完成
日期：2026-10-29
边界：本阶段建立可靠的本地 adapter 进程通道，没有接入真实 PDF 渲染器或 PaddleOCR / PP-StructureV3。

## 1. 目标

具体 OCR SDK 不进入通用执行器。通用层只负责：

- 把已冻结请求原子写入一次性工作目录；
- 使用绝对可执行文件、参数数组和显式环境启动 adapter，始终禁用 shell；
- 从只追加 JSONL 文件读取有界、单调进度；
- 进程退出后从稳定普通文件读取唯一结果并再次执行严格合同验证；
- 通过本地取消文件给 adapter 协作退出机会；
- 对超时、输出洪泛、协议篡改和不响应进程失败关闭。

这让未来 PDFium、MuPDF、PaddleOCR 或其他引擎可以替换，而不会把第三方 API 传播到任务合同和论文工作流。

## 2. 工作目录与通信边界

每次请求使用 `root/requestId/` 独占目录：

- `request.json`：管理器原子写入，adapter 只读；
- `progress.jsonl`：adapter 只追加；
- `result.json`：adapter 应通过临时文件加 rename 一次性发布；
- `cancel.json`：管理器原子写入，adapter 轮询。

请求提供的三个输出路径必须精确等于管理器为 request ID 派生的路径。已存在工作目录会被拒绝，不能把旧结果当作新运行，也不能把输出重定向到任意路径。

## 3. 进度和结果验证

管理器串行读取进度，防止定时轮询与进程退出时的最终读取竞争。每次读取都验证：

- 文件是普通文件而非链接；
- 内容只能在已观察前缀之后追加，不能截断或改写历史；
- 总字节数不超过冻结请求限额；
- 每行都是完整 UTF-8 JSON，并通过 request-bound 单调进度合同；
- 进程退出后不能留下半行。

结果只在进程结束后打开，打开前后复验普通文件身份、大小和修改状态；随后验证精确页集合、方法、坐标、诊断和错误语义。stdout/stderr 只作为有界本地诊断，不能承载业务结果。

## 4. 取消、超时和进程树

用户取消或超时时先写 `cancel.json`，给 adapter 一个有限协作退出窗口；仍未退出才发送终止信号，再超时则强制结束。管理器自身不假设普通 Node 进程能够可靠枚举 Windows 后代进程，生产运行仍必须位于已有 Windows Job Object 沙箱内，由外层 helper 保证整棵进程树终止。

服务端 4 核 8G 主机不运行此进程。模型、渲染器、输入和结果都留在用户本机授权边界内。
