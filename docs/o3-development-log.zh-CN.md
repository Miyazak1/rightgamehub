# O3.2：作者开发日志与公开作品时间线

状态：已合并部署并由用户完成生产验收（2026-10-12）。

## 目标

让玩家在同一个游戏详情页里看见作品如何持续变化，以及社区贡献最终进入了哪个版本。开发日志属于每个具体游戏，不新增“开放游戏馆”，也不把游戏迁入社区栏目。

## 产品流程

1. 创作者在“创作者中心 → 作品 → 开发日志”新建草稿。
2. 日志可以标记为“开发进展”“版本说明”或“里程碑”，并可关联该作品当前公开可用的版本。
3. 草稿只有创作者自己可见；作品公开后，创作者可以将日志发布到作品详情页。
4. 已验收完成的公开贡献任务自动进入同一时间线，并显示贡献者和验收版本。
5. 创作者可撤回自己发布的日志；历史操作保留在只追加审计记录中。

## 隐私与可信边界

- 玩家提交的结构化反馈继续只存在于作者私人收件箱，反馈正文不会自动公开。
- 公开时间线只展示作者主动发布的日志和已经完成的公开贡献任务。
- 关联版本必须属于同一作品，并且是当前公开、通过校验且可访问的版本。
- 日志发布使用版本号做乐观并发控制，避免旧页面覆盖新状态。
- 日志事件只追加，禁止 SQL 更新或删除。
- 作品撤下后，公开时间线接口与作品本身一起不可访问；不会单独泄露日志。

## 数据与接口

- 迁移：`0063_work_development_entries.sql`。
- `work_development_entries` 保存草稿、公开和撤回状态。
- `work_development_entry_events` 保存 `draft_created`、`edited`、`published`、`withdrawn` 审计事件。
- `GET /v1/works/{workId}/timeline`：公开作品时间线。
- `GET /v1/creator/works/{workId}/development-entries`：作者管理列表。
- `POST /v1/creator/works/{workId}/development-entries`：新建草稿。
- `PATCH /v1/creator/development-entries/{entryId}`：编辑、发布或撤回。

## 验收清单

1. 创作者中心每个作品都有“开发日志”入口。
2. 草稿不会出现在匿名公开接口或作品详情页。
3. 已发布日志出现在对应游戏详情页，类型、作者、时间与版本关系正确。
4. 已完成贡献任务出现在同一时间线，并能进入公开任务详情。
5. 私人玩家反馈正文不出现在公开接口、页面或日志创建表单的自动填充中。
6. 非作品所有者不能读取或修改管理列表。
7. 没有 `works:write` 权限的账号不能创建、编辑、发布或撤回日志。
8. 关联其他作品、非当前版本或已停用版本会被拒绝。
9. 并发使用旧版本号修改会返回冲突。
10. 撤回后公开时间线不再显示该日志，审计事件仍保留。

## 生产验收建议

使用一个测试作者账号和一个普通玩家账号完成：玩家提交反馈 → 作者确认并创建公开贡献任务 → 玩家领取、提交 → 作者关联上线版本并验收 → 作者发布版本说明。最后匿名打开作品详情，确认只看到公开任务、贡献者、版本和作者日志，看不到原始反馈正文。
