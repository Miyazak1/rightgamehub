# EXE 在右侧栏内游玩：验证计划

更新：2026-09-24 · 原生窗口画面与部分鼠标回传已实测，完整游玩未通过 · [目录](./README.md)

**本机实验结果已补充**：[22 原生 EXE 实测](./22-native-exe-local-test.zh-CN.md)。下载版桌猫的窗口画面已进入 Harness 右栏；后台鼠标部分通过，键盘、音频、停帧及性能门槛仍未通过完整验收。以下保留完整实验目标，未标记通过的项目仍需验证。

TD-1.1 当前实验目标为 **Harness 功能区、VS Code WebviewView、Cursor 编辑器 WebviewView**，分别记录版本和结果。本文中的 Codex 记录是前期研究与样本历史，不代表这三个宿主已通过。EXE 安装包分发已纳入首版，具体见 [18](./18-multi-host-client-spec.zh-CN.md)、[19](./19-windows-package-spec.zh-CN.md)。

**后续样本结果**：已实际启动并检查用户提供的桌猫 EXE，发现它是 Electron 网页封装。包内原始 HTML 在 Codex 内置浏览器中完成了交互与存档测试，见 [实测报告](./10-deskcat-test.zh-CN.md)。下面的原生嵌入/串流实验仍未完成；实施前应先识别样本是否已有可独立运行的网页版本。

## 1. 要验证的真实体验

用户在 agent 右侧功能区或右侧内置浏览器内看见游戏、听见声音、操作角色；开始会话后无需切换到独立游戏窗口。下载并弹出 Windows 窗口不算通过，单纯把游戏画面展示在侧栏也不算通过。

**2026-09-24 用户明确的硬性条件：从启动到退出，游戏只在右侧功能区呈现。**玩家电脑可以运行后台游戏进程，但不得出现独立可见的游戏窗口，包括启动时短暂弹出再隐藏；不得抢走编辑器焦点，也不得要求玩家手动最小化、还原或切换游戏窗口。菜单、游戏内弹窗和输入都应在功能区完成。把已有独立窗口的画面复制进右栏，不满足此条件。

现有 PrintWindow 探针依赖独立桌面窗口，按该条件判定 **产品路线验收不通过**，只保留研究证据。后续优先评估作者/引擎配合的离屏运行与专用输入接口；未经改造的任意 EXE 暂无通用可行性结论。不能仅靠隐藏窗口就假定渲染、声音和输入都会继续正常工作。

桌面实测已暂停。后续任何启动可见程序、切换前台窗口或模拟键鼠的测试，都须先向用户说明具体影响并取得明确同意；当前文档修订不构成再次实测的授权。

Windows 上传、扫描与下载管理属于首版；上述完整体验另行验证，并决定何种 Windows 构建可以开放“在功能区运行”。原生运行实验不阻塞分发模块，也不能由分发测试代替。

除了服务器运行后串流，还应验证**玩家电脑本地运行、串流到同一电脑的右侧浏览器**。它可能省去云端游戏计算费用，但需要安装本地运行组件，且输入焦点、窗口捕获和引擎兼容性都尚未证实。不要把本地组件称为普通网页插件，也不要承诺任意 EXE 可用。

| 候选路线 | EXE 在哪里运行 | 侧栏显示什么 | 第一项验证 |
| --- | --- | --- | --- |
| 宿主正式支持原生窗口嵌入 | 玩家电脑 | 被宿主接纳的程序窗口 | 是否存在公开容器接口和可安装扩展契约 |
| 本地运行与串流，优先实验 | 玩家电脑 | 实时游戏视频，并回传输入 | 不切到游戏窗口，能否持续正确操作 |
| 远程运行与串流，后续评估 | 独立 Windows 机器/隔离会话 | 实时游戏视频，并回传输入 | 网络延迟、会话隔离、运行成本 |

## 2. 第一关：宿主允许什么

### 原生嵌入

前期 Codex 核查：当时查阅的 OpenAI 公开文档描述技能、MCP 工具及可选 UI，未找到足以依赖的第三方将任意 Windows 窗口嵌入 Codex 常驻右侧功能区的公开契约。这是历史核查边界，不用于推断 Harness 或 VS Code 已具备原生容器。[插件架构](https://developers.openai.com/plugins/concepts/plugins)、[可选 UI](https://developers.openai.com/plugins/build/chatgpt-ui)。

只有找到正式的原生容器 API 后，才做最小扩展：注册容器 → 放入自有测试程序 → 验证尺寸、焦点、关闭和重启。拥有 HTML webview 或能打开 URL，不等于拥有原生容器。VS Code 扩展的既有原型也只证明设计了网页容器，不能用来宣称能装入 EXE 窗口。

Windows 的 `SetParent` 是窗口管理 API，涉及窗口样式和 DPI 等兼容问题；它不是编程软件的扩展契约。不要通过枚举并改挂宿主私有窗口、修改安装文件或注入进程，作为正式产品路线。[Microsoft SetParent](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)。

没有公开接口时，这条路线记录为暂不采用，继续验证右侧浏览器接收串流，不无限投入逆向尝试。

### 浏览器接收端

普通浏览器作为对照，Harness、VS Code、Cursor 编辑器功能区分别作为目标；Codex 内置浏览器仅作为额外候选。每项记录宿主版本、界面形态和运行设备。第一份诊断页面测试：

1. WebRTC 实际协商、解码持续视频和双向数据通道，不只检查 API 名称存在。
2. 点击开始后的声音、键盘事件、鼠标点击；需要视角控制时增加指针锁测试。
3. 窄面板、缩放、隐藏后恢复、任务切换和连接断开提示。
4. 播放器和本地组件连接是否受 CSP、浏览器私网访问规则或宿主权限限制。

可先用带帧号的自有测试画面建立 WebRTC 回环，以排查接收端。回环成功只证明该环境的媒体/数据路径，不能证明 Windows 捕获、EXE 控制或跨网串流。WebRTC 可承载实时音视频与数据，但目标宿主是否启用这些能力仍要实测。[MDN WebRTC](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API)。

## 3. 第二关：本地 EXE 在侧栏内实际可玩

### 最小原型

```mermaid
flowchart LR
  G[玩家电脑上的测试 EXE] -->|窗口画面与声音| R[本地运行组件]
  R -->|WebRTC 音视频| B[右侧浏览器播放器]
  B -->|键鼠事件| R
  R -->|适配后的输入| G
```

三个组件足够：一个可控的测试 EXE、一个本地捕获/编码/输入组件、一个右侧网页播放器。作品商城、用户上传、支付和云服务器都不属于这次实验。

从自有、可审查的测试程序开始，界面显示连续帧号、按键状态、可移动角色、点击计数和可开关声音；每次输入生成编号，画面显示实际处理到的编号。这样能区分“指令发出”与“游戏确实响应”。随后再用有权测试的、未针对播放器改造的 Godot/Unity Windows 构建检查真实引擎兼容性。

### 显示与声音

原生组件可研究 Windows Graphics Capture 的窗口捕获，再编码为接收端实际支持的 WebRTC 媒体；音频捕获另做验证。只选择测试游戏窗口，避免采集整个工作桌面。窗口被遮挡、失焦、最小化、调整大小及游戏暂停时分别记录画面是否继续，不假定这些状态等价。[Microsoft 屏幕/窗口捕获](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)。

仅使用网页 `getDisplayMedia()` 时，需要用户主动选择共享对象并授予权限；它提供捕获，不提供控制 EXE 的通用能力，不能偷偷替用户选择桌面，也不能当作无需本地组件的完整方案。[MDN getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)。

### 输入是关键停止条件

当宿主侧栏获得焦点时，普通 Windows 游戏能否收到正确输入，要单独验证。Windows 键盘消息与焦点相关，`SendInput` 还受完整性级别限制；不能因为 API 调用返回成功，就断言输入去了指定后台游戏。[Windows 键盘输入模型](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input)、[SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。

依次验证点击、方向键按住/松开、组合键、拖动、滚轮、连续移动、鼠标相对位移。点击 agent 输入框后，游戏应停止接收输入；断线、失焦或退出时释放所有按键，不得把游戏按键发到聊天框或其他应用。

如果程序只在抢回前台后能操作，判定当前本地通用路线不通过。对接作者 SDK 或改造游戏输入可作为受限兼容方案，但结果必须写“需作者适配”，不能写“支持任意 EXE”。独立本地虚拟机/桌面会话也可能提供另一条路线，但涉及图形加速、隔离和资源开销，需单独实验；虚拟显示器本身不等于解决输入焦点问题。

### 本地组件边界

原型只绑定回环地址，使用配对与短期会话认证，校验连接 Origin/Host；不能仅依赖端口不公开。只控制指定测试进程，不提供网页可调用的任意 shell、文件路径启动、文件读取或系统热键接口。内容作品本身不能取得本地组件令牌。关闭页面应释放输入并按明确会话策略停止捕获，组件可由用户退出，不设置静默开机启动。

测试只使用自有/可信样本，不在本机运行陌生作者上传的程序。真实 UGC 的分发检测与执行隔离仍需另行设计；串流不会自动把本地 EXE 变成安全沙箱。

## 4. 样本、通过标准和结果记录

| 样本 | 要证明什么 |
| --- | --- |
| 网页测试帧回环 | 接收端协商、视频解码、数据通道可用 |
| 自有最小 Windows 测试程序 | 捕获、输入、声音和会话生命周期能闭环 |
| 普通窗口化 Godot 2D 构建 | 未专门适配的引擎输入与资源表现 |
| 普通窗口化 Unity 或其他独立引擎 3D 构建 | 不同图形/输入路径，避免用一个样本推断全兼容 |

建议先限定 Windows、窗口化、键鼠操作、轻量游戏。需要管理员权限、驱动、反作弊、独占全屏或额外服务的作品不作为首轮支持目标。

以下是**拟定实验门槛，尚无测量结果**：

- 最低 720p/30 FPS 目标；面板 360/480/960 px 宽和常见 DPI 缩放下可操作，画面等比例显示，鼠标坐标映射正确。
- 本机输入到可见画面响应的 p95 先以 100 ms 为目标；休闲小游戏之外的动作游戏另设更严格目标。数据通道 ping 的 RTT 不能替代端到端操作延迟。
- 连续游玩 30 分钟，切换焦点 20 次，无抢前台、卡住按键、持续黑屏或无法恢复的连接。
- 声音跟随游戏会话，暂停/退出后没有残留播放；退出后没有残留捕获或输入活动。
- 记录 CPU、GPU 编码/解码负载、内存和帧率；同时在 agent 中输入文本，确认两侧输入不串扰。

延迟测量：用测试 EXE 的输入编号和帧号关联客户端发送日志与解码画面，对自有样本给出可复核数据；通用样本用高帧率录像或可靠的画面变化检测复核。日志说明采样量、p50/p95、测量方法及分辨率，不把网络 RTT 包装成总延迟。

结果表按“宿主版本 × 引擎/样本 × 操作类型”记录：

| 项目 | 当前状态 |
| --- | --- |
| Codex 轻量 Canvas 游戏运行 | 既有本地实测通过，见原验证报告 |
| 第三方原生容器公开接口 | 本次资料未证实，暂不作为依赖 |
| Codex WebRTC 回环和本地组件连接 | 待实现、待实测 |
| Harness / VS Code / Cursor 编辑器 WebRTC 回环、组件连接及完整闭环 | 三者分别待实现、待实测；当前优先目标 |
| Windows 窗口视频及声音送入右侧浏览器 | 待实现、待实测 |
| EXE 失焦时的真实键鼠控制 | 待实现、待实测；关键阻断点 |
| 30 分钟稳定性、延迟和引擎矩阵 | 待实测 |
| 任意作者 EXE 的安全运行 | 未证明，不因单个样本通过而承诺 |

## 5. 本地路线不通过后如何决策

若接收端可用、但普通 EXE 无法在本地后台可靠控制，可选择只支持接入作者 SDK 的 Windows 包，或转测独立远程机器：游戏在另一台 Windows 电脑保持前台，侧栏通过网络接收画面并回传输入。第一轮可用已有的第二台机器，不必直接购买云 GPU；这只能证明串流体验，不能证明商业云部署成本。

远程路径通过后，再验证广域网、NAT/TURN、中断恢复、每位玩家的独立会话、图形资源和存档隔离。成本按游戏实例时间、并发、编码、流量与中继计算，不套用静态网页 S 档预算。共享一个交互桌面不能算作多个玩家的隔离运行方案。

| 实验结果 | 产品决定 |
| --- | --- |
| 本地普通 EXE 的显示与输入均通过 | 推进“本地运行组件 + 侧栏播放器”，公布经过验证的兼容范围 |
| 只有改造过的程序通过 | 限定作者 SDK/引擎模板，单独说明接入要求 |
| 本地不通过，远程通过且预算可接受 | 另立云端运行版本，不并入最小静态托管方案 |
| 目标宿主媒体/输入受限，或运行成本不合适 | 保留网页在线玩与首版 EXE 下载管理；明确原生功能区游玩未通过，不把独立窗口算作达成目标 |

建议按关卡限时投入：先做宿主能力检查与接收端，再做一个自有 EXE 的真实操作闭环，最后投入引擎兼容和长时间测试。任何一关未通过，先记录原因再决定下一条路线；无需先搭建完整平台或购买云资源。

本计划制定时的产出是公开资料核查与实验设计；后续桌猫样本测试见第 1 节前的实测报告链接。尚未安装通用本地运行组件、测试原生串流或采购服务器。
