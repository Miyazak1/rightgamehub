在本项目根目录构建和打包：

```powershell
npm run build:harness
npm run pack:harness
```

生成的 `.tgz` 位于项目 `artifacts` 目录，可在包含 Web 界面的 Harness 受管 profile 中通过官方插件管理器安装。包名仅供本地测试，尚未发布到 npm。不要将测试包装到只有 base 的 profile。

游戏样本使用 opaque-origin sandbox，只授予脚本权限，没有宿主消息桥或账户能力。内嵌样本仅验证容器，不替代正式远程独立域、SDK、UGC 或下载验收。

### 上传与下载

选择 ZIP 或 EXE → 点击“上传” → 等待“上传成功” → 在已上传文件列表点击“下载文件”。保存完成后可点击“选择下载文件校验”，重新选择保存的文件，比较字节数与 SHA-256。选择文件不会自动上传；校验需要再次传输文件，但不保存第二份。

文件通过 Harness 已认证的同源 `/api/gamehub/*` 流接口传输，继承宿主登录、Host/Origin 和 Fetch Metadata 检查。没有独立的无认证端口，也不借用聊天附件存储。此认证只代表本机操作者，不能替代未来的平台账号和作品权限。

单文件上限 500 MiB，已提交记录合计最多 2 GiB / 50 个文件；单实例同时接收一个上传或校验任务，30 分钟超时。上传可取消；中断可能发生在提交完成之后，取消或断网后请刷新列表确认结果。文件保存为随机 ID，原始名称只进入元数据；校验格式头不等于安全扫描。

项目 BAT 将存储位置设为 `.runtime/m0/gamehub-storage`。独立安装可设置 `GAMEHUB_STORAGE_DIR`；默认使用 `DSH_HOME/gamehub-storage`（未设置 DSH_HOME 时为用户目录的 `.dsh/gamehub-storage`）。目前仅面向单机单服务试运行，不支持多个服务同时写入同一存储目录。不要删除该目录来更新插件。掉电或强制终止可能留下未提交临时文件，尚无自动回收管理。

“下载文件”支持 HTTP Range，由浏览器负责保存；插件无法确认浏览器保存完成，也尚无下载队列或跨重启续传管理。0.0.12 启用本机启动后，GUI EXE 另有平台管理的下载和独立窗口启动入口；单文件依赖、安装后入口和任意架构兼容性不保证。文件均未经过病毒扫描、未公开发布。历史桌猫捕获实验仍为单独的固定哈希研究路线。

### 上传后在右栏玩

网页游戏 ZIP 的根目录必须是 `index.html`，同包放入脚本、CSS、图片、字体、音频、WASM 等相对路径资源。先构建再打包，不上传项目源代码、node_modules 或额外的外层目录。当前不支持依赖 CDN、后端 API、SPA 路由重写、Worker、JS eval 或预压缩 `.br/.gz` 的导出。

上传完成后自动检查 ZIP，合格包生成默认封面和名称（来自 ZIP 文件名），点击“开始游戏”在此功能区运行。支持重新开始、结束和全屏；功能区隐藏、切换会话、页面离开或卸载会释放游戏。重新开始会重置本局状态；当前不提供持久存档。

网页包上限 100 MiB，展开后总量 300 MiB、单文件 100 MiB、条目 5000、路径深度 16。检查独立 Node 子进程，192 MiB V8 堆上限、120 秒时限，逐文件流式解压和 CRC/SHA-256 校验；拒绝路径穿越、重名、大小写/Unicode 歧义、链接、加密、安装脚本和嵌套压缩包。未通过网页检查的 ZIP 保留原始下载，并显示原因。解压量计入 2 GiB 本机额度。

资源服务只监听独立环回主机 `127.0.0.2` 的随机端口，不共用 Harness 主机 Cookie。只有已认证的 Harness API 能创建或结束运行会话；随机能力 URL 只授予该游戏的只读清单资源，最长 2 小时，结束后撤销。iframe 与 HTTP CSP 双重 `sandbox allow-scripts`，不授予 same-origin、宿主桥、外部网络或 Worker；CORS 仅为 opaque frame 读取自己的模块、数据、字体和 WASM，不允许凭据。

这是本机桌面试运行：需要浏览器和 Harness 在同一电脑，不能当作远程部署。ZIP 解析子进程不是 OS 安全容器，结构检查不是恶意代码扫描；公开投稿仍须落实正式方案中的容器隔离、账号、扫描和发布流程。

在项目根目录运行 `node scripts/build-web-samples.mjs` 可生成两个可上传的多文件测试 ZIP，位于 `artifacts`。上传后应出现游戏卡片，进入后显示独立模块/JSON/WASM 的实际加载结果。

客户端构建遵循该宿主 `window.__ModuleLoader__.load({id,factory})` 格式，React 来自宿主模块表，不打包第二份 React。当前源码无额外构建依赖；完整业务客户端阶段可切换到有类型检查的构建工具链。
