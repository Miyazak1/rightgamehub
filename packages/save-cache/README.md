# Durable host save cache (S2)

The trusted platform host owns this store. A game iframe can pass only a namespace and slot through the approved cloudSave capability; it cannot choose an account, API origin, work, channel or filesystem path.

## Durability and identity

- Browser: one IndexedDB read/write transaction, with strict durability, commits the entire slot record and quota accounting. Success is returned only after transaction completion.
- Cursor/VS Code and Harness: host-owned SQLite, WAL and synchronous FULL; version CAS and quota accounting run inside BEGIN IMMEDIATE. SQLite also arbitrates distinct processes.
- Cache key: API origin, user/anonymous installation ID, work ID, channel, namespace, slot. Runtime/release IDs are deliberately absent so compatible releases can resume the same work's save.
- Native RPC checks the API origin and current SecretStorage/OS-vault account. An anonymous ID is generated by the host and never exposed to games. Harness accounts without an available host credential vault currently fail closed.
- Local storage initialization, corruption, quota and commit failures are errors, never a successful in-memory fallback.
- A known authorization failure is persisted. Reopening that cache requires successful server revalidation under the current grant before it can be read again.

Browser storage can be removed by the user/browser; these receipts are not backups. Native files inherit the host application's data-directory access controls on Windows; Unix directories/files use 0700/0600. This implementation does not add encryption at rest.

## Outbox

Each atomic record contains current, confirmed, immutable inFlight, coalescible pending, a monotonically increasing local sequence, local CAS ETag, local idempotency receipts, recoveries, explicit import plans and a sync lease.

Only an unsent pending snapshot is replaceable. An inFlight operation retains its body, digest, original operation UUID and cloud base ETag across retries/restarts. A cloud acknowledgement clears only the matching operation and retains any newer pending snapshot. A delayed cloud read cannot replace a newer locally acknowledged revision.

A persisted lease keeps live windows from sending different operations simultaneously. After a process crash, another instance can retry the same operation after the 60-second lease expires; the server's idempotency receipt handles any duplicate delivery. Automatic synchronization normally runs at most once per minute per slot, retries transient failures after 15 seconds, and explicit sync may flush immediately. It runs while an approved game launch has opened the slot. No closed-app background sync or offline asset/catalog installation is included.

Cloud CAS conflict freezes sending and retains the newest local snapshot. Resolution requires a comparison token and the exact local ETag inspected. A local CAS collision also retains the rejected snapshot as a recovery, without replacing the other window's progress.

Budgets: 1 MiB document hard limit; 64 MiB total cache; 32 slots per origin/owner/work/channel group; 7 MiB atomic record; at most 3 recovery copies and 1 MiB recovery body total per slot. There is no silent eviction. Full recovery storage blocks further resolution; user-facing recovery export/removal and retention management remain S3 work.

## SDK

Existing client.cloudSave.read/write APIs retain their online/cloud-ACK meaning. Durable caching is an explicit opt-in:

~~~js
const resource = { namespace: 'default', slot: 'autosave' };
const current = await client.cloudSave.local.read(resource);
const receipt = await client.cloudSave.local.write({
  ...resource,
  expectedEtag: current.etag,
  idempotencyKey: crypto.randomUUID(),
  schemaVersion: 1,
  data: { chapter: 2 },
});
// receipt.durability === 'local': host transaction committed; cloud may be offline.
const sync = await client.cloudSave.local.sync(resource);
// Only sync.state === 'cloud' confirms cloud acknowledgement.
~~~

The SDK transfers large documents in bounded chunks. Additional methods: status, compare, resolve, recoveries and readRecovery; status events use cloudSave.local.changed. compare returns a token, local ETag and the downloaded cloud candidate. resolve accepts choice ('local' or 'cloud'), token and expectedEtag.

Anonymous saves never upload automatically. The trusted player UI lists only this work's anonymous slots and offers an explicit import action after login. Import uses the original slot only when empty; otherwise it creates a recovery-anon-* slot. Its operation is persisted before enqueueing; the anonymous original is retained indefinitely until later retention/management work. Games cannot invoke the cross-owner import function.

This is a closed-test S2 implementation. The production cloudSave capability gate remains closed. Native executable launch-ticket integration, full S3 save management and backup/restore exercises are separate release gates.
